Strong in-process

src/kernel/events.ts（5 行）· src/kernel/http.ts（113 行）

Before — facade 名存实亡

全仓 735 处 @/server/** import，最厚的两条 seam 无减压阀

After — 一个 interface，一个入口

读函数补齐（getFailureAttempts…） Biome 禁直 import

Problem

kernel facade 是 5 行 re-export，82/124 个文件绕过它直穿 quarry——seam 存在但没人走，迁移没有减压阀。

Solution

把 events/queries 与 http/errors 本体迁入 kernel（quarry 留 re-export 过渡），facade 补齐读函数，加 lint 规则禁直 import。

Wins

  • leverage：一个 interface 供 9 包
  • locality：事件读写改动单点
  • quarry 依赖首次可度量下降
  • 测试只打 kernel seam

对齐 ARCHITECTURE.md「迁移期豁免：kernel facade 可包装遗留 src/server/**」——此卡是把豁免走完，不违背任何 ADR。

4 · 抽公共 runner-fn：消灭 22 份 DI boilerplate + type leak

Strong in-process

22+ 文件复制同一段 6 行（tagging.ts · session_summary.ts · variant_gen.ts · quiz_verify.ts · note_generate.ts …）

新建：src/server/ai/runner-fn.ts（或随 Card 1 入 kernel）

Before — 22 份复制 + 强转

const { runTask } = await import('@/server/ai/runner');
const r = await runTask(kind, input,
  ctx as Parameters<typeof runTask>[2]);

每格 = 一个文件里的同一段 boilerplate；ctx 在调用方是 unknown，到 runner 边界才强转——危险开关（enableTransientRetry）手填无校验

After — 一个 typed factory

makeRunTaskFn(db, opts?): RunTaskFn<TIn>
// factory 装配 ctx，调用方只传 db
22 文件各删 6 行 ~130 行净删
ctx 形状在 factory 单点校验，type leak 消失

Problem

DI seam 是好意图，但 22 个调用方各自重写同一段 lazy-import + 强转——seam 的形状泄漏给了每个 caller。

Solution

单点 export 一个 typed factory：调用方注入或默认，都走同一构造；ctx 由 factory 装配并校验。

Wins

  • 净删 ~130 行重复
  • type guard 单点
  • leverage：22 callers 一处学
  • 测试仍走同一 seam

7 · runner.ts：三份主循环 → withRunLifecycle

Worth exploring in-process

src/server/ai/runner.ts（1395 行）：runTaskAttempt（203 行）· streamTask（264 行）· streamTaskCollecting（248 行）

Before — 同一段控制流写三遍

runTaskAttempt：try/finally + abort + 写库 + 计费
streamTask：同上 80% 复制（注释自承 intentionally self-contained）
streamTaskCollecting：同上 90% 复制（注释说「第二个 caller 出现就抽」）
YUK-576 retry 兼容 = 3 处同步改

RunTaskCtx 13 字段中 4 个 YUK-seam 字段只有 1 个调用方——interface 宽度 > 使用宽度

After — 生命周期一次，消费形态各异

withRunLifecycle：写库 / 计费 / abort / retry —— 一次
runTask = lifecycle(collect)
streamTask = lifecycle(enqueue)
streamTaskCollecting = lifecycle(onDelta)

YukSeamOptions 抽 sub-interface，22 个普通调用方 type 变干净

Problem

三份 80-90% 相同的主循环：改 retry / signal / 写库行为要同步改 3 处（YUK-576 已是实例）；locality 失败。

Solution

抽 withRunLifecycle 承载写库/计费/abort/retry 骨架，三个入口只保留消费形态差异；YUK-seam 字段收成 sub-interface。注释里预定的「第二个 collecting caller 出现就抽」条件已满足。

Wins

  • retry 行为改 1 处
  • interface 减 4 字段
  • locality：生命周期单点
  • 入口退化为 20 行 adapter

风险：streamTask 的 enqueue/close 形态有既有测试（stream-cancel）锁定，需先跑合并 PoC 再动。

Top recommendation：Card 1 — 让 kernel facade 成为真实 module

其它每张卡都需要 kernel 有真实载体：proposal applier 入包要立在生命周期契约上、subject-profile 上提要有个「上提到哪」、typed client 生成要消费 kernel 契约。但 facade 现在 82/124 处被绕过——不先把它坐实，后面每张卡都在沙地上盖楼。改动机械、风险最低、立刻让 quarry 依赖首次可度量下降，同时为 Card 2（提议生命周期 P2）和 Card 5（共享 reader 上提）清出落点。

快速连击：Card 4（runner-fn）与 Card 1 同属「给 seam 一个真实 module」，可同批做。Card 2 是下一张大牌。
