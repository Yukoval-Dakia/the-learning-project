# ADR-0065 — TypeScript 全栈与实时自适应学习

**Status:** Accepted target（2026-10-06）；尚未实施或部署。
**Decision source:** owner「不错。就这么定下来了。」
**Tracking:** [YUK-1337](https://linear.app/yukoval-studios/issue/YUK-1337)（决策记录）、[YUK-1338](https://linear.app/yukoval-studios/issue/YUK-1338)（集成验证）。
**Related:** ADR-0051（产品操作所有权）、ADR-0052（持久交接语义）、ADR-0062（会话生命周期）。

## 目标与约束

owner 明确要求：「学习状态的追踪和学习的安排，不是先后不是次序，最好的状态是实时准确的追踪，动态适应的安排。」

学习状态与教学安排持续共同演进：证据改变状态判断与教学选择，教学活动同时获得新的证据。
不能把这个目标降格为先完成画像、再批量生成固定日程，也不能把框架替换当作学习效果的证明。

- 目前在一台服务器部署自有应用与数据库；允许 Web 与 worker 分进程运行。
- 技术选择同时考虑 AI runtime 生态、复杂学习交互和可靠执行。
- 前端需要整体改造；视觉方向本轮暂不讨论，具体 UI 实施仍遵循设计 pre-flight。
- 已有确定性学习能力、可追踪与可逆的业务动作继续作为一等能力。

## 已批准的技术方向

| 职责 | 选择 | 所有权 |
| --- | --- | --- |
| 全栈 Web | TanStack Start / React / TypeScript | 页面、路由、服务端操作、加载与错误处理；复杂编辑与作答交互留在客户端 |
| 学习业务 | 按产品操作组织的 TypeScript 模块 | 证据、状态判断、教学策略、领域校验和最终产品结果 |
| AI 执行 | 保留 Pi（pi-ai / pi-agent-core） | 模型调用、上下文与工具循环；经业务操作执行领域动作 |
| 持久执行 | DBOS | 可恢复的任务与步骤；具体完成条件仍归业务模块 |
| 权威存储 | PostgreSQL / Drizzle | 学习事实、状态版本、业务提交与恢复所需的记录 |

采用单仓库的模块化全栈应用。同一应用镜像以 Web 和 worker 两个进程运行；Pi 作为
worker 内的库使用。数据库与应用部署于同一服务器，模型服务和已有 blob storage 的外部
依赖单独说明，不能把“单服务器”写成“全部离线”。具体进程资源配额与依赖版本在实施时固定。

## 业务边界

页面命令、Pi 工具和后台任务调用同一套业务操作。例如记录作答、修正掌握判断和调整下一项
学习活动，各自只有一个拥有权限、领域校验、幂等、事务与产品结果的实现。

- **学习状态**记录当前判断、所依据的证据、置信程度与版本；推断与已经发生的事实分开保存。
- **教学策略**结合状态、目标、可用时间和当前活动选择下一步，也能选择用于消除不确定性的练习。
- **AI 结果**记录所依据的版本；提交时在业务事务中校验。如果相关状态已经变化，重新校验或
  重新计算，不能直接覆盖更新的判断与安排。
- 确定性更新与需要模型解释的工作共同参与闭环；模型等待不得阻塞新证据的接收，也不得占住
  长数据库事务。已开始的学习活动如何保持稳定，由明确的教学策略决定。
- Web 通过带版本的通知与重新读取已提交状态获得更新。通知断线或乱序不得成为业务事实丢失，
  UI 不把模型流中的临时输出当作已经生效的学习状态。

这延续 ADR-0051 的产品操作所有权。TanStack server functions 只是网络入口，不能取代运行时
输入校验、身份和权限检查，也不能把业务规则重新分散到页面、工具与任务三个入口。

## Pi 与 DBOS 的恢复边界

保留 Pi 是目标架构的一部分。其适配层暴露领域需要的请求、结果和执行事件；旧 SDKMessage
形状的兼容转换是否删除，以消费者迁移与行为验证为准，不将旧协议扩散到新的业务模块。

DBOS 是选定的持久执行方向，Pi 与 DBOS 的步骤级集成尚未验证。只把整个 `agentLoop()` 包成
一个可重试步骤，会使恢复粒度退化为整个循环。实施必须明确以下边界：

1. 模型请求、完整响应与检查点的对应关系；恢复复用已保存的响应。
2. 工具调用的稳定身份、业务事务与工具回执；业务提交后丢失回执，恢复也不得重复业务效果。
3. 取消、状态版本失效和失败分别如何结束或继续工作；取消不等同于回滚已经提交的动作。
4. 模型或外部工具已经执行、检查点尚未保存的窗口如何识别和处置。框架不能保证外部系统
   恰好执行一次，也不能保证未知 provider 结果不会再次产生费用。

每项工作只由一个持久执行机制负责恢复。采用 DBOS 不恢复 ADR-0052 否决的通用 callback
业务壳；各业务的事务边界、回执、幂等单位和完成条件仍需明确保存。旧 pg-boss 任务与恢复
义务的迁移、清空和回滚属于实施计划，不能在这些义务尚未处理时直接删除队列。

`pi-durable` 作为后续评估对象，不与 DBOS 同时管理同一循环的恢复，也不在本次被选为
整个学习系统的持久化基础。

## 接受的代价与证据边界

2026-10-06 核查的上游资料：

- [TanStack Start overview](https://tanstack.com/start/latest/docs/framework/react/overview)
  仍标为 RC；采用时需要固定版本并验证本项目使用的服务端与客户端边界。
- [DBOS architecture](https://docs.dbos.dev/architecture) 描述其 PostgreSQL 支持的库式执行，
  无需另设编排服务器；[工作流约束](https://docs.dbos.dev/typescript/tutorials/workflow-tutorial)
  要求遵守步骤记录与恢复规则。这里只核查了文档，没有证明 Pi 集成已运行。
- [Pi Durable README](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md)
  标为 Experimental；列出的内置存储是 Memory、SQLite、JSONL，并要求一个进程拥有存储。
  不能把其会话持久化能力直接等同于 PostgreSQL 业务事务能力。

本决策没有运行性能基准、模型质量评估或恢复原型。“实时”和“准确”是产品目标；具体延迟、
错误率与资源预算必须以真实链路测量和评估确定，不凭框架名称承诺。

## 下一项验证

YUK-1338 用一个有真实业务含义的隔离竖切验证三个核心行为：

1. 新证据更新学习状态，并影响下一项学习安排；同时记录生效延迟与版本。
2. 推理期间出现新证据，旧版本结果不能覆盖新状态。
3. 在模型检查点、工具提交和回执边界终止并重启 worker，已提交业务效果不重复，已保存响应可复用。

先用可控模型替身和真实数据库、真实进程重启验证恢复与并发契约。模型实际输出质量、外部
provider 行为和费用属于单独证据，不能由替身测试替代。完成该验证后再展开迁移实施计划。

## 与当前系统的关系

本 ADR 取代 ADR-0051 §6 对**目标技术栈**固定为 Hono + Vite SPA + pg-boss 的选择，保留其
静态模块化应用和业务所有权原则；同时允许以 DBOS 实现通用执行机制，但不取消 ADR-0052
对领域交接语义和旧协议删除的证据要求。

当前运行代码仍为 Hono + Vite SPA + pg-boss，现役入口与部署说明仍以 README 为准。
本次交付是决策文档与跟踪记录，不包含依赖变更、业务迁移、生产写入、部署或 UI 代码。
