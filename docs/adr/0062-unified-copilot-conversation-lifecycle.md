# Copilot 只有一种持续会话生命周期

Owner 于 2026-09-06 明确“copilot的消息不应该分前后台，默认都是不被打断的，对标chatgpt等产品”。因此取消让用户选择 inline/durable 或 Mission 的方案：消息持久受理后由服务端拥有运行，浏览器只是可重连订阅者。关闭抽屉、刷新、网络断开不代表 Stop；显式停止、安全/费用限制或可解释的执行失败才产生终态。

复用现有 Copilot 会话、`copilot_run`、幂等受理、执行栅栏与终态恢复，不增加通用执行框架。按同一会话顺序持久接纳后续消息，在前一条结束后自动消费；已有活动消息不是 `session_busy` 拒绝理由，也不要求先停止再发送。相同幂等键但不同内容仍是冲突，安全的容量限制仍须明确返回，不能暗中丢消息。在线向同一 SDK query 注入补充内容是额外语义，未验证前不把顺序接纳冒充即时 steer。

此决定取代 ADR-0041 §3 的短/长根请求分流，不取代其同会话一次一 run、显式停止、可逆操作原则，也不恢复旧版抬高轮数的预算建议。统一执行不能以增大默认模型轮数或重试计费来实现。教学结构化行为及题目/回复原子写入保留；原生 SDK 续接、每轮学习状态、上下文压缩与发布校验由同一执行 owner 维护。

SDK 临时会话只可被确实拥有该文件的进程恢复，数据库中的 SDK id 不是跨容器存储证明。进程重启后以产品事件历史冷启后续消息，不重复执行已越过付费栅栏的消息；不在此任务增加共享卷或部署亲和。无本地缓存的新页面也必须从服务端发现已接纳、排队、运行中和完成的消息。实际模型与浏览器断线验收完成前，不宣称产品已满足以上协议。

## 实施边界

- 后端先补同会话顺序受理/唯一执行与教学、SDK 续接能力，再切换统一入口，避免只改 `durable` 默认值的半成品。
- UI 保留现有 Copilot drawer；owner 于 2026-09-07 批准修改发送、恢复和消息展示逻辑，不增加前后台开关或新表面。
- 生产部署、生产数据副本、SoT 开关、共享卷和历史数据删除不在授权范围内。
