## 1. 关键事实校正（勘察报告之上的实测修正）

实现 lane 必须先读这一节——以下三点与勘察报告不一致，是地雷：

### 1.1 分支拓扑：S1 + YUK-281 **不在本地 main**，而是同处一个上游分支

- 勘察报告称 S1 / YUK-281 「已 merge main」。**实测：本地 `main` 上 `app/(app)/questions/**`
  与 write 端点均不存在**（`git cat-file -e HEAD:'app/(app)/questions/[id]/page.tsx'` → 不存在）。
- 实测：`origin/yuk-288-question-bank-ui-s1` **同时包含** S1 只读 UI **和** YUK-281 写端点
  （`app/api/questions/[id]/route.ts` 已有 `export async function PATCH` + `DELETE`；
  `src/server/questions/write.ts` 已在该分支）。
- **结论（owner 决策点 D0）**：S3 lane 应从 `origin/yuk-288-question-bank-ui-s1` 切分支，
  而非从 `main`。否则编辑/删除依赖的 UI shell 与端点全部缺失。最终合并顺序由 wave/PR 协议决定
  （S3 → S1 集成分支 → main，或 S1+S3 合并后整体进 main）。

### 1.2 编辑/删除 CSS **未随 S1 ported 进 app**（勘察报告完全遗漏）

- S1 只把**只读侧 chrome** 从 `docs/design/2026-06-08-question-bank-ui/questions.css` ported 进
  `app/globals.css`（`.questions-loom` 作用域下）。
- **实测：编辑/删除态所需的 CSS 类在 `app/globals.css` 全部缺失**（grep count = 0）：
  `qd-edit` / `qd-textarea` / `qd-diffset` / `qd-chip-add` / `qd-opt-correct-tag` / `qd-sec-act` /
  `qd-note` / `qd-fam-rail` / `qd-fam-line` / `qb-modal` / `qb-modal-wrap` / `qb-modal-head` /
  `qb-modal-ic` / `qb-modal-title` / `qb-modal-body` / `qb-modal-q` / `qb-modal-safe` /
  `qb-modal-foot` / `qb-constraints` / `qb-constraint` / `qb-c-n` / `qb-confirm-field` /
  `qb-confirm-input`，以及 `@keyframes qb-pop`。
- **因此 S3 必须把这批类从设计 `questions.css` ported 进 `app/globals.css`**（沿用 S1 的
  `.questions-loom` 作用域 + token-only 约束）。`btn-danger` 已是全局类，无需重复。
- 动画红线已被设计稿满足：`@keyframes qb-pop { from { transform: translateY(8px) scale(.985); } to { transform: none; } }`
  —— **纯 transform，无 opacity 门控**。port 时**逐字搬运，不得引入 `opacity:0→1`**（design README +
  chat4.md L184-188 红线）。

### 1.3 DELETE 第一段（取关联计数）**不能走 `apiFetch`/`apiJson`**

- 实测 `src/ui/lib/api.ts` 的 `apiFetch`：非 2xx 时抛 `ApiError(message, status, code)`，
  **只从 body 提取 `error`→`code` 和 `message`，丢弃 `associations` / `has_associations`**。
- 而 DELETE 首次请求**故意返回 409** 且把关联计数放在 body 的 `associations` 字段里。
- **结论**：DELETE 第一段（无 `?confirm=true`，目的是拿到关联计数渲染弹窗）必须用**裸 `fetch`**
  自行读 409 body，**不能用 `apiJson`**（会把计数丢掉）。需手动加 `x-internal-token` 头。
  二段（`?confirm=true&version=N`）成功返回 2xx，可以用 `apiJson`。
  - token 取法复用 `getInternalToken()`（`@/ui/lib/api` 已 export）；裸 fetch 时手动
    `headers: { 'x-internal-token': token }`。401 处理可简化为透传错误（详情页本就有 ApiAuthError 壳）。

## 2. 端点契约（YUK-281，已在上游分支，逐字核对）

来源：`app/api/questions/[id]/route.ts` + `src/server/questions/write.ts`（origin/yuk-288-question-bank-ui-s1）。

### 2.1 `PATCH /api/questions/[id]`

请求 body（`.strict()`，未知 key 直接报错；血缘字段 `variant_depth/root_question_id/parent_variant_id/parent_question_id/part_index` 提前拦 400）：

```jsonc
{
  "version": 0,                 // 必填，乐观锁
  "prompt_md": "…",             // 可选，min(1)
  "reference_md": "…" | null,   // 可选
  "choices_md": ["…"] | null,   // 可选，每项 min(1)
  "difficulty": 1,              // 可选，int 1..5
  "knowledge_ids": ["…"],       // 可选；[] = 清空全部关联（合法）
  "kind": "mcq",                // 可选，QuestionKind 枚举
  "draft_status": "draft" | "active" | null  // 可选
}
```

- 至少要带一个可编辑字段（仅 `version` 报 400 `no editable fields provided`）。
- 成功：`{ ok: true, noop: boolean, version: number, event_id?: string }`
  - `noop:true` = patch 与现行 row 一致（无版本 bump、无事件）；UI 应当作一次成功保存对待。
- 冲突：`409` `code='conflict'`（version 不匹配）→ UI 提示「题目已被修改，请刷新后重试」+ refetch。
- knowledge 无效：`400` `code='validation_error'`，message 含 `unknown knowledge_ids: …`。
- 404：题不存在。

### 2.2 `DELETE /api/questions/[id]`

两段式：

**第一段** —— `DELETE /api/questions/[id]`（**不带** `?confirm`）：
- **永远返回 409**，body：
  ```jsonc
  {
    "error": "confirm_required",
    "message": "…",
    "associations": { "attempts": N, "mistakes": N, "fsrs_cards": N, "paper_refs": N },
    "has_associations": boolean
  }
  ```
- 注意：第一段**不需要** `version`（bot 修复后的正确行为）。

**第二段** —— `DELETE /api/questions/[id]?confirm=true&version=N`：
- 成功 `2xx`：`{ ok:true, archived:true, event_id, cascaded_part_ids:[…], associations:{…} }`（软删除=draft_status 改 'draft' + cascade 小题）。
- `409 conflict`（version 过期）/ `404 not_found` / `400`（version 缺失或非负整数校验失败）。

### 2.3 关联计数字段映射（设计稿 ↔ 端点，R2 决策）

设计稿 DeleteModal 列 5 项；端点 `QuestionAssociationCounts` 只返回 4 项：

| 设计稿行 | 端点字段 | 状态 |
|---|---|---|
| N 条作答记录 | `associations.attempts` | ✅ |
| N 张 FSRS 复习卡 | `associations.fsrs_cards` | ✅ |
| N 份试卷引用此题 | `associations.paper_refs` | ✅ |
| N 条错题归因记录 | `associations.mistakes` | ✅ |
| **N 道小题挂在此大题下** | **无 `children` 字段** | ⚠️ R2 |

**R2 决策（owner 决策点 D2）**：
- **方案 A（推荐，端点改动）**：`countQuestionAssociations()` 补一路 SQL 查
  `kind='question_part' AND parent_question_id=id AND (draft_status IS NULL OR <>'draft')`
  的活跃小题数，返回 `children`。`QuestionAssociationCounts` interface + route 透传 + write.route.test.ts 补断言。
  → 设计稿 5 项完整对齐；端点扩字段是兼容性扩展（新增字段不破坏现有调用）。
- **方案 B（UI 降级）**：UI 在 `associations` 无 `children` 时不渲染该行。
- **planner 建议 A**——`children` 是删除大题时最该警示的破坏面（会 cascade 软删小题），
  缺它的 confirm 弹窗有误导性。A 的 SQL 与既有四路 `Promise.all` 同构，成本低。

## 4. 数据流 / 接口变更

### 4.1 version 穿透（R1）

```
question.version (DB, 已存在)
  → detail.ts loadQuestionDetail 返回 version        [改]
  → QuestionDetail.version (types.ts)                [改]
  → page.tsx detailQ.data.version                    [读]
  → PATCH body.version / DELETE ?version=N
```

- **version 来源铁律（R7）**：始终读 `detailQ.data.version`（加载快照），**不进 React state**。
  PATCH/DELETE 成功后 `invalidateQueries(['question-detail', id])` → query 刷新 → 新 version 自动到位。
- `refetchOnWindowFocus:false` S1 已设，保持——避免编辑期间 dirty state 被 refetch 覆盖。

### 4.2 编辑态 state（page.tsx 本地）

镜像设计稿 `ScreenQuestionDetail`：
```ts
const [draft, setDraft] = useState<EditableDraft | null>(null); // null = 未脏，渲染用 detailQ.data
const dirty = draft !== null;
const [saved, setSaved] = useState(false);
const [editOptIdx, setEditOptIdx] = useState(-1);
```
- `draft` 持有可编辑字段子集（prompt_md/reference_md/choices_md/difficulty/knowledge_ids/kind/draft_status）。
- 渲染优先 `draft ?? detailQ.data` 的字段。`edit(patch)` → merge 进 draft、`setSaved(false)`。
- `detailQ.data` 变化（id 切换 / 保存后刷新）时 `useEffect` 重置 `draft=null` / `editOptIdx=-1`。
- **保存**：PATCH useMutation，body = `{ version: detailQ.data.version, ...draft }`；
  `onSuccess` → `setSaved(true)`、`setDraft(null)`、`invalidate ['question-detail',id]` + `['questions']`；
  `onError` → 若 `ApiError.code==='conflict'` 提示「题目已被修改，请刷新后重试」+ `detailQ.refetch()`，
  其它错误透传 message。

### 4.3 DELETE 两段式状态机（R6）

```ts
type DelState =
  | { stage: 'idle' }
  | { stage: 'loading_counts' }                              // 裸 fetch 取 409 计数中
  | { stage: 'confirm'; associations: QuestionAssociationCounts; hasAssoc: boolean }
  | { stage: 'submitting'; associations: …; hasAssoc: boolean };
```

流程：
1. 点「删除题目…」→ `stage='loading_counts'` → **裸 fetch** `DELETE /api/questions/${id}`（带 token，无 confirm）
   → 解析 409 body 的 `associations` + `has_associations` → `stage='confirm'`（打开 DeleteModal）。
2. 弹窗内确认（零关联免输入；有关联需输入「删除」）→ `stage='submitting'` →
   `apiJson(DELETE /api/questions/${id}?confirm=true&version=${detailQ.data.version})`。
3. 成功 → `invalidate ['questions']` → `router.push(目标)`（见 R5）。
4. 取消 / Esc / 点 scrim → `stage='idle'`。
5. 二段 409 conflict → 提示版本过期 + refetch + 回 `idle`（让用户重走）。

- **R5 删除后跳转**：`q.parent_question_id !== null` → `router.push('/questions/' + q.parent_question_id)`；
  否则 `router.push('/questions')`。`useRouter from 'next/navigation'`。

### 4.4 知识点 add（R3 决策点 D3）

- 全仓**无现成知识点搜索/autocomplete 组件**（实测）。
- **方案 A（推荐，S3 范围内）**：只实现 **remove**（chip 上的 `×`，对应设计稿 `qd-chip` 内 close icon
  → `edit({ knowledge_ids: filter(...) })`）。「添加」按钮（`qd-chip-add`）渲染为 **disabled + tooltip
  「知识点搜索 follow-up」**，并在 Linear 开 follow-up issue（见 §8）。
- **方案 B（超范围 +1~2h）**：基于 `GET /api/knowledge?q=` 做 text input + dropdown autocomplete。
- **planner 建议 A**：S3 scope 是「edit/delete 交互接线」，知识点全文检索是独立 feature，不应膨胀本 lane。
  remove 已能覆盖「改知识点关联」的减法；add 留 follow-up。
