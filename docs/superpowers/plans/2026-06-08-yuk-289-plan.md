## 1. 范围与红线（owner 约束，硬性）

给三个**只读浏览面**加「按科目」派生轴过滤，**零 schema 变更**：

| 面 | 派生路径 | 实现轴 |
|---|---|---|
| 错题 `/mistakes` | mistake → `failure.referenced_knowledge_ids` → effective_domain | API `?subject=` + 内存交集 |
| 笔记 `/notes`（artifact note 列表） | `artifact.knowledge_ids`（OR-containment）→ effective_domain | 新建 list API `?subject=` + SQL OR-containment |
| 图谱 `/knowledge` | node `effective_domain`（节点自带） | **纯 client-side** filter（无 API 变更） |

**终版红线（subject-is-view-not-structure，owner 钉板，违反即返工）**：
- 科目 = **派生视角**：`effective_domain` = node 自身 `domain` 属性 + 祖先继承（父链 walk 到首个非 null domain）。
- 按科查询**一律走派生轴**：实体 → `knowledge_ids` → `effective_domain` → `resolveKnownSubjectId`。
- **绝不**给 `question` / `mistake`(learning_record) / `note`(artifact) / `learning_item` 等实体加 `subject` 列。
- **永远不动树**：不改 `knowledge` 表结构、不改 parent 关系、不写 `domain` 字段。
- 复用 `resolveSubjectKnowledgeIds`（`src/server/knowledge/domain.ts`，YUK-288 已实现）——**不重写**它的 walk 逻辑。

### 与 YUK-288 先例的精确对照（照搬目标）

- **helper**：`resolveSubjectKnowledgeIds(db, subject): Promise<string[]>` — 一次拉全部 `isNull(archived_at)` knowledge 行，内存 effective-domain walk（镜像 `ingestion/tagging.ts:112`，`seen` 防 cycle，归档祖先自然截断 → null），用 `resolveKnownSubjectId(domain)`（**不是** `resolveSubjectProfile`，防 null/unknown 被归默认 wenyan 的 over-match）匹配 `subject`，返回命中 node id 数组。空数组 = 该科目当前无标注 → 调用侧空列表非 404。
- **API 接线**（`app/api/questions/route.ts` 行 25–30 / 64–95 范式）：
  - `ListQuerySchema` 加 `subject: z.string().min(1).optional()`；`safeParse({ subject: sp.get('subject') ?? undefined, ... })`。
  - `const subjectKnowledgeIds = q.subject !== undefined ? await resolveSubjectKnowledgeIds(db, q.subject) : undefined;` —— **三态**：`undefined`（无 subject filter）/ `[]`（subject 标注空 → 空结果）/ 非空（交集）。传入 reader。
- **reader 空集语义**（`src/server/questions/list.ts` 行 210–216 范式，**必须照搬**）：
  ```ts
  if (params.subjectKnowledgeIds !== undefined) {
    filters.push(
      params.subjectKnowledgeIds.length > 0
        ? knowledgeContainmentOr(params.subjectKnowledgeIds)  // OR of `@> [id]`
        : sql`false`,                                          // 空集 → 强制空结果，NOT 无过滤
    );
  }
  ```
  `subjectKnowledgeIds === []` **绝不能**退化成"不过滤返回全部"——必须 `false`。这是 over-match 的反面坑，三面都要守。
- **UI 科目 tab**（`app/(app)/questions/page.tsx` 行 63–67 / 78 / 95 / 296–303 范式）：
  ```ts
  const SUBJECT_TABS = [
    { id: '__all', label: '全部科目' },

  ];
  const [subject, setSubject] = useState('__all');

  // render: SUBJECT_TABS.map → 一排 tab，aria-selected={subject===t.id}
  ```

## 3. 数据流 / 接口变更（逐面）

### 3.1 错题面 `/mistakes`

**派生路径多一跳**（比题库复杂）：`listMistakeProjectionRows` 先 `listLearningRecords` 再 join failure events，subject 过滤只能在**最终 projection 层**做（`failure.referenced_knowledge_ids` 在 flatMap 内才可用，行 68）。

- `mistakes.ts` 改：
  ```ts
  export interface ListMistakeProjectionFilter {
    limit: number; since?: Date; questionIds?: string[];
    subjectKnowledgeIds?: string[];   // 新增；undefined=无过滤 / []=空结果 / 非空=交集
  }
  ```
  在 `records.flatMap((record) => {...})` 内、拿到 `failure` 之后加守卫：
  ```ts
  if (filter.subjectKnowledgeIds !== undefined) {
    if (filter.subjectKnowledgeIds.length === 0) return [];          // 空集 → 该 row 排除
    const hit = (failure.referenced_knowledge_ids ?? []).some(
      (kid) => subjectSet.has(kid),                                  // subjectSet = new Set(filter.subjectKnowledgeIds)
    );
    if (!hit) return [];
  }
  ```
  （`subjectSet` 在 flatMap 外建一次，避免 N×M。OR 语义：referenced_knowledge_ids 任一命中即保留——与题库 `knowledge_ids overlap` 一致。）
- `route.ts` 改：`GetQuerySchema` + `subjectKnowledgeIds = q.subject !== undefined ? await resolveSubjectKnowledgeIds(db, q.subject) : undefined`，传入。

> **量级注记**（风险，不阻断）：subject 过滤在 projection 层（晚于 `getFailureAttempts`），limit=100 单用户量级 OK。若未来量大，可考虑把过滤前移到 records 层减少 question prompt 查询——本 wave 不做，留注释。

### 3.2 笔记面 `/notes`（**从零新建 API + 页**，工作量最大）

**派生路径最直接**（无 note→question 中间层）：`artifact.knowledge_ids`（OR-containment over subjectKnowledgeIds）→ effective_domain。

- `notes-read.ts` 新增：
  ```ts
  export interface ListNotesFilter {
    limit: number;
    since?: Date;                       // created_at >= since
    types?: readonly string[];          // 默认全部 NOTE_TYPES
    subjectKnowledgeIds?: string[];     // 三态
  }
  export async function listNotes(db, filter): Promise<NoteSummary[]>
  ```
  WHERE 组装（复用既有写法）：
  - `inArray(artifact.type, [...(filter.types ?? NOTE_TYPES)])`
  - `isNull(artifact.archived_at)`
  - `since` → `gte(artifact.created_at, since)`
  - subject 三态：`undefined` 不加条件；`[]` → `sql\`false\``（空结果）；非空 → `or(...ids.map(id => sql\`${artifact.knowledge_ids} @> ${JSON.stringify([id])}::jsonb\`))`（复用 `notesForItem` 行 139–141）
  - `orderBy(NOTE_TYPE_ORDER, desc(artifact.created_at))`、`limit`
  - `.map(toNoteSummary)`
- `app/api/notes/route.ts` 新建：`GET`，`runtime='nodejs'`，middleware 已管鉴权。`ListQuerySchema`：`subject` / `limit`（默认 50 clamp [1,200]）/ `since` / `type`（可选，限 NOTE_TYPES）。`subjectKnowledgeIds = subject !== undefined ? await resolveSubjectKnowledgeIds(db, subject) : undefined`。返回 `{ rows: NoteSummary[] }`。
- `app/(app)/notes/page.tsx` 新建：照搬 questions/page chrome 惯例（Chrome / 标题 / `Stateful` / grid / stagger / `EmptyState`），`SUBJECT_TABS` + `subject` state + `useQuery(['notes', queryString])` → `apiJson<{rows}>('/api/notes?'+queryString)`。**仅列表 + 科目 tab**，不加额外过滤轴（见 owner 决策 D-3）。每行 link 到 `/notes/[id]`。

> **笔记 subject 语义**（owner 决策 D-4 已定）：一条笔记可标多个 knowledge（跨科笔记），subject 过滤语义 = 「**至少一个** knowledge_id 的 effective_domain 匹配选中 subject」（OR）——与题库 `overlap` 一致。在 reader / route 注释里写死这个语义。

### 3.3 图谱面 `/knowledge`（纯 client-side，无 API 变更）

`GET /api/knowledge` 返全量 `loadTreeSnapshot`，node 已带 `effective_domain`（行 46 `effective_domain: string | null`），图谱 subject 过滤完全 client-side（`passesFilter` 行 597–600 已用 `node.effective_domain ?? node.domain`）。**不碰 API**。

三处 UI 改造（KnowledgeGraph 内部 + page 驱动）：

**(a) domain chip 用 displayName（KnowledgeGraph.tsx 行 583–598 / 993–1008）**
现状：`distinctDomains` 返 raw domain string（`'wenyan'`），chip label 直接显示 raw。
改：chip label 映射成 subject `displayName`（`'文言文'`）。**坑**：`filter.domain` 是 raw `effective_domain` 字符串等值比较（行 599），而 raw domain 可能是 alias（如 `classical_chinese`），与 subject profile id（`wenyan`）不相等。
方案：保持 `filter.domain` 仍存 **raw domain string**（不破坏 `passesFilter` 等值语义），只在**渲染层**把 raw domain → `resolveSubjectProfile(d).displayName` 做 label（拿不到 profile 的 raw domain 回退显示 raw）。这样过滤逻辑零改、仅显示中文。

**(b) filter.domain 可 controlled（KnowledgeGraph.tsx 行 574–580 / 658–680 / 995–1006）**
现状：`filter` 完全内部 `useState`，默认选首字母序第一个 domain（行 664）。
改：`KnowledgeGraphProps` 加可选 `domainFilter?: string | null` + `onDomainFilterChange?: (d: string | null) => void`。
- 若传入 controlled props → `filter.domain` 受控于 page；chip 点击调 `onDomainFilterChange`。
- 未传 → 完全回退现有内部 state（**向后兼容**，避免破坏性）。
- 默认值：owner 决策 D-2「默认按科视图」——page 层初始 subject 不是 `__all` 而是第一个 subject profile（或最多 node 的 subject，简单起见取第一个 profile）；「全局视图」= 显式切到 `__all` → controlled domain = `null`。

**(c) 跨科 mesh 边渲染 + 图例（KnowledgeGraph.tsx `buildElements` 行 310–322 + stylesheet 行 ~115 + 图例 UI）**
- 在 `buildElements`（node map `nodeIds` / 可扩展为 `nodeById` 已在作用域）对每条 mesh edge 计算两端 node 的 `effective_domain ?? domain`，经 `resolveKnownSubjectId` 比较：不同 subject → edge data 加 `cross_subject: true`。
- stylesheet 加选择器 `edge[cross_subject = 'true']`：虚线（`line-style: dashed`）+ 异色（用现有 token，如 `--ink-3` 或专用强调色，不硬编码）。
- 图例：在现有 filter chip 区下方加一行「跨科连接 N」（N = visibleNodes 范围内 cross_subject edge 计数），仅当 N>0 显示。
- **不引入 schema 字段**：`cross_subject` 是 cytoscape element data 的运行时计算属性，非 DB 列。

**(d) page 驱动（knowledge/page.tsx 行 150 view state + 620 KnowledgeGraph 用法）**
- 加 `SUBJECT_TABS` + `subject` state（默认非 `__all`，见 D-2）。
- graph view：subject → raw domain 映射后传 KnowledgeGraph `domainFilter`。**映射坑**：subject profile id（`wenyan`）→ 该 subject 实际在树里出现的 raw domain（可能是 `wenyan` 本身或 alias）。简化：直接传 subject id 作 domain，并在 KnowledgeGraph `passesFilter` 比较前对 node domain 也过 `resolveKnownSubjectId`——即把过滤语义从「raw 等值」升级为「alias-aware subject 等值」。这是更正确的语义，且与三面派生轴口径统一。**此改动需同步改 `passesFilter`**：`resolveKnownSubjectId(node.effective_domain ?? node.domain) === filter.domain`（filter.domain 改存 subject id）。⚠️ `passesFilter` 是 exported + 有单测（`KnowledgeGraph.test.ts`），改语义须同步更新测试。
- tree view：`flattened` 按 `resolveKnownSubjectId(node.effective_domain) === subject`（`__all` 不过滤）。

> **图谱风险（最高）**：KnowledgeGraph props 接口变更 + `passesFilter` 语义升级是本 wave 最易回归处。controlled props 用「可选 + 未传回退内部 state」保向后兼容；`passesFilter` 改 alias-aware 必须同步 `KnowledgeGraph.test.ts`。建议图谱单独 commit，便于 review / revert。

## 6. 风险点（按严重度）

1. **【最高】图谱 props 接口变更 + `passesFilter` 语义升级**：controlled domain props 是破坏性变更，必须「可选 + 未传回退内部 state」保向后兼容；`passesFilter` 改 alias-aware（3.3d）须同步 exported 单测。图谱单独 commit 便于 revert。
2. **【高】笔记面从零新建**：无 list API、无 list 页，工作量≈题库列表侧。先确认 UX = 仅列表 + 科目 tab（D-3），不蔓延。
3. **【中】空集语义三面统一**：`subjectKnowledgeIds === []` 三面都必须 → 空结果（`sql\`false\`` / `return []`），**绝不**退化成无过滤。这是 over-match 反坑。reader 注释写死。
4. **【中】错题派生多一跳 + projection 层过滤**：subject 过滤晚于 `getFailureAttempts`，limit=100 OK；量大需前移，本 wave 留注释不做（phase-deferred 注释，project-memory）。
5. **【低】`resolveSubjectKnowledgeIds` 一次拉全树**：YUK-288 已验证，单用户百级节点 OK；mistakes/notes 各调一次，图谱不调（纯 client-side），无 N+1。
6. **【低】nav `/notes` 入口**：`TITLES.notes` + `PATH_ACTIVE /notes` 已就位，仅缺 NAV item，加一行即可。
7. **【低】视觉环**：三面都改 UI，按 project-memory「UI 视觉环：边做边看」用 playwright 截图 + visual-verdict 对照 loom 参考稿（错题/笔记/图谱）。注意先查 `:3000` 谁占着（OrbStack 容器）再 `pnpm dev`（跳 `:3001`）。
8. **UI design pre-flight（CLAUDE.md 硬性）**：三面都动 UI，实施前须逐字引用相关 design doc 段落 + 声明组件类型（page / tab 控件）+ 列 touch 文件，等 owner 批准才写 UI 代码。questions/page 已是批准过的 tab 范式，mistakes/notes 照搬属同一 design 系统；图谱跨科边渲染 + 图例是**新视觉**，须单独 pre-flight。

## 8. owner 决策点（须 owner 拍）

- **D-1 三面同批 vs 分批**：本 plan 按**同批一个 wave**（3 commits 链式）写，单 PR `Closes YUK-289`。若 owner 想分批（如先错题+笔记、图谱单独），可拆成两 PR——图谱风险最高，最适合单拆。
- **D-2 subject 视图默认 vs 显式切换**：终版「**默认按科视图，全局视图显式切换**」。错题/笔记面默认 tab 该落在 `__all`（全部科目，列表面通常想看全部）还是第一个 subject？图谱面默认非 `__all`（避免 hairball，与现有 D1「不默认全 domain」一致）。本 plan 取：**列表面（错题/笔记）默认 `__all`，图谱默认第一个 subject**——需 owner 确认是否要列表面也默认按科。
- **D-3 笔记面过滤轴范围**：本 plan 取「**仅列表 + 科目 tab**」，不加 type/状态等额外轴。若 owner 想要笔记面更丰富（按 note type tab、按 verification 状态），需扩 scope。
- **D-4 笔记 subject OR 语义**：跨科笔记（多 knowledge 标签跨科）按「**至少一个 knowledge_id 命中**」(OR) 归入该 subject——与题库一致。已在 plan 定，列此供 owner 知情确认。
- **D-5 图谱 `passesFilter` 语义升级**：3.3d 建议把 domain 过滤从「raw 等值」升级为「alias-aware subject 等值」（`resolveKnownSubjectId`），口径与三面统一但触及 exported 单测。若 owner 想最小改动，可保留 raw 等值 + 仅做 displayName 映射（subject→raw domain 映射在 page 层处理，alias 场景可能漏匹配）。本 plan 推荐升级。
