# YUK-1107 session cron test acceleration

The fixture uses the real DBOS scheduler with a two-second native cadence and
100 ms polling. It reads and validates the production schedule declaration before
overriding cadence in cron-mode workers. Production schedules remain unchanged;
legacy pg-boss still uses its real minute scheduler.

Owner's subsequent direction removes real minute waits: logical correctness is
checked by controlling fixture time. Production's 60-second horizon is unchanged.
An isolated PostgreSQL clock advances the application time while retaining the
actual phase/obligation queries. The producer trigger uses the same fixture clock;
its original function body is preserved and its search path is restored after
owned children exit. DBOS and pg-boss scheduler clocks remain real.

The held Timekeeper forwarder is aged logically beyond 61 seconds and must remain
an active blocking obligation with no receipt. Rollback computes the actual
production horizon, independently checks all three inputs plus 60 seconds, then
requires cooldown rejection one microsecond before it and acceptance exactly at
it. The rejection preserves controls and the ledger. A real pg-boss enqueue after
rollback verifies the producer/consumer and exact receipt without waiting for a
new minute occurrence; it no longer proves a second Timekeeper occurrence after
rollback.

Both scheduler processes must observe a common native point;
the database independently verifies SUCCESS, admission, receipts and retained
history. After both families' native behavior is observed, the fixture pauses new
native scheduling and settles existing workflows before time-boundary assertions.
Teardown repeats that check and verifies a quiet scheduling interval, then
awaits child exit. It does not prove simultaneous enqueue or shutdown under
continuous incoming ticks.
