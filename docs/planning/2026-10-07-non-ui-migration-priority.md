## 交付顺序

1. 完成 Pi + DBOS 状态版本、过期结果拒绝、进程恢复 gate 的审查与验收。
2. 完成 TanStack 前门及现有页面接入，明确 API 和 server function 鉴权边界。
3. 业务操作由页面命令、Pi 工具与后台任务共用；逐族迁移 DBOS，验证切换、重启、取消、未知外部结果及幂等行为。
4. 完成全部路由与任务切换后移除旧 SPA 运行路径、pg-boss 恢复职责、废弃依赖配置和无调用方适配层。Hono 去留根据现有 ADR 的职责边界裁决，不把留下未裁决的双栈称为完成。
5. 再按依赖和实际产品缺口逐项完成 Linear 残留功能。重复、被替代或已实现票须以证据合并/关闭；不是按票面盲目重复开发。

## 完成标准

- 只有一套最终运行路径；兼容层仅为过渡，每项记录调用方、退出条件和清理归属。
- PostgreSQL 保持业务事实来源；不新增与现有学习状态竞争的真相源。
- 每类任务有唯一恢复负责人；不可由 DBOS 与旧队列同时接管同一义务。
- pre-AI 确定性能力和用户已认可的行为保持可用；结构清理不能成为功能退化的理由。
- scoped tests、typecheck/lint/build、独立实际 diff 审查、exact-head CI 与真实业务/恢复验收分别记录；绿色测试不等同迁移完成。
- 收口审查包含旧调用方、路由、worker、配置、依赖及文档的清理核对，不能仅删除目录后宣称完成。
