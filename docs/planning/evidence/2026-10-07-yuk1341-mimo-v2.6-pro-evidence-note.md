# YUK-1341 — opencode-go/mimo-v2.6-pro runtime evidence note

日期：2026-10-07 · 实施分支：`fix/yuk-1341-mimo-go-runtime`（基于 origin/main
`5d738dbc0`）· 目标：让 product Copilot（及兼容的 generative/vision task）在
`opencode-go/mimo-v2.6-pro` 上可运行，且不削弱 capability / admission / cost 门。

## 1. 问题与 bootstrap 难题

- 线上 Copilot 走 `xiaomi/mimo-v2.5-pro` 时撞 402 insufficient_balance；
  `opencode-go` 的 runtime creds（`OPENCODE_API_KEY`）在 app/worker 均已就位。
- 唯一缺口是能力门：`opencode-go` 的 pi catalog JSON 不带 `tool_call` 位，
  `modelDefaults.capabilities.toolCalling:false` 是权威分类；needsToolCall 的
  kind（含 `CopilotTask`）在 `assertModelProfileCapabilityFit`（run-lifecycle
  构造期，付费调用之前）直接拒绝。生产入口 harness 因此**无法**在绑定前产出
  证据——这正是 ticket 点名的 bootstrap 陷阱。
- 解决顺序（绝不先广告能力再补证据）：phase A 合成 tool loop 先证明 wire
  真的走 tool call → 再翻 per-model binding → 再跑生产入口收正式封存。

2. 路由翻转（二选一，推荐 a，爆炸半径最小）：
   a. 面板 per-task DB override：`task.CopilotTask.provider=opencode-go` +
      `task.CopilotTask.model=mimo-v2.6-pro`（config write 侧
      `assertModelProfileCapabilityFit` 现会放行该 pair）；其余 kind 按需同理
      （QuizGen/QuizPlan/SupplyPlan/KnowledgeReview/Coach/Dreaming/
      ResearchMeetingDirector/Sourcing 及 vision 类）。
   b. 全局 env pin：`AI_PROVIDER_OVERRIDE=opencode-go` +
      `AI_PROVIDER_MODEL=mimo-v2.6-pro`（注意 `providerRequiresExplicitModel
      ('opencode-go')===true`，不设 model 会 throw；env pin 是 incident
      kill-switch，优先级压过 DB 行）。
3. registry 默认（xiaomi/mimo-v2.5-pro）不动；xiaomi 402 是该 lane 的 billing
   问题，需 owner 在 provider console 侧处理（YUK-863 域外）。
