## Behavior and implementation

`server/start/routes/practice.tsx` (new) registers the file route `/practice` with
`ssr: false`. It lazy-mounts the retained `loadPracticeFacePage` inside
`StartWorkbenchShell` + `<Suspense>`, passing the unchanged prop contract
`navigate`/`getQuery`/`setQuery`:

- `navigate` = `startNavigate` (document navigation to the Start owner or retained
  fallback), same as every mounted page route.
- `getQuery`/`setQuery` are a verbatim mirror of `admin.config.tsx`: `getQuery` is
  reactive through `useRouterState(select: location.searchStr)` so the page's
  `[getQuery]` re-sync effect keeps working across search-only navigation; `setQuery`
  is `router.history.replace` over the live `window.location.search` params, so all
  untouched query fields are preserved and replace stays out of the history stack —
  byte-equivalent semantics to the retained SPA wrapper, including hash handling.
- No `client` prop is passed: `PracticeFacePageProps` takes only
  `navigate`/`getQuery`/`setQuery`. All page and Copilot HTTP keeps the existing
  `apiFetch` → `/api/*` protocol, which in the Start server flows through the existing
  `api.$` catchall → original Hono app (token + epoch gate unchanged). TokenGate/token
  storage are shared components already inside `StartWorkbenchShell`.

`web/src/router.tsx`: `PracticeRoute` becomes
`import.meta.env.PROD ? StartPageEntry : <existing lazyRouteComponent>` — production
document handoff to the Start owner, matching the convention used by
today/inbox/mistakes/agent-notes/notes/events/admin routes. The Vite dev fallback
wrapper is byte-identical to before.

`server/start/routeTree.gen.ts` was regenerated by the existing `tanstackStart` Vite
plugin during `pnpm build:start` (not hand-edited); the diff is additive `/practice`
entries only.

No feature behavior changes. This is the entry mount only — it is NOT native transport,
NOT domain migration, and NOT a full-migration exit for the practice surface.
