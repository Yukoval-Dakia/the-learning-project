## 决定与执行责任

本线程负责产品取舍、设计细化、实施、验证、必要修复、GitHub PR 与审查处理、满足仓库门禁后的合并，以及这台 Mac 上的配置、发布和运维。owner 主要通过使用建议提供反馈，不再承担常规任务排序、UI 方案确认、逐次实施批准或逐次部署批准。

旧文档中的“待 owner 逐次批准设计/实现/付费验证/部署”不再阻止本授权范围内的工作。需要产品决定时，由 agent 给出具体方案、记录理由、独立复核并负责验收。UI 的设计引用、组件形态和变更文件仍应在实施前明确，已有持续授权替代反复向 owner 询问。

这并不把此前所有设计提案都改写成 owner 逐项批准。采用、修改或放弃具体提案的决定须明确标为 agent 在本委托下作出，并保留与目标的关系。

确实只能由 owner 完成的账号登录、外部权限获取等，报告具体阻塞，同时继续不依赖它的工作。用户后来的纠正、限制或暂停优先。

## 工作方式

- Linear 是任务、缺陷和跟进真相源；先去重，状态与实际结果一致。
- GitHub 保存可审查的代码与交付记录；保留独立 review、真实检查和仓库合并门禁，不以授权跳过正确性。
- 使用 T3 编排与已安装工具。owner 后续指定本项目工作模型为 OpenCode Go MiMo 2.6 Pro，子任务明确使用 `providerInstanceId=opencode`、`model=opencode-go/mimo-v2.6-pro`、`options={}`，优先于通用模型选择表。核对实际运行选择，不把配置回执当作已切换。角色与浏览器按任务选择。
- 一个工作树仅一个代码写入者；先识别现有工作与资源占用，避免抢写、重复部署和重复计费。并行写入使用隔离工作树。
- 本机只跑匹配改动的 scoped tests 与适用静态检查、构建；完整测试门禁交给 exact-head GitHub CI。
- 用户可见的交付需要实际浏览器/接口/数据效果证据；模型质量需要实际输出证据，不能用工具调用成功或替身测试代替。
- 记录决策与结果，便于无人值守续作；不新建没有产品消费者的自主平台、MCP 或额外控制系统。

## 部署与资源

部署和运维目标是这台 Mac。已有本机 Compose、数据库和数据目录应先辨认和复用，不要求迁往 NAS，不把开发演示误当生产交付。

生产变更前核对目标、版本、备份新鲜度、恢复证据、数据库迁移和现有任务义务。必须先在恢复副本上运行完整迁移，再停止全部 writer 并取得最终备份，最后迁移生产、恢复 worker、恢复 app。迁移后切回旧镜像不默认安全；只有副本兼容验证通过才能作应用回退，否则采用经验证的数据库与对象恢复方案，并明确备份后新写入的保留或损失。不可自动覆盖生产数据库。保留原用户数据、回退路径及部署记录；不用清库、删除队列、破坏审计或盲目重试来制造成功。

本机发布互斥目录为当前 runtime 下的 `deployment.lock`，其中记录线程、目标与阶段。接续任务先核对持有者和活动进程，不凭时间过期强占；通过验收或明确停止后释放。当前私有 Compose 只管理 app/worker/migrate，复用外部数据库网络和 mem0 卷；禁止对它运行 `down`、`--remove-orphans` 或 `down -v`。

可使用已提供的计算、模型和服务资源。真实模型验证给出具体场景、运行上限、结果与费用记录；未知费用保留未知。开发验证默认每次唤起不超过 $5、每天不超过 $20 的新增模型费用，未知请求按保守上限占用预算；这是执行纪律，尚非全局自动费用拦截器。用户主动学习和已有产品调度沿用其现有预算设置，不能声称开发预算覆盖全部产品费用。不把广泛授权解释为无限开支或自行购买新订阅。常规配置和已授权范围内的资源使用不反复询问。

不修改与任务无关的用户级 provider/auth/telemetry 配置，不公开凭据，不停止未识别的其他工作负载。应用内部已经授权的数据处理可以运行；新接入私人数据来源、对外分享或代表用户联系他人不从本运维授权自动推导。
