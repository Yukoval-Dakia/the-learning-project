## 设置入口与配置边界

设置仍存在于 `/admin/config`。`src/kernel/ui-surfaces.ts:225` 注册 search 而未注册 nav；`src/ui/shell/nav-config.ts` 的侧栏只消费带 nav 的 surface，命令搜索则包含 Admin·配置。`ui/observability-shared.tsx` 的 AdminLinks 也有配置链接；subjects 两页使用自己的链接集合，没有该链接。这是源码导航结论，尚未在当前部署浏览器核验可见性。

config 的六个 section 为 overview、flags、ai-models、thresholds、locale、runtime。模型/预算和 locale 的编辑、确认、reset 与只读 flag/threshold 分开。facts_injected=false 禁用模型编辑；provider 凭据只显示存在状态，不下发值。runtime schedule 声明不证明调度器实际执行。

`api/admin-config.ts` 调用 `buildAdminConfigReadModel(process.env, facts)`；该读面依赖现有全局配置 store/registry，零 DB 查询不代表纯函数或全部依赖已注入。`server/index.ts` 在 serve 前注入 facts/writer；缺 writer 返回 503。写入沿 `src/server/config/admin-config-write.ts` 的 `createAdminConfigWriter(db=defaultDb)` → `mutateConfigs`，actor 保持 panel:admin；不得另建 writer。

UI 只有全部清空时选择 reset POST，否则 PATCH；保留 JSON 400、编辑权限、确认及 reset 契约。receipt 的 committed_epoch 与读取快照 epoch 分别表示提交和本进程应用；页面明确不保证 worker ACK。提交后刷新失败必须与写失败区分，不能再次执行写入来补刷新。Start canonical bootstrap 仍须接既有 hydration/facts/writer，不能将默认配置冒称有效运行配置。

## Subject 与 trait 写入

当前 API 壳为 `api/admin-subject-control.ts`、`admin-subject-trait-write.ts`、`admin-trait-write.ts`，复用 `src/server/subjects/{subject-control-write,trait-write}.ts`。API 仍承担输入校验、结果到 HTTP 的映射，并在 kind=ok 后调用 hydrateSubjectRegistryFromDb；领域函数存在不等于这个 post-commit 效果已迁走。

| 动作 | 当前输入/效果边界 |
| --- | --- |
| rename、retire、restore、reset subject | expectedRevision；rename 碰撞、陈旧 CAS、重复操作 noop 分开。general 不可 retire，general 绑定结构锁定使 reset 被拒绝；不是一律禁止所有 general 编辑。 |
| subject trait PUT | expectedSubjectRevision 与 expectedTraitRevision 双轴；自有 trait 原地编辑，非自有 trait 在同事务 fork-and-edit。general 自有种子可编辑及 fan-out，但不能 fork/换绑。 |
| shared trait PUT | expectedRevision；显式影响全部绑定者，走既有 fan-out 校验，不变成局部 COW 编辑。 |
| fork、换绑、reset-to-seed | 保留确认、来源/绑定和 revision 语义；created 返回 201，既有/noop 返回 200，journalLocation 保留。 |
| validate | 零写校验；422 issues 保持结构与受影响绑定者，不折叠成一条无定位错误。 |
| rollback | expectedRevision + targetRevision；沿 rollback-forward 及 append-only journal，不删除历史。 |

UI 对包含 currentRevision 的 409 重新取数并显示 CAS 提示；名称碰撞等其他 409 留在当前编辑错误，不自动重放。写后 invalidates admin subjects、subject traits、trait journals、catalog/public subjects。迁移须保持 pending/confirm 和草稿，不把请求错误变成成功或清空编辑。

`api/admin-trait-journal.ts` 读取 getTraitJournalPage：limit 缺省 100、最大 200，正整数严格校验，cursor 分页；响应同时保留 canonical data/page 与 legacy journal/next_cursor。页面只消费默认首屏，未做翻页。journal 不下发 payload；缺 trait 为 404，空 journal 是另一状态。`api/admin-traits.ts` 的 kind 校验和目录读取仍需随消费者接线，不能用全目录替代过滤。

## 既有领域读取与下一步边界

基线的四个管理 API 分别调用 `server/ai-observability.ts` 的 listAdminRunsPage、getAdminRunTimeline、getAdminCost、getAdminFailureClusters；不是只导出 listAdminRuns 这个旧 wrapper 就完成真实消费者迁移。

- runs：HTTP limit 缺省 50、最大 200，严格 Number 正整数/status/task_kind/cursor 校验和 collection envelope；详情保留原 params parse/errorResponse 路径与缺记录 404。直接传非法 params 时，ZodError 被现有 errorResponse 映射为通用 500；正常 [id] HTTP 路由可达性另验，不能误称原 handler 返回 400。嵌套 run/ledger/tool/timeline 日期须保持原 HTTP ISO/null 契约。
- cost：现有 rolling days 下界，不是 Today 的 BJT 日窗。1381 要注入单次 now，保留现有 normalization、没有上界过滤的行为、各 currency/truth/task/day 字段。
- failures：缺省 200，parseInt 非法或非正回退 50，上限 200；只查询最近失败窗口，按 reason/prefix 分组、每组最多五 sample，按数量与近期时间排序。

coverage/conjecture 不在 1381 写入范围。准确增量候选为 `api/{coverage-lattice,conjecture-scores}.ts`、`server/{coverage-lattice,conjecture-scores}.ts`、public.ts 及其 scoped tests；diagnostic-contracts 维持现有响应字段。

`loadCoverageLattice(db:Db,now=new Date())` 已复用 practice/public 的 assembleScanInput 与 scanCoverageGaps，再读活动事件、构建 DTO。它还读取 subject registry 显示名称，用 Date.now 记录 scan_ms。`practice/server/question-supply/target-discovery.ts:742` 的 assembleScanInput 目前只声明 Db，内部再用 Date.now 生成 evidenceDemandControl.neededBy；所以不能把外层 now 参数当整条调用链时间均已注入。跨 practice 的 Db|Tx/必要时钟变化须与主线另定界，本线程未改该文件。

`loadConjectureScores(db:Db)` 已有 bounded event/typed-state 查询和坏行过滤，使用 getEffectiveProbeResultStatuses 排除 corrected/dependency_inactive 的 probe 证据。保留 bounded scan 的诊断、缺失与损坏区分；不得用另建 selector 或回填历史取代当前真相。
