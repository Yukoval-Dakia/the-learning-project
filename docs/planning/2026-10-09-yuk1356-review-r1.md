## R1-P1-03 / P1 — DBOS scheduledAt 被用作 fresh recovery 授权时钟，延迟 tick 可越过七天边界

位置：`src/server/durable/judge-worker.ts:64`（至 65）。证据层：`SOURCE_PROVEN_NOT_EXECUTED_BY_REVIEWER`。

**触发：** DBOS reconcile tick 的 scheduledAt 为原件提交后6天23小时，首次执行或未 checkpoint 的恢复实际发生在7天以后。有效原件仅有 reserved_unsent/send_unknown、engine 权威确认 absent，或已有 SUCCESS delivery 而无 domain completion；新的 send 尚未在边界前授权。

**源码/实际证据：**

- `src/server/durable/judge-worker.ts:53`：schedule 参数和 workflow ID 固定；63-65 将原 scheduledAt 作为 now 传入 reconcile；70 行容许该 workflow recovery。
- `src/capabilities/practice/jobs/judge_pending_reconcile.ts:153`：now 在整次 sweep 固定为 args.now；300-326 的 capacity、七天 gate、reservation 和 send authorization 全部使用这个值。
- `src/capabilities/practice/jobs/judge_pending_reconcile.ts:312`：用旧 scheduledAt 计算 age <7d，实际7d后的 transaction仍会 admitJudgeRun 并 authorizeJudgeSend。
- `src/capabilities/practice/server/judge-operational.ts:259`：gate_checked_at 也持久化为传入的旧时间。
- `src/capabilities/practice/server/judge-run-dispatch.ts:230`：最终 send gate 校验 owner/phase/epoch/authorization digest，没有实际时间的 age 复核。

**后果：** 允许七天以后产生新的自动恢复授权并排队可付费执行的 delivery，同时把授权证据时间回填为旧 tick 时间。这不属于边界前已经授权/接受的 final delivery 继续完成的许可。即便去掉 scheduledAt 参数，整次 sweep 开始时冻结 now 也不能证明每条后续授权发生在边界前。

**最小修正：** scheduledAt 仅保留为 tick 身份/选择时刻；每次 fresh send authorization 在短 transaction 的 R 内读取当前服务端授权时钟，应用 <7d 规则并记录真实 gate_checked_at。测试可注入时钟。保留边界前已授权/接受 final delivery 的完成权。

**修复验证应保留：**

- 用真实 registered reconcile workflow 的旧 scheduledAt、当前>=7d 时钟，断言不新增 send receipt/enqueue/model。
- 覆盖首次延迟执行、未 checkpoint 重启，以及 sweep 中途跨过边界。
- 保留 <7d、恰好7d、两槽、unknown reservation 容量和 pre-boundary live final delivery 完成断言。
