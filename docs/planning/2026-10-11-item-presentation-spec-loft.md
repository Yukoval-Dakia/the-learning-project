## 2. 展示说明长什么样

它是现有五层契约（`src/core/schema/assessment/`）上面的**一层视图**，不另起炉灶：

| 东西 | 住在哪 | 本文是否新增 |
|---|---|---|
| 题面显示内容、积木顺序、作答方式 | 展示说明（新） | 新 |
| 作答位置的形状（slot_id、选项 option_id） | `ResponseSpec`（已有） | 不变 |
| 分数、判分方法、答案键、部分分规则 | `ScoringUnit`（已有，私有） | 断句加一种判据（§8） |

```ts
type ItemPresentationSpec = {
  specVersion: 1;
  revisionId: string;          // 随题目版本固定，字节进 revision digest
  blocks: Block[];             // 固定积木，按顺序
  slots: AnswerSlot[];         // 每个作答位置
};

type AnswerSlot = {
  slotId: string;              // = ResponseSlot.slot_id
  unitId: string;              // = ScoringUnit.scoring_unit_id（校验时与契约对账）
  label: string;               // 只是显示，"(2)""第 3 空"
  input:
    | { mode: 'photo_or_handwriting'; typedAllowed: boolean } // 默认：屏上手写或拍照，整张交 AI 判
    | { mode: 'choice' }                                      // 点选：选项、断句字缝等
    | { mode: 'short_text'; maxChars?: number };              // 可选打字（英语单词等）
};

type Block =                    // 封闭集合，共 13 种
  | text | passage | figure | table | formula
  | options | matching | sentence_breaks | ordering
  | audio | code | subquestions | sandbox;
```

- 题干里的空写成 `{{slot:<slotId>}}`，只是“位置 + 编号 + 跳转”，输入控件放在页面规定的位置。
  `{{ref:<slotId>|文字}}` 是一段跳转锚点（如文章里画波浪线的那段），不算放置。
- `options` 积木**不带选项内容**，只引用 `ResponseSpec` 里那个选择槽；图片选项用 `optionMedia` 把 option_id 映射到材料。
- `sentence_breaks`：一行不带标点的原文，字缝可点（§4.3）。
- `matching`：左右两列只是显示，带一个手写作答位置，人在两列上直接画线（§4.4）。
- `subquestions` 只嵌一层，并声明每个小问下的作答位置（每小问一块手写/拍照区）。
- **布局不由 agent 选。** 有 `passage` 积木就自动左右分栏（R9）；没有就单栏。
- 展示说明是严格结构：未声明的字段（answer、solution、key…）会让校验失败。

## 3. 页面怎么承载

### 3.1 积木 → 现有组件

| 积木 | 画法 |
|---|---|
| text / passage | `MathMarkdown`（公式按 R7 用 KaTeX）；空和锚点变成可点的编号块 |
| figure | `StimulusFigure`（点开放大，放大层是浮层用玻璃） |
| options | `ResponseSlotField` → `ChoiceSetResponse`（单选/多选，数字键直选） |
| ordering | `ResponseSlotField` → `OrderingResponse` |
| sentence_breaks | 新的点字缝面：字与字之间是按钮，按下显示一道斜杠 |
| matching | 两列显示 + 盖在上面的手写面 + 拍照（`EvidenceComposer`） |
| photo_or_handwriting 的作答区 | 新的手写面 + `EvidenceComposer`（拍照/上传，已有） |
| table / formula / code / audio | 表格（格子可以是作答位置）/ KaTeX 块 / 等宽块 / `StimulusFigure kind="audio"` |
| 未知积木 | 取出可读文字，按纯文字显示，标“不认识的积木” |

注册表按积木种类写死（`block-registry.tsx`）；积木不取数据、不含业务规则（ui-next I1）。

### 3.2 布局

- 桌面单栏：题干 → 积木 → 每个作答位置的输入 → “写下想法（可选）” → 提交。学习伙伴在最右（C1）。
- 桌面有文章：文章左栏独立滚动，题在右栏，学习伙伴仍在最右。点文章里的空 → 右边那题滚到并亮一下；聚焦右边某题 → 文章里的空滚进视野并亮一下（1.6s 淡出，M6）。
- 手机（≤ 640px 容器宽，原型用容器查询）：
  - 文章题（R9 手机形态仍待定，这是候选之一）：顶部「文章 / 题目」切换；题目页上方常驻一条“当前空所在的句子”，点一下回到文章那一处。
  - 解答题：小问上下排，每小问一块手写区；“拍照代替”直接开相机。手机不出书写模式建议，主路径是纸上写完拍照。
  - 触控目标 ≥ 44px（A2 可达性）。手机端形态是浏览器 + 加到主屏幕（另一条线负责）。

## 4. 作答

### 4.1 网页笔写（A4）

PaperKit 是苹果的原生框架（Swift / SwiftUI / UIKit），**浏览器里调不到**。网页上用 Pointer Events 做等价的一套：

- 书写面是 `<canvas>`，`touch-action: none`，写的时候不滚动、不缩放。
- `pointerType === 'pen'` 时读 `pressure`、`tiltX/tiltY`，粗细随压力变。
- `getCoalescedEvents()` 补回一帧里合并掉的点；`getPredictedEvents()` 先画一段淡色预测线，抬笔后丢掉，体感延迟更低。
- 防手掌：笔在用（或 2 秒内用过）时，书写面上的 touch 一律忽略。
- 笔尾橡皮（`buttons & 32`）直接当橡皮；另有笔、橡皮、撤销、清空。
- 鼠标、手指也能写，只是没有压感。
- 笔迹存成**笔画（矢量）+ 图片**，作为证据交判分。

### 4.2 书写模式与平板自动建议（A4）

- **何时建议**：粗指针（`pointer: coarse`）且屏幕短边 ≥ 700px（平板），一道要写的题进入视野时；或者第一次检测到笔落在题目上（任何设备）。页面底部浮出玻璃提示条：“看起来你在用平板。要进入书写模式吗？”［进入书写模式］［这次不用］。点过“这次不用”的题不再提示；Esc 也算“这次不用”。手机不建议。
- **书写模式里**：同一页面的全屏状态，题目为书写重新排版——题干钉在顶部（可单独滚动）；有文章的题文章仍在左栏（R9）；手写区放大（每小问约半屏高）；书写面上不滚动，要滚只能在书写面外拖；顶栏有退出（Esc）、笔、橡皮、撤销、提交，并显示当前用的是笔、手指还是鼠标和压力。
- 自由手写的笔迹按宽度归一化保存，进出书写模式时跟着缩放；连线的手写面固定最大宽度，进出书写模式时不变形，线不会错位。

### 4.3 断句：agent 生成的点字缝（A3）

- 展示：`sentence_breaks` 积木放一行**不带标点**的原文（标点就是答案，校验会拦带标点的行）。字与字之间是按钮：点一下断开（出现一道斜杠），再点一下取消。可选 `candidateGaps`，只让卷面上 A–H 那几处可点。
- 交给后端：沿用现有多选槽，选项就是字缝（`gap_<i>` = 第 i 个字后面断开，从 0 数），作答是 `{ kind: 'choice', option_ids: ['gap_1','gap_10','gap_17'] }`。点按的位置是精确的，不需要追问。
- 判分：确定性。规则作为这道题的数据存进**私有**判分单元（答案键绝不进展示说明）。卷面「每对一处 1 分、超 3 处 0 分」写成：

```ts
{ kind: 'sentence_breaks',
  key: [1, 10, 17],
  scoring: { per_correct: 1, over_mark_limit: 3, over_mark_score: 0 } }
// 点的处数 > over_mark_limit → over_mark_score；否则 命中数 × per_correct
```

原型里可以直接点「师者所以传道受业解惑也人非生而知之者孰能无惑」的字缝，下方实时显示读出的断点和按规则算出的分（仅为演示规则；真实做题提交后才判，页面拿不到键）。

### 4.4 连线：只收手写，整张交 AI 判（A3）

- 两列条目只是显示；人在上面直接画线（屏上用笔/手指/鼠标），或者纸上画完拍照。
- 设备**不读线**。笔迹和图片绑到这道题的判分单元，整张交给准入的 AI 判分；私有判分单元里存参考配对和评分细则（如“每连对一条 1 分；同一项连出两条线的该项不得分”）。
- 这类单元和其他 AI 判分单元一样，要过单题标定（认对参考作答、认对等价画法、判错典型错连）才能出题（ADR-0073 草案 D2）。

### 4.5 选择、填空、解答

- 选择：一下点选；多选的部分分规则逐题存（示例：全对 4、漏选 2、错选 0）。
- 数学填空：空只是位置标记；作答区默认手写（或拍照），可展开打字。手写整张交 AI 判；打字走类型化判定。
- 解答：每小问一块手写区 + 拍照兜底；每小问的笔迹/照片绑到对应判分单元，交 AI 判。
- 任何题都能写“想法或过程（可选）”，另外触发过程分析，结果标“未核实”，不改分。

### 4.6 以后若做原生/套壳 app（只是选项，什么都没建）

用 PaperKit / PencilKit 能多拿到：系统级笔迹渲染和更低延迟、Apple Pencil 双击/捏合换工具、悬停预览、系统手写识别、和系统一致的标注工具。代价是要有 iPad app（或 WebView 套壳 + 原生书写层桥接）；书写数据仍转成“笔画 + 图片”交同一套判分，网页契约不用改。

## 5. 录题时的校验（入库前，挡住就不发题）

| 检查 | 结果 |
|---|---|
| 结构合法（严格结构、版本号对） | 不合法 → 拒收 |
| 未知积木 / 写坏的积木 | **不挡**，降级成纯文字显示，并报给录题侧 |
| 每个 `ResponseSpec` 里的作答位置在页面上恰好出现一次 | 漏了或重复 → 挡 |
| 每个 `AnswerSlot.unitId` 与契约里该判分单元的 `slot_refs` 一致；每个判分单元至少有一个作答位置可达 | 不一致 → 挡 |
| 作答方式与槽类型相容（点选只给选择/排序槽；打字只给 text/numeric/formula） | 不相容 → 挡 |
| 不泄题：积木文字里不出现参考答案（规范化后比较）；断句行不带标点 | 撞了 → 挡 |
| 沙箱积木必须有录题预览通过的记录 | 没有 → 挡 |

“放置”的口径：选项/排序/断句/连线积木、表格格子、小问声明的作答区才算放置；`{{slot:}}` 只在没有别的积木承载输入时才算（数学填空那种）。文章里的空只是锚点，不算重复放置。

## 6. 沙箱：极少数“拼不出来”的题（A2）

- 只负责**画**，里面不放任何作答控件；作答仍在外面的标准积木里，判分契约不受影响。
- `<iframe sandbox="allow-scripts">`（不给 `allow-same-origin`，拿不到 cookie、存储和页面数据），内容自带 CSP `default-src 'none'`，不能联网。
- 内容按摘要固定在题目版本上；录题时先预览：显示完整、可读、不泄题，通过才记 `previewApprovedAt`，否则不发题。
- 原型“附：录题校验”里有一个可拖动旋转的正方体截面，就是在这样的隔离框里画的。

## 7. 作答怎么回到判分

1. **点选**（选项、断句字缝）：编号 → 确定性比较器（部分分规则逐题存）。
2. **打字**：文字 → 允许答案列表 / 类型化判定。
3. **手写 / 拍照**（填空、解答、连线）：
   - 笔画 + 图片作为证据，绑到对应判分单元（现有 `GroupEvidence.target = { scope: 'units', scoring_unit_ids }`）；也可以一张照片拍整题，由判分那一步按小问对应。
   - 整块交准入的 AI 判分，用录入时冻结的方法和评分细则；判分结果附“读到了什么”，显示给学习者看。
   - AI 看不清的地方：**只追问一句**（“最大值这里写的是 3 还是 8？”），学习者点一下，回答作为澄清附在这次作答上再判；不答就记“看不清，待复核”（现有 `unreadable_evidence` 待定态），不猜、不记零分。
4. **想法 / 过程（可选）**：触发过程分析，标“未核实”，只进过程那条线，不改分。
5. 没有作答：只记“看过这道题”，不记一次作答。

后端收到的只有：`response_set.entries`（按 slot_id，点选和打字）+ `group_evidence`（手写/照片，按判分单元）+ 追问的回答 + 可选的学习者笔记。展示说明不进判分。

## 8. 需要动契约的地方

- `ScoringUnit.criterion` 加 `sentence_breaks`（键 + 每处得分 + 超限规则），或把“超限清零”做成选项集合判据的通用部分分策略。
- `ResponseSlot` 不加新类型：断句复用多选槽（选项 = 字缝）；连线是 `open_response`（收图片证据）。
- 作答记录加“追问与回答”（澄清）字段，和证据格式“笔画 + 图片”。
- 展示说明作为 revision 的一部分进 integrity digest（随 ADR-0074 草案定）。

## 9. 还没定、请 owner 定的事

1. **一题里多处看不清**：逐处各问一句，还是合成一屏一起问？
2. **诗词默写能不能打字**：打字会被输入法纠成正确的字，测不出错别字。建议默写只收手写/拍照，或打字作答单独标“不检查字形”。
3. **断句的候选字缝**：卷面是 A–H 涂卡的，展示成“只在这几处能点”还是放开所有字缝？前者忠于原卷，后者更接近真实断句能力。
4. **R9 手机形态**：原型试了“文章/题目切换 + 常驻当前句”；另一候选是带分隔条的上下分屏，和“不要上下”有张力，需要定手机是否豁免。
5. **作图题**（物理连电路、画 U-I 图线、生物画柱状图）：既然手写整张交 AI 判，是否也按连线的路子收手写、交 AI 判（同样要先过标定），还是继续不出这类题？
6. **学习者能不能看到“AI 读到了什么”**：建议判分结果里显示，方便发现读错并申诉；也可以只在追问时显示。
