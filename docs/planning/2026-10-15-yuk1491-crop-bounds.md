# 录入裁图边界修复（YUK-1491）

服务阶段：第一天能用。基线 `1f887ed`；产品修复 `8879892`。

## 故障与修改

`cropAndUploadFigures` 分别对起点和宽高取整。1275 像素宽的页面上，合法
`x=0.5,width=0.5` 得到 `left=638,width=638`，超过页面 1 像素。
真实 Sharp 调用抛出 `extract_area: bad extract area`；现役 OCR job 在付费
OCR 之后调用该函数，错误会使整次抽取失败。PDFium 3 升级不是此问题的根因。

修复将起点限制在有效像素内、宽高限制在剩余页面范围内。零面积框不生成图片；
后续裁图仍保留原始数组下标组成的 asset ID。微小正面积框保留一个像素。
原始 `source_bbox`、存储错误传播和配图隐私检查保持原语义。

## 实际验证

直接调用生产模块与 Sharp 0.35.5；页面为内存生成的 1275×1651 PNG，
R2 使用内存接收器读取输出 PNG 元数据，没有访问远端存储或模型。

| 输入 | 修改后实际输出 |
| --- | --- |
| 右半页框 `x=.5,y=.1,width=.5,height=.1` | 637×165 PNG |
| 下半页框 | 128×825 PNG |
| 右下角微小正面积框 | 1×1 PNG |
| 第一项零面积，后续三项有效 | 不上传第一项；结果为 fig-1、fig-2、fig-3 |
| 存储写入失败 | 原错误继续抛出 |
