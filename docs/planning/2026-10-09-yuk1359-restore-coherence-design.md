## Quiescence is an external operational precondition

The finite supported invariant is: throughout the interval from before the snapshot export until all dump/source reads, companion captures and sealing finish, no actor can change source table/schema/sequence state. This includes nextval/setval/sequence DDL, not only committed row writes. An idle connection with cached sequence values is still an actor.

Parent must establish and retain the existing exclusive runtime ownership and maintenance boundary. Stop intake and all writers, including app, worker, DBOS workers, schedulers, cron, administrative CLI and migration processes; prevent their restart/reconnect; drain or explicitly preserve interrupted obligations; account for replication and database-resident writing jobs; exclude uncontrolled database clients. A container-name list alone cannot cover host processes or remote clients. A mutex alone only coordinates cooperating operators. A read-only transaction or database default-read-only setting alone does not fence all writers. Do not introduce database ACL/configuration changes into these helpers to simulate this boundary.

Require `--quiescence-evidence=<file>` for a new full source capture. This is an input artifact supplied by the parent's already authorized maintenance procedure, not a new agent or subsystem. It identifies the runtime owner/window, source cluster/database, immutable source application/worker images and source revision, stopped writers and restart/admission controls, treatment of other clients/background writers, and an interval that remains held until explicit parent release. Missing, unknown or merely requested controls mean `quiescence_unestablished`; do not produce a usable source manifest. A bare `--writers-stopped` boolean is insufficient.

The helper validates the evidence shape and target identity, hashes its exact bytes, observes listed container states without stopping anything, and checks source sessions plus prepared transactions before and after capture. Exempt only the helper's exact session identities and understood nonwriting system processes; application_name by itself is not proof of ownership. Unknown background clients, prepared transactions, insufficient visibility or unavailable state inspection fail closed. Record observations and their timestamps. A parent-managed host writer cannot be independently certified by Docker inspection; preserve its external attestation as such.

These observations detect violations but do not establish the continuous invariant. Record `basis: "external-maintenance-boundary"` and `assurance: "operator-attested-with-observations"`, not `concurrency_proven:true`. Do not market a passing receipt as unconditional exclusion of arbitrary superuser activity. If the parent cannot actually enforce the invariant for the source, full capture is unavailable in this scope. A separate isolated source whose writers are fully controlled is suitable for the runtime acceptance fixture. Obtaining stronger automatic exclusion on an uncontrolled production source would require changes to its connection/admission controls outside the four files, and must be identified before implementation, not silently added.

Do not require writers to remain stopped for hours until a later scratch drill. Once the dump, source manifest and companion capture artifacts are sealed, parent can release the source boundary. Scratch verification only needs those immutable artifacts and an isolated scratch database without workers or other clients.

## One concrete capture flow

1. `cutover-final-backup.sh` checks arguments and target resolution, reads the external quiescence artifact and creates unique staging outputs. No status check may substitute a default success. Check the host `--target` and container connection against source cluster system identifier, database OID/name and server identity through read-only queries; same database name alone is insufficient. Lack of permission to obtain the identity is a failure. Do not log connection credentials. Resolve the source postgres image to its immutable ID/digest and capture server/client/extension versions. Repository HEAD identifies helper code, not necessarily the deployed source image.
2. Start a keeper with `docker exec -i ... psql -X -qAt -v ON_ERROR_STOP=1`. Keep stdin open. Issue `BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY; SELECT pg_export_snapshot();` and read its one validated snapshot token. Do not run the keeper via a command substitution that closes stdin or commits immediately. The TypeScript child-process owner awaits the snapshot response and continuously monitors premature exit. No background shell sleep is the snapshot lease.
3. Run source catalog inspection and each table read in read-only REPEATABLE READ transactions with `SET TRANSACTION SNAPSHOT '<token>'` before their first query. Run `pg_dump -Fc --snapshot=<token>` through the same container/database into a unique staging dump. Keep the keeper transaction open until both dump and every source reader finish. Use sequential table inspection to bound resources; dump and inspection need not run concurrently. Spawn argv arrays with `shell:false`; SQL identifier and SQL string quoting are separate functions. Snapshot values still require validation/escaping.
4. Source inspector enumerates every non-system schema, table and sequence and produces the content/state manifest described below. Sequence values are read directly while the external boundary is held. The snapshot fixes catalog/table visibility; it does not fix sequence visibility. Reject unsupported relation/type cases explicitly. Take sequence/inventory observations again at the end to detect some boundary violations, while retaining the external assurance qualification.
5. The bounded TypeScript capture operation executes the existing DLQ export query and invokes the existing migration-capture CLI as child processes, with verified target identity, inside the same maintenance interval. Move those orchestration calls out of the shell stages so they are not run twice; do not edit migration-capture itself. Their sessions need not be changed to import the snapshot because the asserted source state is unchanged throughout that interval. State this basis explicitly. Do not pretend the existing migration-capture implementation imported the snapshot. Preserve their exact file hashes in the source artifact's companion references if the final capture claims their coherence. Their failure prevents complete final capture.
6. Check all process exits and keeper health; validate TOC with a standalone successful `pg_restore -l` before counting/listing entries. Remove the arbitrary 100 KiB acceptance criterion, which excludes valid small test databases without proving larger dumps valid. Hash exact completed dump bytes by streaming, capture size and TOC result, and write a versioned source manifest containing that dump identity. Then close/rollback the keeper and await clean exit. If the keeper fails before controlled closure, fail the capture.
7. Publish artifacts only after these stages pass. Use a unique capture directory, temporary files and atomic rename; publish the manifest/ready reference last. A crash may leave partial files, which cannot be accepted without a complete valid manifest. There is no circular hash: the source manifest contains the dump hash; the restore receipt later contains the source manifest's exact byte hash. Existing migration manifest is a different artifact and is never substituted for this full source inventory.

On capture failure, preserve structured failure diagnostics and any useful dump as explicitly incomplete evidence. Never synthesize an empty successful inventory. Parent releases the external boundary on its own cleanup path; the helper closes only its own sessions/processes and never restarts writers.

## Shared inspector and canonical bytes

Use the same implementation and algorithm version on source and scratch. Define the scope predicate once: all `pg_namespace` entries except `information_schema` and PostgreSQL-reserved `pg_` namespaces. Do not use a business-schema allowlist and do not exclude schemas owned by extensions. Keep empty schemas in the schema set. Store identifiers as `{schema, name}` objects, never ambiguous `schema.name` keys. Compare arrays as sets keyed internally by a JSON tuple; reject duplicates. Catalog query output must use PostgreSQL JSON construction and a real JSON parser, never `-F '|'`, awk or interpolated JSON.

Enumerate `pg_class` relations with table kinds `r`, `p`, `m`, `f` and sequences `S`. Include ordinary, inherited, partitioned, unlogged and extension-owned tables in inventory. Record relation kind, persistence, partition/inheritance parent identities and the ordered visible column descriptors. Foreign-table data is not in an ordinary unfiltered pg_dump: record it and fail the full-parity capability check rather than silently omitting it. Materialized-view contents must compare if present; if unpopulated or unsupported, fail explicitly rather than invent rows. This is complete schema/table/sequence inventory and content parity, not exhaustive equivalence of roles, privileges, functions, indexes, large objects or external services.

For data-bearing local relations, select physical rows with `FROM ONLY <quoted schema>.<quoted table>` so inherited/partition children are each hashed once. Record partitioned parents with their metadata and zero local rows; their child set still must match exactly. Never replace leaves with a count/digest of a recursive parent scan. Check partition relationship identity as well as names. Views have no stored table rows and are outside the table content contract. Unsupported kinds remain explicit failures where relevant, not omissions.

Use a versioned logical text-byte contract, for example `pg16-column-text-sha256-multiset-v1`:

- Pin UTF-8 client output, `search_path=pg_catalog`, `TimeZone=UTC`, `DateStyle=ISO,YMD`, `IntervalStyle=postgres`, `extra_float_digits=3`, `bytea_output=hex` and `row_security=off` on every inspector session. Require compatible PostgreSQL and extension versions; record the exact versions. RLS must not filter rows silently. Insufficient privilege or a row-security error fails inspection.
- Order non-dropped columns by attnum; preserve column name, qualified type name, type modifier, array dimensions and collation identity in metadata. Do not compare transient catalog OIDs between source and scratch. Handle a valid zero-column table with the explicit empty-array row representation.
- For each row build `json_build_array(col1::text, col2::text, ...)::text` under those fixed settings, convert to UTF-8 bytes, then compute PostgreSQL's built-in SHA-256 and emit lowercase hex. SQL NULL becomes a JSON null; the string `null` stays a JSON string. All values are text before JSON construction, avoiding JavaScript numeric rounding and JSONB conversion of user JSON values. A JSON column's textual whitespace/key order is retained inside its text value; JSONB uses its database representation. Binary values use hex. Unicode is not normalized. Include every user column, including operational timestamps and durable checkpoint payloads; no migration fact-hash exclusions apply.
- Sort row hashes lexically under `COLLATE "C"`, preserving repeated hashes. Stream their ASCII hex plus LF through a host SHA-256 initialized with the fixed algorithm header and canonical column metadata. Count emitted rows as BigInt, serialize decimal strings. Empty tables hash the header/metadata with zero row records. Duplicate multiplicity is significant. Do not use XOR, checksum sum, sample, LIMIT, PK-only digest, ctid or physical row order.
- A value type must have a deterministic, value-preserving text output for this algorithm. Use an explicit documented supported type set for ordinary builtin value types and the actual vector type, including supported arrays/domains recursively. Reject OID-reference types, unknown user-defined output functions and unsupported types until their representation is defined and tested. Generic `to_jsonb(row)` is not a byte contract. Arbitrary identifiers are supported; arbitrary undocumented type output is not silently certified. The source manifest records any unsupported type and prevents verified parity.

The query shape is `COPY (SELECT h FROM (SELECT encode(sha256(convert_to(<row-array-text>, 'UTF8')), 'hex') AS h FROM ONLY <qualified relation>) AS rows ORDER BY h COLLATE "C") TO STDOUT`. The derived table makes `h` an input column for the collation expression, rather than relying on an output alias inside an expression. Generate identifier references with double-quote escaping or server `%I`, never shell interpolation. Set psql quiet/tuples-only and require clean exit with exactly 64 lowercase hex bytes per data line. Stream parsing must handle chunks split inside a line and reject truncated/extra output. SQL errors on stderr and nonzero exit invalidate the entire table.

This approach has bounded host memory and hashes full rows even for tables without keys. PostgreSQL performs the sort and may spill to disk. Bound `work_mem`, monitor available temporary space and give the operation an explicit deadline; exhausted disk, canceled queries, broken pipes or timeout fail the capture. Do not aggregate all rows with `string_agg/json_agg`, buffer COPY with spawnSync, or read the full dump with readFileSync. Hash the dump itself with streaming I/O as well. The first implementation does not need a chunk tree, paginated content protocol or resumable hashing. One table at a time and native external sort are sufficient. Each individual row still must fit PostgreSQL's supported value size; serialization failure is reported, never truncated.

Read every sequence using a safely quoted direct `SELECT last_value::text, is_called FROM <qualified sequence>`. Preserve a signed decimal string and a real boolean, including never-called sequences and values above 2^53. Include sequence parameters such as start/increment/min/max/cache/cycle and ownership identity to detect obvious contract differences, without pretending to prove all DDL equivalence. Do not use nextval, pg_sequences.last_value alone, max(table.id), or cached sequence metadata as state. Compare both sequence set directions and both state values. Sequence cache reservation is durable state; a read-only snapshot cannot freeze it.

## Scratch flow and artifact identity

`restore-drill.sh --dump=<file> --source-manifest=<file> --out=<receipt>` is the full mode. `--list-only` remains an explicitly limited TOC operation and never emits a verified parity receipt. For legacy dumps without a source manifest, require an explicit `--restore-only` mode; it may prove SQL loading but always emits `verified:false` and `level:"sql-restore-only"`. Missing source input in normal full mode fails with a receipt and nonzero exit.

Stage the input dump once in private scratch storage, stream-hash those staged bytes and restore that same staged file. Do not hash one host file read and later restore a potentially replaced second read. Parse/hash the source manifest from the same captured byte buffer, then validate its dump SHA and byte size against the staged dump. Check artifact version, algorithm and quiescence evidence before comparison. Hash and retain any externally referenced quiescence file; missing/mismatched references are failures. No path is an identity proof.

Start an isolated scratch Postgres at the compatible immutable image with no published service port, app or worker. Restore with existing single-transaction/exit-on-error semantics. A missing extension/role or restore warning promoted to an error is a failed SQL restore, not an excuse to filter data. Scratch inspection is read-only and precedes migrations or worker reopen. Capture the same full manifest from scratch; compare schema, table and sequence sets bidirectionally, then table metadata/count/content and sequence state. Extra restored tables and empty extra schemas also fail. Record explicit missing/extra/mismatch arrays using structured identifier fields.

Only the final successful comparison may derive `verified:true`. Persist source and restored inventories and differences so the TypeScript consumer can recompute the result, not trust summary flags. The receipt may embed these small metadata/digest inventories; no learner row bodies belong in diagnostics. Dump and manifest hashes bind evidence against accidental mixups or replacement; they are not an authenticated signature against a malicious party who can rewrite all artifacts.

## API and receipt contract

Keep a small set of named operations/functions inside `scripts/cutover-backup.ts`:

- `captureParitySource(options)` owns the snapshot keeper, dump subprocess, source inspection and source-manifest sealing. Shell calls `--operation=capture-parity` with source container/user/database, the migration-capture target, output paths and quiescence evidence. This operation also performs the existing DLQ query and invokes the existing migration-capture CLI as described in step 5. Existing final-backup shell remains the ordered entry point and keeps the maintenance interval through companion capture/sealing.
- `inspectDatabase(options)` shares catalog, table-stream and sequence logic. Source options require the exported snapshot token; scratch options use a local read-only snapshot. The container/user/database connection is passed as structured argv, not a URL interpolated into shell code.
- `compareDatabaseManifests({source, restored})` is pure and returns structured differences plus a derived status. `parseSourceManifest`, `parseRestoreReceipt` and `validateArtifactBindings` validate unknown input at the boundary with the existing runtime schema library if available. No type assertion converts arbitrary JSON into evidence.
- `finalizeRestoreEvidence(options)` validates stage results/bindings, recomputes comparison, atomically serializes JSON and returns the exit status. The drill calls it for success and failure. A compact failure union handles failures before source or scratch manifests exist.
- Existing manifest assembly accepts `--source-manifest`, `--quiescence-evidence` when referenced and `--require-restore-parity`. File hashing becomes streamed without forcing all pure tests asynchronous; use an incremental fixed-buffer synchronous file reader for the existing synchronous builder if needed.

Define versioned types in `src/core/migration/cutover-manifest.ts`, preserving the complete normalized result. Prefer discriminated unions for `verified`, `failed`, `sql-restore-only` and `legacy-limited`; keep the serialized `verified` field derived for compatibility. Unknown future versions are rejected, not treated as legacy. Advance the cutover manifest format version because the normalized receipt semantics change.

The source artifact contains `format:"loom-db-source"`, `version:2`, algorithm/version, source cluster/database identity, source image/revision distinct from helper revision, server/extension versions, snapshot token and capture interval, quiescence artifact identity plus assurance/observations, exact dump artifact identity, companion artifact identities when claimed, and complete `schemas`, `tables`, `sequences`. A snapshot token records how coherence was obtained; it is not a durable snapshot usable after capture.

The full restore receipt contains `format:"loom-restore-drill"`, `version:2`, `level:"database-content-parity"`, derived status/verified, exact dump identity, exact source-manifest identity, quiescence identity/assurance, immutable scratch image/container, phase outcomes, source and restored inventories, computed comparison/differences, structured errors and timestamps. `errors` is an array of `{phase, code, message, exitCode?, signal?, stderrTail?, truncated?}`. Counts and sequence values are decimal strings. A successful receipt requires complete inspections, successful SQL restore and all required bindings, no unsupported cases, accepted external quiescence basis, and zero differences. False comparison flags plus `verified:true` are invalid input.

For legacy input without the new format/version, retain its raw artifact hash and historical values as `level:"legacy-limited", reported_verified:<original>, verified:false`. Preserve supplied old table counts as historical observations, not full inventory. Do not alter the old file. Continue checking its dump SHA when a selected dump exists; missing/mismatched binding remains a hard error. Update the matched fixture at `scripts/cutover-backup.test.ts:152` that currently expects the unversioned receipt to produce current `verified:true`. Preserve its legacy claim as historical data and add independent current-proof gate tests; the old expectation must not lock in an unsafe new contract.

Manifest assembly rehashes selected dump/source/receipt bytes, checks all links, parses complete schemas, and recomputes comparison from the supplied source artifact and restored inventory. It validates phase outcomes and assurance fields as well as the digest equality. It retains the full result; no projection back to counts. It cannot independently prove that a claimed database inspection actually ran, so runtime evidence remains the parent's responsibility. `--require-restore-parity` without a dump/source/current successful receipt fails. A recorded failed comparison returns nonzero even without strict mode; missing or legacy-only restore evidence may remain an explicitly warned capture-only result when the restore gate was not requested. `--strict` retains its original required-artifact list.

## Failure handling

Initialize status to failed before creating scratch resources. Every subprocess has an explicit checked exit status and bounded cleanup. Use `psql -X -v ON_ERROR_STOP=1` everywhere. `set -e` alone is not a proof of pipeline error handling. Avoid the inner `pg_restore -l | wc -l` masking path; first save and validate the list, then count non-comment TOC entries. Any inventory, content, sequence, JSON parse, snapshot, artifact binding or comparison failure makes full-mode exit nonzero and `verified:false`.

Use JSON.stringify for all receipt strings and arrays. Never sed-escape stderr or construct table objects with awk. Diagnostic tails have an explicit byte limit and truncation marker; JSON control characters are escaped by the serializer. Do not expose credentials or row values. Temporary paths and arbitrary Unicode/quote/backslash/newline identifiers must round-trip. Use unique temporary names, inherited umask and atomic rename. Refuse receipt overwrite unless explicitly intended; a failed attempt must not leave an old verified receipt at the chosen path looking like the new result.

Install the finalization/cleanup path once output location is known, including readiness/TOC/preflight failures. Best-effort failure receipt plus nonzero exit is mandatory where the output filesystem is writable. If it is unwritable, a receipt cannot be promised: report the write failure on stderr and return nonzero. Cleanup errors must not turn failure into success; report scratch cleanup failure explicitly. SIGKILL or host loss cannot guarantee final receipt emission. Only a fully finalized receipt is consumable. Preserve failure evidence outside disposable stage cleanup.

## Rejected shortcuts

Adding `tlp_dbos` to the schema allowlist still misses arbitrary schemas and proves no source equality. Counting rows misses changed payloads. Computing the source manifest by restoring the same dump is circular. Exporting a snapshot without keeping its transaction alive is invalid; exporting one without quiescence does not freeze sequences. Before/after counts, digests, sequence observations or session polling can miss intervening changes and must not be called concurrency safety. Locking ordinary tables does not fence nextval or arbitrary new-schema DDL. Treating a boolean or a supplied matching hash as proof of runtime execution is unsound. Filtering extension tables, unsupported types or failed queries to obtain a green receipt violates complete coverage. A second backup service, generic job framework or automatic source recovery controller is unnecessary.
