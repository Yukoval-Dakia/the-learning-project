# 给备题 agent 的题库工具：接口与迁移提案

状态：**提案，供 Cordinator 评估后统一排期**。日期：2026-10-11。本文不代表实施批准、上线状态或实测收益。

交付范围是 agent 可调用的工具及其信息契约。产品代码、备题 agent 的教学策略、迁移执行和 UI 实现均不在本轮交付内。

## 1. 本轮需求与结论

Owner 本轮明确纠正了两个前提：

> 关键还在给 agent 什么工具。
>
> 当前已有的结构正在被推翻，或者说可以被改变，这些新方案会和迁移，功能改造与 ui 重写一起排期。

Owner 指定本轮输出为文档，交回 Cordinator 评估，随后排期实现。

**推荐给 agent 三个职责明确的工具：`search_bank`、`read_bank`、`check_bank`。** 名称是提议。它们负责找候选、取得内容、回答指定对象上的检查问题。备题 agent 决定练什么、选什么、如何组合、何时补题以及何时结束。

这份提案替代上一版中“查询层选择完整练习、组织后续阶段”的建议。上一轮的跨学科查询仍是有用的攻击材料，但不再作为扩张查询层职责的理由。本文包含完整查询附录，评估不依赖此前聊天、临时目录或交互演示。

当前表结构、模块、工具名称和 UI 都是迁移输入，不是新设计的硬边界。下面要求的引用、内容证据和能力状态，是为了让工具可用、让 agent 能判断；它们可以由全新的数据结构提供。既有 ADR 如需修改，由 Cordinator 一并裁决，不以“现在已经有某类型”决定保留，也不因类型存在就声称能力已实现。

## 2. 到底要减少什么摩擦

一个好工具应让 agent 少做以下工作：

- 把自然语言教学需求硬翻译成自己并不知道的知识点 ID、题型枚举和难度数字。
- 在多个近似工具之间猜测该调用哪一个，或手工融合向量、全文、图片检索结果。
- 为了理解一题，分别找题干、材料、图、解答、评分规则和出处，再判断它们是否对应。
- 反复复制完整题文与音频转写，仅为检查其中一个条件。
- 因摘要省略、索引缺失或搜索截断，把“没找到”误当成“没有”。

同时，工具不能靠代替 agent 做全部教学决策来消除这些摩擦。工具输出应该使决策更容易，而不是只交回一个不透明的“最佳练习”。

## 3. 责任划分

| 事情 | 题库工具负责 | 备题 agent 负责 |
| --- | --- | --- |
| 理解一次检索 | 处理本次 query、引用、范围，回显采用的条件与尚未验证的要求 | 决定为什么发起这次检索、需求是否需要追问用户 |
| 找到相关候选 | 选择合适检索通道、合并和排序候选，保留可追溯命中依据 | 判断候选是否值得进一步看，是否换检索方向 |
| 读取一题 | 找到对应内容、关联材料、来源、评分与可用能力信息 | 阅读和解释内容，作出教学判断 |
| 检查候选 | 回答 agent 明确提出的事实、关系或语义检查，报告方法、依据与未知 | 决定检查什么，怎样权衡检查结果 |
| 两题或整组 | 返回显式请求的关系事实；可检查 agent 已提出的组合 | 提出配对或组合，决定用途、顺序、是否采纳 |
| 个性化 | 使用调用中有权限的锚点，不擅自拉取和改写完整 learner state | 使用学习者工具获得需求与证据，决定个性化策略 |
| 缺题与后续安排 | 返回所查范围、缺少的证据或能力 | 决定继续找、外找、生成、换方案或以后再查 |

`check_bank` 即使内部使用模型，也只执行这次指定检查。不新增目标、不迭代搜索、不选择整套练习、不修改 learner state、不调用供题动作。检索相关性排序属于工具能力；教学效用排序、组卷与计划属于 agent 决策。

## 4. 比较三种接口形态

| 形态 | 调用感受 | 主要代价 | 裁决 |
| --- | --- | --- | --- |
| 一个 `prepare_questions(intent)` 返回完整方案 | 表面最简单 | 教学策略藏进工具；与备题 agent 重复；难解释失败来自搜索还是决策 | 不推荐用于这层 |
| 暴露 SQL、向量搜索、全文搜索、关系读取、图片下载等底层操作 | 能力组合自由 | agent 必须理解索引、数据布局和大量协议；迁移后提示词也跟着变化 | 留作内部实现或开发诊断，不作为日常主接口 |
| `search_bank` + `read_bank` + `check_bank` | 操作意图清楚，可按需组合 | 需要认真设计引用、返回内容和检查边界 | **推荐** |

两工具版本也成立：先只提供 search/read，agent 自己读原文判断。本文将它作为 LIGHT 选项。第三个工具的价值必须在批量或跨对象检查上验证；如果只是让另一个模型重复读相同内容、增加费用又不改善结果，就删去相应语义检查能力。确定性检查与模型检查应分别评估。

## 5. 共同契约：agent 拿到什么对象

### 5.1 内容引用与搜索句柄分开

- **内容引用 `ref`**：指向一次确定内容版本，可用于 read、check 和后续内容消费方。题、材料、原有题组都可以有 ref。它不要求沿用当前 question/revision 表，也不等于公开题号。
- **搜索结果引用 `result_ref`，可选增强**：短期候选集合句柄，用于反复在已召回集合内收窄。提供时必须带过期时间、所属调用上下文和集合范围。它不是学习者事实，不是题库条目；简单分页只需 cursor，不要求创建这类句柄。
- **续页 `cursor`**：只继续同一次检索快照。新 query 或范围变更应新建搜索；不能把 cursor 与新的条件混用。

内容引用不因结果句柄过期而失效。内容变更产生新版本引用；引用解析、权限和可用性仍要重新检查。短期句柄不能充当永久授权。无法解析或过期应明确返回错误，不能悄悄换成 latest。

`result_ref` 表示该次已经形成的有限候选池，可能大于已返回的一页，**不代表全库所有满足自然语言条件的对象**。响应应提供候选池大小、分页和截断情况。在其中进一步搜索不会扩大范围；要寻找池外候选，agent 发起全库新查询。

第一版可以使用显式 `within_refs` 而不实现结果句柄。§12 独立比较二者的上下文收益、生命周期成本与过期恢复；没有净收益就保留无句柄接口。实现是否提供 within_result 应写进工具能力说明，不能让 agent 通过报错猜测。

### 5.2 共同信息

每个候选至少给 agent：

| 信息 | 用途 |
| --- | --- |
| ref、对象种类、简短名称 | 能继续调用，避免重复粘贴题文 |
| 直接来自原文的相关摘录或媒体定位 | 看出为何被召回；原文缺失时不能补写成原文 |
| 关联对象摘要及可读引用 | 知道材料、原有分题、解答、评分和出处在哪里 |
| 已应用的确定性条件、尚未核实的要求 | 避免把召回当作通过全部要求 |
| 内容/能力缺口 | 缺图、缺出处、未支持执行等不能被“相关”掩盖 |

对象种类先以 question、material、group 表达检索对象；group 指已有内容分组，搜索不创建新的教学组合。代码仓库、音频、数据表等可作为材料资产，不必因此增加一套新工具。

不要求每道题先补齐统一的“教学用途画像”。已有可靠字段直接用；推断特征、反向查询扩展和向量属于派生索引，带内容版本、分析版本与来源，允许重建和撤销。科目与媒体专属能力通过可扩展描述表达，不把首批学科写成永久枚举。

## 6. 工具一：search_bank

**用途：找候选。** 支持自然语言、材料锚点、例题或作答锚点，并可限制查询范围。工具描述必须告诉 agent：返回的是候选，不保证每个语义条件已经满足。

概念签名，最终 JSON Schema 由实现设计补齐：

```text
search_bank({
  query: string,
  anchors?: [{ ref: ContentRef, instruction: string }],
  scope?: {
    subject_ref?: string,
    collection_refs?: ContentRef[],
    within_refs?: ContentRef[],
    within_result?: ResultRef,
    related_to?: [{ ref: ContentRef, relation: uses_material | part_of }],
    exclude_refs?: ContentRef[],
    kinds?: [question | material | group]
  }
})

search_bank({ cursor: Cursor })
```

两种调用形态互斥。常见请求只需要 query。已知科目或集合引用可以精确限定；agent 不必为了发出第一条查询先查一批内部 ID。锚点 `instruction` 表达“参考哪里”“保持什么”“改变什么”；它不负责制定教学策略。

`scope` 内条件是确定性范围。多个 collection 取并集，再与 subject、显式引用范围或结果池、related_to 和 kinds 取交集，最后应用排除。within_refs 与 within_result 互斥；within_refs 只包含明确列出的内容版本。省略表示不加该限制。within_refs、collection_refs 或 kinds 的空数组表示空范围，不得当作全库；exclude_refs 的空数组表示不排除对象，related_to 的空数组表示不加关系限制。

`related_to` 以候选为主语：`uses_material` 表示候选使用所指定的材料版本，`part_of` 表示候选属于所指定的已有题组；多项要求全部满足。若请求同一作品的不同版本，须另行解析作品关系，不能悄悄扩大版本范围。关系不存在与关系索引未覆盖分开报告，后一种不能假称全量查询得到空集。关系名首批限于有实现的这些关系，以后随版本扩展。

`exclude_refs` 排除解析到的同一内容对象，包括它的其他版本；这不自动扩大为“相似题族”。collection_refs 只接受可枚举成员的集合；查询材料下的题应使用 related_to，而不是把材料冒充集合或在材料结果池里切换 kinds。自然语言中的“同题族不要”“用这个字的凭借义”等语义要求，须单独说明是否核实。冲突或无法解析的范围不能被静默忽略。

内部可以结合字面量、全文、向量、图像与关系索引。agent 不需要选择 BM25、RRF 权重或 embedding model。检索算法可以变化，但已应用条件与响应语义要稳定。

最小响应示意：

```json
{
  "result_ref": "r:search-1",
  "expires_at": "<服务生成的时间>",
  "scope_applied": {"kinds": ["question"]},
  "requirements": {
    "enforced": ["只搜索题目"],
    "not_verified": ["与锚点连接关系相同"]
  },
  "hits": [{
    "ref": "q:example@v2",
    "kind": "question",
    "title": "电路连接判断",
    "match_evidence": [{"ref": "q:example@v2", "locator": "prompt", "excerpt": "<原题相关内容>"}],
    "related_refs": [{"ref": "m:circuit@v2", "kind": "material"}],
    "missing": []
  }],
  "coverage": {
    "candidate_pool_size": 12,
    "retrieval_truncated": true,
    "page_has_more": true,
    "unavailable_channels": [],
    "next_cursor": "<不透明续页值>"
  }
}
```

数字和引用均为示意，不是实际检索结果。示例展示提供可选 result_ref 的形态，无句柄实现省略它与 expires_at。`candidate_pool_size` 是有限池的实际数量，不冒充语义匹配总数。`retrieval_truncated` 与 `page_has_more` 分别说明召回截断和池内分页，翻完一池不代表搜索全库穷尽。尚未核实的要求必须继续保留；命中摘要不能暗示它已满足。模型生成的命中解释须标记为分析，并指向证据，不能伪装成 excerpt。

零结果时返回可恢复的信息，如“图像通道不可用”“范围中没有可读取题目”“这一有限池已看完”。它可以列出可用操作，但不自动放宽条件、外找、生成或切换教学目标。

## 7. 工具二：read_bank

**用途：取得指定内容与相关证据。** 支持批量读取，既可快速展开，也可取得完整内容。

```text
read_bank({
  refs: ContentRef[],
  include?: [content | materials | answers | rubric | source | relations | execution | metadata],
  focus?: string
})

read_bank({ cursor: ReadCursor })
```

两种调用形态互斥；ReadCursor 与搜索 cursor 分属不同操作，不能互换。默认请求完整主内容、媒体引用和关联概况，内容过长可以分片返回，不能把第一页称作完整。include 指定额外层；focus 指定优先定位的段落、图中部位或时间段。focus 是定位请求，不能让工具用一段模型总结代替原材料。媒体适配器不能提供所需区域或时间段时，返回完整可用资产或明确缺口。

响应要把原文、媒体、记录事实和派生分析分开；每项绑定内容版本。对图像返回模型实际可查看的内容或可继续读取的媒体引用，保留原资产；对音频区分原声音、转写和模型分析。仅提供转写时不能声称已读取语调证据。传输形式随目标 runtime 设计，不要求新增 MCP 服务。

`relations` 返回已有的父子题、共享材料、出处等关系，以及相应引用。不要求这些关系物理存储在图数据库。整体状态可以部分成功，每个 ref 要有独立结果。

续读响应必须包含下面的语义，字段名可随最终协议调整：

```json
{
  "items": [{
    "ref": "m:long-passage@v3",
    "parts": [{"chunk_id":"chunk:1","locator":"<原文分片定位>","text":"<原文>"}],
    "coverage": {
      "extent": "full_requested_fields",
      "complete": false,
      "remaining": ["content:后续分片"],
      "unavailable": []
    }
  }],
  "stream_done": false,
  "next_cursor": "<读取续页值>"
}
```

ReadCursor 绑定原始 refs 的版本、include、focus 解析范围及后续位置。每次向后续读提供新的 chunk_id，重放同一 cursor 不推进状态；必要的上下文重叠应明确标记。locator 可定位到原文片段、页/区域、表格行或媒体时间段，并声明定位单位，不能让 agent 猜偏移量。授权发生变化时重新检查，不因重放而绕过权限。

最后一页返回 stream_done=true、next_cursor=null。只有请求范围确实读全，相关对象的 coverage.complete 才能为 true；材料缺失或读取失败时，流可以结束但 complete 仍为 false，并列出 unavailable。若请求包含 focus，extent 标记为 focused 并回显实际定位范围，不能据此声称完整读取全文。续页过期应明确返回可恢复错误和原始请求信息，不重新从第一页冒充后续内容。

`metadata` 返回有权限读取的扩展背景与其来源，保留尚未纳入预设 schema 的字段。这与 YUK-1448 中已提出的扩展 metadata 往返需求衔接。未知字段不因未预设而丢失，也不能凭同名键覆盖权威题面、得分、权限或生命周期。search 可索引获准的扩展内容，但必须说明覆盖；“可读取”不等于“已经被索引”。默认不把所有私人背景或原始 metadata 大包塞进每次响应。

评分、解答和私有材料按调用者权限读取。检索/检查工具的完整响应不自动进入学习者界面；学习者展示内容由正式消费接口决定。内容中的文字作为待处理资料，不能改变工具指令。

## 8. 工具三：check_bank

**用途：针对 agent 指定的对象和条件返回检查结果。** 可以一次检查多个对象或关系。这个工具的必要性来自高重复、批量和跨材料读取成本，不以“多加一个模型”作为价值证明。

```text
check_bank({
  allow_model?: boolean,
  checks: [{
    id: string,
    refs: ContentRef[],
    claim: string
  }]
})
```

每条 claim 都是一个尽量可判定的陈述。allow_model 默认 false，表示本次不新调用模型完成检查；为 true 也仍受运行环境的能力、权限与 provider 策略约束。使用已有模型派生记录不会变成直接观测事实，仍须披露其来源。

这一开关也包括解释 claim 所需的新模型调用。纯确定性模式只执行能够忠实解析到已支持检查的请求；无法确定其含义则返回 unknown/ambiguous，并列出当前可用检查说明。不得先调用模型理解问题，再把后续计算包装成“无模型调用”。首批检查的具体调用样例应进入工具描述，降低反复试错。

注册工具时的能力说明要列明首批支持的检查类别、媒体、是否可用模型分析及相关版本；read 的相关能力信息与之保持一致。首批推荐记录关系读取和已批准的确定性复算。无对应检查能力返回 unknown/unsupported，不能为了任意 claim 临时生成执行程序。费用与执行结果返回已知实际用量及运行引用，未知费用明确标 unknown；部分完成、失败和未开始分别标注，不把它们算成 contradicted。

工具回显它采用的解释、实际依赖的对象与关系版本，再返回：

```json
{
  "checks": [{
    "id": "same-material",
    "claim": "这两道题关联的文章内容引用完全相同",
    "interpretation": "比较两题记录中的文章版本引用",
    "verdict": "supported",
    "execution_status": "completed",
    "method": "record_lookup",
    "inputs": ["q:a@v2", "q:b@v5", "m:passage@v3"],
    "evidence": [
      {"ref":"q:a@v2","locator":"material_refs[0]","value":"m:passage@v3"},
      {"ref":"q:b@v5","locator":"material_refs[0]","value":"m:passage@v3"}
    ],
    "steps": [{"method":"record_lookup","input_refs":["q:a@v2","q:b@v5"],"operation":"读取并比较两条版本化材料引用"}],
    "limitations": []
  }]
}
```

`verdict` 采用 supported / contradicted / unknown；method 区分记录读取、确定性计算、模型分析与混合流程。supported 是在所述方法和证据范围内支持，模型分析不能升级成逻辑证明。unknown 要能区分缺数据、能力不支持、证据矛盾和计算未完成。

inputs/evidence 必须涵盖结论实际依赖的题目、材料、关系、规则和执行能力记录的版本或等价不可变标识；独立于题目更新的关系和准入记录也要单独绑定，不能只引用最终文章或答案。steps 披露关键输入的取得方式及其未核实部分。例如先由模型提取电路连线或表格数字、再由程序计算，整体是 mixed；最后一步确定性不能抹去上游模型的不确定性。

缓存键依赖原始 claim、所用解释、全部依赖版本、检查实现/模型版本、权限与相关能力状态，并区分是否允许模型参与。依赖不完整时不作为可跨调用复用的已验证结果缓存；任何依赖更新或可用性撤回都要重新判定。缓存命中仍返回来源和方法。

工具不能把难问题改写成容易的问题后仍标 supported。例如“同一篇文章”不等于“两个 ref 字符串相同”：同一作品可能有不同摘录或版本。只做引用比较时，仅对这一较窄事实作结论；原始语义请求仍可能 unknown。interpretation 必须忠实于 claim，无法忠实归一化就报告歧义，不以执行后的解释替换原要求。

可用检查例子：

- 两题的材料引用是否相同；两个网页是否可追溯到同一原始来源。
- 两个指定命题的条件差异是否只有某一项，并给出差异位置。
- 某图是否包含可辨认的负坐标区域。
- 一组已指定小问是否包含回答另一问的直接线索。
- 数据表重新计算是否出现指定趋势。
- 指定规则和执行环境的已有准入证据是否齐备。

精确元数据或计算能回答的，直接使用确定性能力。语义检查只有在专门评测中证明值得时才接入模型，并向 agent 标明方法。缺少模型/媒体/执行能力时返回 unknown，不偷偷换成仅看摘要的判断。

以下请求仍由 agent 处理：“替我选最适合他的三题”“制定下一周安排”“判断他已经掌握”“不够就继续生成”。工具可返回无法作为局部检查执行的原因，不替 agent 拆成新的教学任务。工具也不在一次检查中安装依赖或执行任意候选代码；编译和运行属于另行获准的执行能力。

检查只回答指定对象，不能说明池外或全库没有其他答案。检查一组不等于优化一组；允许 agent 提出另一组再次检查，但不在工具里自动循环。

## 9. 调用推演：谁在做决定

下面都是假设引用的接口示例，未运行真实题库。它们展示表达力和责任，不规定 agent 固定按几步完成，也不设置总工具次数上限。

### 9.1 数学：相同错误机制，换表面情境

```json
{"tool":"search_bank","input":{"query":"需要检查定义域、但不依赖对数知识的方程题","anchors":[{"ref":"attempt:example@v1","instruction":"参考作答里跳过定义域检查的步骤；寻找可检验相同错误规则的其他题"}]}}
```

agent 自己决定是否把一次错误视为值得检验的假设。工具用这个锚点找候选，不宣告误解已成立。agent 可直接采用有充分依据的候选，也可 read 解答或 check 指定步骤；是否补充对照题由 agent 决定。

### 9.2 物理：保持连接关系，改变画法

```json
{"tool":"search_bank","input":{"query":"找画法明显不同的电路题","anchors":[{"ref":"m:anchor-circuit@v1","instruction":"寻找连接关系相同的候选；该关系需要有依据"}]}}
```

```json
{"tool":"read_bank","input":{"refs":["q:candidate@v2"],"include":["content","materials","answers"]}}
```

```json
{"tool":"check_bank","input":{"allow_model":true,"checks":[{"id":"connectivity","refs":["m:anchor-circuit@v1","m:candidate-circuit@v2"],"claim":"两图表示的端点连接关系相同"}]}}
```

工具返回端点或图像定位依据及方法。agent 判断是否足够、是否再找一个反例。图像相似度不会被当作连接等价证明。

### 9.3 语文：从材料进入题库

```json
{"tool":"search_bank","input":{"query":"课外散文，主题不要母爱，材料长度适中","scope":{"kinds":["material"]}}}
```

```json
{"tool":"read_bank","input":{"refs":["m:passage@v3"],"include":["content","relations"]}}
```

```json
{"tool":"search_bank","input":{"query":"手法赏析或主旨探究小问","scope":{"related_to":[{"ref":"m:passage@v3","relation":"uses_material"}],"kinds":["question"]}}}
```

agent 可以直接读取少量关联题，也可以用第三次调用只搜索这份材料的既有关联题，必要时批量读 rubric。它无需把材料结果池误用为题目范围。不存在目标小问时，agent 决定调用现有供题能力。搜索工具不把材料加工成一道新题，也不以无关题填满数量。

### 9.4 历史：比较来源，保留不同结论

```json
{"tool":"check_bank","input":{"allow_model":true,"checks":[{"id":"independent","refs":["m:source-a@v1","m:source-b@v4"],"claim":"两份材料来自不同的原始来源，而非同一原文的转述"},{"id":"rubric","refs":["q:comparison@v1"],"claim":"评分依据允许不同结论在论证充分时得分"}]}}
```

工具只报告这两个问题的依据。立场不同不保证来源独立；读取到一个评分文本也不保证判分器已被校准。agent 决定是否选用这些材料及如何提问。

### 9.5 英语：相同文字，不同语气

agent 以一段音频为锚点查找目标语气的另一段，read 原音频。check 若无法处理声音，就返回缺少原声分析能力。它不会凭两个相同转写做出“语气相同”的结论。是否采用、是否改成文字练习由 agent 判断。

### 9.6 编程：任务与环境都要读得到

agent 搜索离线 Python 边界错误任务，read materials 和 execution。工具返回仓库或包的固定版本、依赖要求、已存在的运行证据。agent 决定是否适合本次练习。查询不会安装依赖、启动沙箱或新建测评系统。

### 9.7 时间、曝光和下一阶段

“十分钟”“没见过”“三天后再测”可以出现在 query，但工具必须说明自己实际处理了什么。没有个人用时、曝光历史或未来状态时，不能自动补全。agent 自己调用相应的学习者或安排工具，决定范围和后续动作。题库工具只检查显式提供的引用或事实，不成为第二个 learner brain 或调度器。

## 10. 后端技术怎样服务这些接口

以下是有主来源支持的方法及本项目应用提议；没有哪篇研究替代了本项目验收。

| 手段 | 改善哪个工具 | 具体收益假设 | 采用条件 |
| --- | --- | --- | --- |
| 混合检索与按对象分层索引 | search | 字词、题号、材料内容和语义需求各有合适的召回方式 | 与强基线比较，验证不同科目与长材料，不只测平均值 |
| 页面/图像多向量与 late interaction | search/read | 减少 OCR 丢失图表、版面信息；保留可读取的原始区域 | 视觉查询提升值得存储和延迟成本；不声称能验证拓扑 |
| 锚点条件化检索 | search | 以真实题、作答、材料为参照，表达“保留/改变” | 锚点不能只变成一段泛化摘要；有反例评测 |
| 从真实对象生成可能的需求措辞 | search | 帮教师语言命中题库，不要求全库完整画像 | 扩展只用于召回，带来源和版本；不能制造不存在的用途事实 |
| 按需展开与批量读取 | read | 少回合取得证据，减少复制完整材料进上下文 | 必须显式报告省略，验证长文本及多媒体完整性 |
| 有限语义检查、确定性检查和版本缓存 | check | 减少重复跨对象阅读，把特定问题交给合适实现 | 检查正确率与成本优于 agent 直接 read；缓存不能跨权限/内容版本误复用 |
| 程序化工具组合 | 调用 runtime，后续选项 | 大批量独立调用时降低往返和上下文成本 | 只有真实调用瓶颈成立才用，不为三个工具新增代码执行平台 |

研究引用与适用边界：

1. [Anthropic, Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)：强调清晰职责、对 agent 有意义的响应与基于任务的工具评测。本文三工具划分是自己的设计，不是原文给出的题库方案。
2. [Anthropic, Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)：工具发现、程序化调用和调用示例是不同能力。这里只借鉴减少往返和提高调用正确率的思路，不绑定特定 provider。
3. [ColPali](https://arxiv.org/abs/2407.01449)：图像页面的多向量检索；只支持检索技术选择，不证明教学习题的关系核验正确。
4. [Document Expansion by Query Prediction](https://arxiv.org/abs/1904.08375)：从文档预测查询以扩展索引。将教师需求措辞作为扩展是本项目推论，需验证。
5. [LOTUS sem_join](https://lotus-ai.readthedocs.io/en/latest/sem_join.html)：自然语言谓词下的候选关系判断，可启发批量检查；不因此引入数据库框架或把语义判断当确定事实。
6. [FollowIR](https://aclanthology.org/2025.naacl-long.597/)：使用复杂指令与成对变化评估检索。这里要测工具是否尊重条件，也要测 agent 能否正确使用响应。

## 11. 和迁移、功能改造、UI 重写一起排期

### 11.1 可以改变的结构

题目与材料是否独立存储、版本与关系如何编码、全文/向量/视觉索引布局、工具注册位置、接口名称、检索结果 UI 和媒体展示均可重做。本文不要求兼容当前 `query_questions` 参数，也不要求保留既有 matcher 或 assessment schema。

需要保住的是能力及数据语义：能解析过去返回的内容引用、明确当前权限、保留原题/原材料/来源对应关系、区分数据缺失与分析未知。历史作答与评分如何迁移由整体迁移方案负责；本文只列工具对引用可追踪性的要求，不接管迁移策略。

### 11.2 建议拆分的交付包

| 包 | 主要产物 | 与其他线的接口 | 完成证据 |
| --- | --- | --- | --- |
| A：接口与引用协议 | 三工具描述、请求/响应契约、错误和过期语义、内容引用解析 | 和数据迁移确定目标身份/版本/权限映射；不依赖旧表名 | 契约样例与故障样例可执行；代表性材料可完整读取 |
| B：搜索与读取竖切 | search/read 接上真实目标题库，批量、分页、材料关系和媒体可读 | 功能线提供检索与读取；新 UI 消费同一内容引用 | 真实 agent 能找到并读到内容，UI 可显示同一版本与原始材料 |
| C：检查工具 | 显式请求的记录/计算检查；按证据逐项引入语义检查 | 复用或替换可用能力，保留方法与版本信息 | 与 agent 直接读材料的基线对比；错误与 unknown 可复现 |
| D：跨科质量与索引增强 | 图像检索、反向扩展、关系索引等有证据支持的改进 | 与模型路由、索引回填、资产迁移并排协调 | 保留题族的攻击集和真实 provider 调用评测通过 |

包名只用于讨论范围，不是已创建工单、排期或承诺顺序。A/B 的边界需与迁移和 UI 一起确认；允许按目标架构合并为竖切，避免先建一个无消费者的独立检索平台。

UI 必须能定位工具返回的同一内容对象，显示缺失材料与可读取证据；不必把内部打分、检索通道和全部检查原文都显示给学习者。学习者可见内容与备题 agent 可见内容有独立投影。这里不指定页面、抽屉或组件样式，交 UI 重写线设计。

### 11.3 LIGHT 与 FULL

- **LIGHT**：search/read，加少量已有确定性检查。用于尽快验证 agent 是否减少找 ID、重复读取、拼材料的工作；能明确报告不支持项。
- **FULL，推荐作为统一评估目标**：三工具完整契约、真实多模态内容读取、可靠的批量检查和按证据引入的索引增强。与迁移、功能改造和 UI 重写一起设计，可以更改现有结构。内部能力分段兑现，不要求第一天实现所有学科检查。

选择 FULL 不等于加入新备题 agent、新 learner brain、自动组卷器或查询 DSL。Cordinator 应按实际架构和数据状态决定合并或拆分，而不是受当前表结构限制。

## 12. 验收工具，而不只验收检索函数

固定真实 agent 的模型与提示、题库快照、权限和学习者输入，在相同任务上比较：

1. 当前可用工具基线。
2. 强自然语言搜索 + 完整读取。
3. search/read/check 提案。

先控制召回候选一致，验证响应格式、读取和检查是否减少摩擦；再比较端到端索引与工具组合。否则很难区分接口改善与 embedding 更换的效果。提示词中的调用示例和工具描述属于被测产物，应一起版本化。

另外做两个独立比较：check 的记录/计算增量与模型分析增量分别对照完整 read；有 result_ref 的反复收窄对照无句柄的新搜索和显式 within_refs。记录其稳定性、上下文节省与过期恢复成本，不能把全部 FULL 能力一起打包后推断每一项都必要。

验收要记录：任务完成质量、漏掉或擅改条件、内容与媒体取得完整性、错误的已验证声明、有效工具次数、重复读取量、传入上下文大小、延迟和实际费用。不能只用“调用次数少”或工具自己写出的理由评优。样本与阈值在实际跑结果前由 Cordinator 登记，本提案不编造数字。

必须包含的机制攻击：

- 同一材料与不同来源的条件互换，返回范围与检查结果应对应变化。
- 同一个题目版本被修改、删除、撤回，旧引用的行为明确；不偷换 latest。
- 图缺失、原音频不可读、来源不明、评分版本不匹配，不能被高相似度覆盖。
- 中文锚点、否定条件、长材料末尾信息、跨题答案泄露。
- 材料到关联小问的确定性搜索；关系索引未覆盖时不假报空集。
- 全文续读无缺口、cursor 重放与过期、focus 完成与全文完成的区分。
- 模型提取后确定性计算的 mixed 证据链；任一关系/规则版本变化使旧检查不可复用。
- 候选池截断、续页、过期句柄、在池内收窄与全库重查的区别。
- 一批检查部分失败，其他结果仍可解释；模型分析和确定性证据不混淆。
- 不同调用者权限、私有作答锚点与缓存隔离；返回引用不会扩大访问权。
- agent 自己提出的组合检查与“请工具替我决定”的请求分开。

附录是 42 条人工构造的种子请求，不能当成统计代表性样本或已通过的基准。需补充真实教师/学习者需求，并按共享材料、题族和改写家族隔离评测集。最终由真实 provider 调用工具、取得内容，再由消费者展示和使用，才能证明工具确实接通。离线检索指标不能证明学习效果。

| 决策 | 本文建议 | 需要协调的证据 |
| --- | --- | --- |
| 三工具边界是否成立 | 采用；教学选择留给备题 agent | 调用推演与代表性实际任务 |

| 首批覆盖哪些材料能力 | 至少覆盖纯文本与真实图表读取，其他按现役消费需求决定 | 实际题库与模型媒体能力；这不是宣称已具备 |

本轮只提交设计，没有改产品代码，没有调用真实题库做效果验收，没有排期、部署或向其他线程发送实施指令。Linear 查重以 YUK-1448 的题库方向作为已有相关规划输入；本轮没有新增已验证缺陷，不把待评估方案拆成重复工单，不改变现有 issue 的状态。

文档经过一次独立只读接口审查。材料关联搜索、长内容续读、检查依赖及混合方法披露三项缺口已补入；结果句柄与独立检查工具的增量价值保留为上述评估项。文档中的 JSON 示例仅通过语法与内部一致性检查，未据此声称接口已实现。
