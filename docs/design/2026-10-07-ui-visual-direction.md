# UI 视觉方向决策：导航骨架、工作台布局、token 与动效

日期：2026-10-07（Asia/Tokyo）。票：[YUK-1353](https://linear.app/yukoval-studios/issue/YUK-1353)，epic [YUK-1351](https://linear.app/yukoval-studios/issue/YUK-1351)。

状态：**定稿（agent 决定）**。依据[自主交付授权](../planning/2026-10-07-autonomous-delivery-charter.md)，由 Claude Opus 5.5 作出并承担验收责任；
另起 Claude Opus 5.5 独立视觉复核，结论与处置见 [review.md](2026-10-07-visual-loft/review.md)。owner 后续限制优先。

用途：**YUK-1354 起每张 UI 票的 pre-flight 必须引用本文规则编号**（如“遵循 N2、W2、T1、M5”）。偏离某条规则须在 pre-flight 写明理由，
并在该票的独立复核中裁决。本文只定方向与规则，不是组件实现，也不改变任何现役页面。

输入：[pre-flight](2026-10-07-yuk1353-visual-loft-preflight.md)、[评分表](2026-10-07-visual-loft/scorecard.md)、
[loft 原型与证据](2026-10-07-visual-loft/README.md)、行为设计 §4/§6/§7、ADR-0066、准备计划 §6（PR #1589）。

## 1. 选定方向：A「纸页」第二版

一句话：**安静的单栏阅读页 + 顶栏与命令面板；工作台是一份文档，帮助写在页边，宽屏把题干钉在左侧。**

| 方面 | 选定 |
| --- | --- |
| 导航 | 桌面顶栏三个去处 + `⌘K`，无常驻侧栏；手机顶层页底部标签栏，任务页让位给任务自己的操作条 |
| 首页“回来时” | 一段回来时说明 → 等大并列的“继续你的 / 系统建议” → 带来新的 → 其余可做 → 系统准备的 → 折叠的全部未完成 |
| 工作台 | 题干 / 我的草稿 / 页边帮助三处同时存在；帮助锚定到它针对的那一步，从不覆盖草稿 |
| 视觉 | 暖纸与暖墨、唯一珊瑚强调色、衬线叙述标题、层级靠字号字重灰度与底色差，阴影只给浮层 |

### 1.1 为什么是 A

评分（[scorecard](2026-10-07-visual-loft/scorecard.md)）：A 33 / B 28 / C 24（满分 35）。决定性的理由：

1. **三种进入方式真正等重**（行为设计 §4 第 78 行）：A 把“继续你的”和“系统建议”做成同尺寸并列卡，手机上两张都在首屏；
   B 在手机上把建议挤到首屏之外，C 把其他建议降级到“其他学习线”的次要行。
2. **帮助从不遮住自己的尝试**（§4.3 第 103 行）：A 的帮助写在页边并锚定到步骤，窄屏就地展开在该步下方；
   B 在手机上切到“帮助”标签时草稿不可见，C 的升起面板在手机上占 62% 高度。
3. **高级感来自克制**：A 的层级几乎全靠排版与底色差，没有仪表盘式的框与徽标；B 的密度适合管理面，不适合每日入口。
4. **手机是一等公民**：单栏结构在 390px 下不需要另一套信息架构。

### 1.2 第二版吸收了什么（loft 内修订）

第一轮评分暴露了 A 的两个弱点，按授权在 loft 内修订后再评，第一轮截图保留在 `evidence/round-1/`：

- **宽屏题干会滚走**：写到第 5 步时已看不到题干与图形。吸收 B/C 的“同屏”原则：≥1360px 把题干钉在左栏（W2）。
- **手机缺少拇指可达的导航**：吸收 B 的底部标签栏，但只在顶层页出现，进入工作台即让位（N2）。
- 同时补上顶栏的三个主去处与“系统为我做了什么”的状态指示（N1），避免次级区域只能靠 `⌘K` 发现。

### 1.3 为什么不选 B「工作室」

B 的三栏工作台在桌面上最好地满足“三位置同屏”，也最贴近现有 `RootShell`（侧栏 + 顶栏 + 手机标签栏）。不选的原因：
常驻侧栏在最重要的工作台上吃掉 232px，使三栏都变窄；首页成为面板仪表盘，信息密、层级平，与“回来时只呈现可以继续的事和有理由的建议”
（§4.1 第 82 行）相悖；手机上工作台退化为分段切换，帮助与草稿不能同看。B 的同屏原则与手机标签栏已被 A 第二版吸收。

### 1.4 为什么不选 C「学习线」

C 的“现在 → 分叉”最好地表达了连续性与“停下也是正式选择”，学习线的关联依据说明（“都需要先选择设直线的方式，不是因为都属于椭圆”）
也最贴近 §13.2。不选的原因：首页把跨线索的建议降为次要，所有安排都附着在一条线上；工作台的升起面板多一次开合，手机上遮挡大；
需要新造 Dock、Sheet、Timeline 三个原语，复用成本最高。C 的两点保留为规则：“停在这里”与继续、建议同级可选（H2），
关联须写明依据（H8）。

## 2. 导航骨架（N）

- **N1 桌面顶栏**：左为品牌；随后三个主去处“回来时 / 资料 / 我的学习”；右侧依次为“系统为我做了什么”状态指示（有“准备好了 / 需要复核”时显示点）、
  `⌘K` 搜索框、“＋ 带来材料”、外观与账户。**不设常驻侧栏。** 顶栏 56px，半透明底 + 模糊，滚动时保持。
- **N2 手机**：顶栏保留品牌（或页标题）、状态指示、搜索；顶层页底部标签栏为“回来时 / 资料 / ＋带来 / 我的学习”。
  工作台等任务页不显示标签栏，底部让给该页的固定操作条（提交、提示、讲解、停下）。
- **N3 命令面板**：`⌘K`（手机为搜索图标）是全局入口，分组为“继续 / 带来 / 这道题 / 前往 / 外观”；无匹配时回车把这句话交给学习伙伴。
  高频动作在面板中显示快捷键。
- **N4 任务上下文条**：从首页进入任务后，顶栏下方有粘性上下文条：返回“回来时”、任务标题与当前小问、下一项是否已备好、保存状态。
- **N5 §4.4 功能区落位**：“资料”承载按主题/来源/时间/目标/问题找资料与作品；“我的学习”承载判断与变化、纠正、关闭跟进；
  “系统为我做了什么”是指示 + 页面，显示后台结果、未完成工作与费用。管理面（`admin-*`）不进主导航，经 `⌘K` 与设置进入，
  沿用准备计划 §2 的 LIGHT 处理。
- **N6 现有导航的默认归宿**（P6 各波次票确认后实施）：今日 → 回来时；练习、录入 → 工作台入口与“＋带来”；收件箱、草稿审核、AI 观察 →
  系统为我做了什么；题库、笔记、知识、错题本 → 资料；Coach、画像 → 我的学习；Copilot 浮层 → 工作台页边的“问学习伙伴”与命令面板。

## 3. 首页“回来时”（H）

- **H1 顺序**：日期 → 回来时叙述（衬线一句 + 一两句说明，含未知与准备好的东西）→ 今晚可用时间（可改，注明来源）→
  等大并列“继续你的 / 系统建议”→ “或者带来新的”（拍照、粘贴、口述）→ “也可以”（逐行标“你的 / 建议”）→ “系统准备的”与本周费用 →
  折叠的“全部未完成 · 不会累积成欠账”。
- **H2 并列与主次**：继续与建议同尺寸、同层级；继续在阅读顺序前位并持有唯一主按钮（回车）；建议用次按钮“开始”与“为什么 · 换一种”。
  “今晚只记录 / 停在这里”始终是可见的正式选择（取自 C）。
- **H3 建议必须说明**：卡面直接给出“为了什么”与预计投入（标注“估计”）；展开后逐项给出 §7.2 的做什么、为了什么、为什么现在、需要、
  可以停下，以及一键替代（换成、推迟、不再跟进）。替代与推迟是乐观写入 + 撤销（M5）。
- **H4 准备状态诚实**：只有可用结果显示“准备好了”；“生成中”显示进度并禁用开始；“需要复核”用 caution 色说明原因与影响。
- **H5 久别**：标题直说多少天没见；说明“没有新记录只是没有新观察，不代表退步”；不累加到期任务；给出继续断点或 5 分钟确认两种方式。
- **H6 三态**：载入是与布局一致的骨架；空是三个进入方式（带来一道题 / 粘贴材料 / 让系统先提一个）；出错按区域隔离——
  建议取不到时，已保存的继续项照常可用，并给重试。
- **H7 确定性能力同级**：到期复习等不依赖模型的项与 AI 建议同列，并标“按复习间隔 · 不需要 AI”。
- **H8 关联要写依据**：任何“与之前相关”的提示写明关联依据（取自 C），不能只因同主题就归并。

## 4. 学习工作台布局（W）

- **W1 三位置不变量**：正在看的内容（题干、图形、材料）、自己正在做的东西（草稿步骤、作品）、围绕它的帮助（判断、提示、讲解、提问）
  同时存在于页面；**帮助不得覆盖自己的尝试**，打开讲解不清除草稿。
- **W2 断点**：
  - ≥1360px：左栏题干（360px，sunk 底，独立滚动，粘性）｜中栏草稿（阅读宽度）｜右侧页边帮助（300px）。
  - 721–1359px：单栏，题干与图形在上、草稿在下；页边帮助折叠成该步下方的标签按钮，点开就地展开；上下文条保留当前小问。
  - ≤720px：同上，另加固定底部操作条；从操作条请求的帮助在对应步骤下展开并滚入视野。
- **W3 帮助锚定**：每条帮助锚定到它针对的步骤（提示 1 ↔ 第 4 步；提示 2、讲解、判断 ↔ 正在写的一步）。宽屏页边注以浮动方式排在页边，
  后一条在前一条之下堆叠，草稿列不因页边注出现空白。
- **W4 步骤来源**：每一步标注来源与帮助条件（学校草稿照片 / 今晚 / 看提示 N 后 / 正在写）；识别不清的部分用中性虚线标记并注明“未用于判断”。
- **W5 帮助条件先说后做**：打开提示前写明会怎样记录（“打开后，第 5 步记为看提示后完成”）；讲解注明不改草稿与判分。
- **W6 临时输出不冒充生效**：模型流式输出以弱化文字和“生成中 · 未生效”标识呈现；完成后说明记录了什么（ADR-0066 第 45–46 行）。
- **W7 判分与解释分开**：确定性核对结果明确陈述；原因未判断时用中性虚线标“原因还没判断”，不按最终答案解释能力（§6.3）。
- **W8 不确定的呈现**：判断按“观察到 / 你说过 / 还不知道”分行；“还不知道”用中性虚线标记，**禁止使用 critical 红色**（§6.4）；
  数值只在含义与可靠性说明齐全时出现。
- **W9 草稿编辑**：点任一步进入原文编辑（等宽），失焦渲染公式；保存状态 100ms 内变化（保存中… / 已保存）；回车添加下一步。
- **W10 推广到其他活动**：三位置按任务映射，不改原则——阅读：原文为主栏、批注与讨论在页边；写作：作品为主栏、要求钉在左栏、反馈在页边；
  听说：音频与转写为主栏、可定位反馈在页边。具体形态在各活动的 UI 票 pre-flight 中声明。
- **W11 公式渲染**：KaTeX 样式表与渲染插件同包按需加载；现役页面从未加载该样式表，公式会以 MathML 加乱码重复显示
  （[YUK-1379](https://linear.app/yukoval-studios/issue/YUK-1379)）。

### 5.2 规则

- **T1** 组件只引用语义 token（`--bg*` `--text*` `--line*` `--accent*`、状态色、尺寸与动效 token）；色阶原值只出现在 token 文件。
- **T2** 新设计系统在独立作用域落地（例如独立 CSS layer 或根属性作用域），供 TanStack Start 前门（`server/start/`，PR #1592）
  下重写的页面使用；不复制、不继承 `web/src/globals.css` 的 1.58 万行；旧样式在 P7 删除（准备计划 §12 风险表）。
- **T3** 所有文本 token 在 `--bg` 与 `--bg-raised` 上 ≥ 4.5:1（`--text-disabled` 除外），亮暗两套都满足；数字使用 `tabular-nums`。
- **T4** 原型中仍有少量尺寸字面量（芯片高、状态点、图标尺寸等，见 scorecard §3），生产实现须收进 token（如 `--h-chip`、`--dot`），
  组件内不得出现裸数值。
- **T5** 主题默认跟随系统（`prefers-color-scheme`），用户显式选择后才持久化覆盖；现役 `RootShell` 总是写入 `data-theme`，
  导致系统暗色从不生效，新壳不得沿用。

## 6. 动效与交互（M）

- **M1 反馈**：任何点击/按键 100ms 内有可见反馈（悬停与按下颜色 90ms，按下 `scale(0.98)`）。
- **M2 移动**：160 / 220ms；只动 `transform` / `opacity`；进入位移 6px；退出更快（ease-in）。
- **M3 布局过渡**：页面切换用 View Transitions API 与命名元素，新旧快照不拉伸（`object-fit: none`），首页卡片标题与工作台标题共享名称、
  切换时形变衔接。页面内的展开、插入步骤、移除建议在原型中同样走 View Transition；4× 降速下这会触发整页快照并出现长帧
  （scorecard §4），且命名元素在过渡期间会画到粘性顶栏之上（`video/a-desktop-flow.mp4` 添加步骤处可见）；生产改用元素级 FLIP
  （只动 `transform` / `opacity`），只有路由切换使用整页 View Transition。
- **M4 减少动态效果**：`prefers-reduced-motion` 下时长归 1ms，不启用 View Transition，旋转与微光动画停止。
- **M5 乐观写入**：推迟、换一种、不再跟进等写操作立即生效并给 5 秒撤销；失败时恢复原状并用 critical 提示说明。
- **M6 预取**：继续入口在悬停/聚焦意图时预取工作台（TanStack `preload="intent"` 与 loader）；作答期间预取下一项，就绪后显示“下一项已备好”。
  预取包含昂贵渲染：公式在服务端（Start server function / SSR）或空闲时预渲染，不在切屏那一帧同步渲染（原型实测：空闲预热后 4× 降速下
  C 桌面 INP 由 240ms 降到 80ms，见 `evidence/metrics-before-math-warmup.json` 与 `metrics.json`）。
- **M7 键盘**：`⌘K` 面板；首页回车继续；工作台 `H` 提示、`E` 讲解、`D` 聚焦草稿、`⌘↵` 提交、`Esc` 收起、`[` 返回；按钮内显示快捷键，触屏隐藏。
- **M8 长列表**：资料、题库等长列表虚拟化（loft 未覆盖，相关波次票验收）。
- **M9 门槛**：INP < 200ms、CLS < 0.05、关键过渡在 4× CPU 降速下维持 60fps；每张 UI 票附真实操作录屏与指标。
  loft 实测（scorecard §4）：INP 与 CLS 在三个变体、两种设备、1×/4× 下全部通过；4× 下切屏与插入步骤出现 78–114ms 长帧，
  60fps **未达成**，按 M3、M6 处理后须在真实路由与中端手机上复测，未达成不得宣称满足本条。
- **M10 三态**：每个区域都设计载入（布局一致的骨架）、空（带进入动作）、出错（区域隔离、重试、已保存的工作不受影响）。
