## 0. 分层与排期

2026-10-09 owner 决定：**迁移期间不重写现有页面；UI 重写并入之后的功能改造，按功能区逐波上线。**
功能改造的方向由 [YUK-1388](https://linear.app/yukoval-studios/issue/YUK-1388)（全库审查与只基于目标的理想系统设计）给出，它允许推倒重建，可能改变页面的信息架构。
因此本文的规则分两层，经 YUK-1388 线程协商确定：

| 层 | 含义 | 规则 |
| --- | --- | --- |
| **稳定层** | 视觉语言与交互语法。现在就定，设计系统基座按它实现；改动须走本文的修订 | 外壳机制 N2、N4、N5（`⌘K` / `⌘J` / `⌘\`）；阅读页 R3、R4、R5、R6、R7；学习伙伴机制 C1（侧栏机制）、C2、C3、C4、C6；吉祥物 B2–B6；全部 T、A；动效 M1–M3、M6–M15；资料 L4；回来时 H5、H6、H7；迁移期间的约束 I1–I5 |
| **待定层** | 信息架构与内容组成。到功能改造的对应一波，以 YUK-1388 的理想设计裁决为准再定稿；在此之前只作为原型的现状记录 | 侧栏与标签栏的具体条目 N1、N3、N5 的首页 `N`、N6；回来时 H1–H4；题目页结构 R2；帮助的载体（R1、R8 中“帮助在学习伙伴里”）；学习伙伴默认开合（C1）与确认型建议 C5；资料 L1–L3；吉祥物各页尺寸 B1；动效的具体起点与落点 M4、M5 |

稳定层中与理想方向高度一致、应作为交互语法长期保留的四条：临时输出不冒充生效（C3）、判分与解释分开（R3）、不确定的诚实呈现（R4）、准备状态诚实（H5）。

YUK-1388 已预告会挑战的方向（待定层，届时裁决）：

- **帮助就地出现**：步骤级分级提示、卡住检测与主动介入，帮助可能锚定在题目的那一步出现，学习伙伴对话只是载体之一（R1、R8）。
- **单焦点今日**：回来时可能从“两张等大卡 + 列表”变为单一下一步加理由（H1、H3）。
- **审批最小化**：只改变当日或本周排程的建议，可能直接生效、可撤销、说明理由；只有改变目标、范围、考试日期级别的变更才需要确认（C5）。
- **劳动转嫁**：“收进来的”“系统为我做了什么”这类要求学习者去处理系统产物的入口可能取消，改为自动生效、可撤销、只在异常时通知（N1、N3、H2）。

**排期**：

1. **迁移期间**：只做稳定层的设计系统基座（YUK-1354，见 §0.1）与吉祥物（[YUK-1395](https://linear.app/yukoval-studios/issue/YUK-1395)，只动原型与其专属静态资源，不改应用入口、Service Worker 或 CSP）。
   不替换任何现役页面，也不把 UI 设为迁移的前置条件。
2. **迁移收尾**：旧 SPA 与 pg-boss 退役，全部页面跑在 Start 上，仍是旧界面。退役日期由迁移协调线（YUK-1359）在退出清单形成可信区间时给出，不预设。
3. **功能改造**：YUK-1388 给出功能区与顺序后，每一波拆两张票：先合后端（非 UI），再合 UI（只交 Opus 5.5）；用同一路由下新旧组件的切换开关上线，一周无 P0/P1 后删除旧组件。
   该波涉及的待定层规则在这张 UI 票的 pre-flight 里按理想设计定稿，并回写本文。
   第一波在迁移退出后直接上 Start。功能区与顺序由 YUK-1388 按真实功能票与数据契约给出，不依赖预设日期。

### 0.1 迁移期间的约束（与迁移协调线 YUK-1359 商定）

- **I1 数据走现有契约，渲染层可替换。** 页面读取与命令一律经已鉴权、带 epoch 边界的 Start adapter，调用现有的公开领域契约。
  - 新旧组件共用同一套类型化 client、读取 DTO 与命令契约；已有的类型化聚合直接复用，不为 UI 新建没有消费者的 view model 层。
  - 不把“取齐数据”理解为强制合并成单个大请求：今日摘要、隔夜摘要、费用、分页、自动刷新各自已有的载入、出错与时钟语义保持不变。
  - 页面可以持有本地交互状态与草稿，业务规则不得下沉到组件。
- **I2 不在旧组件上新增样式投入**，迁移期间只修缺陷与回归。
- **I3 同一路由切组件版本。** UI 波次的回退方式是：同一个 Start 路由下，在新旧两套组件之间切换。
  - 不重建旧 SPA、Hono 回落或双应用。
  - 开关在该波有真实消费者时，由 Start 的 owner 集成。
  - 组件回退不回滚数据、不重放写入；新旧两套组件都兼容当波的后端契约。
  - 一周观察窗口只用于让旧组件退出，不能成为保留旧 SPA 的理由，也不能用“一周没人用”代替验收。
- **I4 设计系统基座的位置与禁区。**
  - 基座放在独立目录 `src/ui-next/`（`tokens.css`、`primitives/`、`shell/`、`showcase/`、`public.ts`）与它专属的静态资源目录。
  - 样式用显式的根作用域或 CSS module，变量挂在新作用域下；不改 `:root`、`body`、全局 reset、全局字体，也不改现有的 `src/ui/` tokens、primitives、shell。
  - 展示页只交付组件与 props。路由由 Start 的 owner 挂到一个精确路径，基座本身不写 `server/start/routes`、`routeTree.gen`、router、frontdoor、context、boot。
  - 其余禁区：`web/src/router`、全局 manifest、package/lock/vite/build 入口、kernel、schema/drizzle、durable/boss/practice/AI、现有 `/mistakes` 及进行中的恢复工具。新增依赖须另行协调。
  - 复用成熟的可访问性、数学与编辑器能力；不另建 QueryClient、鉴权或业务状态系统。展示页只读使用公开接口，示例不得调用真实的业务写入。
- **I5 已知 UI 观察的归属**（不重复登记）：
  - Inbox 忽略某条后，页面计数 499 而侧栏 500，刷新后才一致：这是共享数据的刷新与失效契约，由对应波次的非 UI 票先修，不能只靠新视觉遮掉。
  - Google Fonts 的 import 被 CSP 拦截（fallback 可用）：归 YUK-1354 的字体方案，保持 CSP 不放宽，评估本地授权字体或既定 fallback。
  - 管理页把未知费用显示为 $0.0000：已有 [YUK-1382](https://linear.app/yukoval-studios/issue/YUK-1382)，管理 UI 波次须区分“未知”与“真实为 0”。

## 1. 选定方向

一句话：**像 Linear 一样克制的工作软件外壳，内容旁边常驻学习伙伴；玻璃只给浮层，动效只在变化时出现、可以打断，并说清东西从哪来、到哪去、算不算数。**

| 方面 | 选定 |
| --- | --- |
| 外壳 | 左侧可折叠侧栏（248 ↔ 60px）+ 内嵌圆角主框；主框里是 48px 顶栏和内容。`⌘K` 命令面板，`⌘\` 折叠侧栏 |
| 页面 | 回来时（含快速记录）、题目、笔记、资料四类。题目与笔记是阅读与复盘页，不是手写解题页 |
| 学习伙伴 | 内容旁边常驻侧栏（384px），`⌘J` 开合；默认在题目、笔记页打开，在回来时、资料页收起。手机上是可拖动的底部抽屉 |
| 手机 | 底部悬浮玻璃标签栏：回来时 / 资料 / 记一下 / 学习伙伴。往下读时标签栏收窄，往回滚时恢复 |
| 视觉 | 暖纸暖墨、唯一的珊瑚强调色、衬线叙述标题。层级靠字号、字重、灰度与底色差；玻璃只给浮层 |
| 品牌 | 吉祥物是一朵透明玻璃风车花，三维，每页 banner 一朵。logo 是另外设计的二维编织方块 |

原型：`docs/design/2026-10-07-visual-loft/prototype/`，入口 `index.html`。运行方式见 [README](2026-10-07-visual-loft/README.md)。

### 1.1 为什么这样选

1. **贴近真实使用。** owner 明确了主要场景：回顾、看题目、读笔记、与学习伙伴协作；手写暂不在内部做。
   因此主体是阅读页，原型里帮助集中在常驻的学习伙伴中（帮助的载体属待定层，见 §0），不再为手写草稿设计三栏工作台。
2. **学习伙伴是常驻搭档，不是弹窗。** 它固定在内容旁边，并知道“正在看”的是什么。
   回答里的引用可以点回正文，正文里被引用的段落也能点回对话（R5、C4）。
3. **高级感来自克制与准确。** 结构参照 Linear 的密度与侧栏，质感参照 Apple Liquid Glass，但玻璃只用在浮层上。
   卡片不投影，正文区没有装饰性动画。
4. **顺畅感来自连续。** 每个动画都回答一个问题：这个东西从哪来、到哪去、算不算数。动画只在变化时出现，任何时候都可以打断（M 节）。

### 1.2 演进过程

| 轮次 | 内容 | 结果 |
| --- | --- | --- |
| 第一轮 | A 纸页、B 工作室、C 学习线三个结构变体，首页 + 手写解题工作台 | 两轮独立复核后选 A + 三区同屏工作台（commit `147ce1615`）。owner 之后要求重新探索 |
| 探索 | D/E/F：贯穿的几何动画、毛玻璃与液态元素 | owner 否决：“表现欲太浓，不优雅美观，也没有考虑产品实际” |
| 讨论 | 动效只在变化时出现；参考 Linear 与 Apple Glass；三维几何或花作为随动标志物；结构与质感一起重来；聚焦回顾、阅读与协作；首页要有快速记录 | 先做标志物三样稿（花 / 几何 / 结），再整体 |
| 第二轮 | 吉祥物定为玻璃风车花（建模由 owner 指定的 Astra agent 完成），logo 单独设计；一套贴近产品的完整方案；手机布局；四组连续动画 | owner 认可，选定 |

第一轮的原型与证据只保留在 git 历史里（commit `147ce1615` 的 `docs/design/2026-10-07-visual-loft/`），
它们的规则已按本文重写，**不再作为引用来源**。

## 2. 导航骨架（N）

- **N1 侧栏**（待定层，见 §0）
  - 自上而下：品牌（logo + 字标）与折叠按钮；“搜索或跳转 `⌘K`”；主去处“回来时 / 资料”及资料下的“题目 / 笔记 / 错题”（带计数）；
    “我的学习”；“收进来的”（带计数）；“系统为我做了什么”（带计数）；“最近和学习伙伴”的对话；底部是外观切换。
  - 折叠到 60px 时只留图标，文字与计数淡出；宽度变化是布局过渡（见 M8）。
- **N2 主框与顶栏**
  - 主框内嵌，四周留出侧栏底色，带圆角与发丝线。顶栏 48px：面包屑（资料 › 题目 › 当前项）、当前页的主动作、学习伙伴开关（`⌘J`）。
  - 页面级的主动作放在顶栏，不放在浮层里。
- **N3 手机**（待定层，见 §0）
  - 侧栏隐藏。顶栏左侧是返回（详情页）与页标题，右侧是吉祥物的停靠位（B3）。
  - 底部悬浮玻璃标签栏：回来时 / 资料 / 记一下 / 学习伙伴。“记一下”是唯一的实心按钮，带“收进来的”计数。
  - 往下读超过 80px 时标签栏收窄；学习伙伴抽屉拉到一半或全屏时，标签栏让位隐藏。
- **N4 命令面板**：`⌘K` 打开，玻璃浮层。分组为“前往 / 继续 / 动作 / 外观”，高频动作显示快捷键，方向键选择，回车执行，`Esc` 关闭。
- **N5 快捷键**：`⌘K` 面板、`⌘J` 学习伙伴、`⌘\` 侧栏；首页 `N` 聚焦快速记录（随 H2 属待定层）。按钮内显示快捷键，触屏隐藏；只有图标的按钮必须有可访问名称。
- **N6 现有导航的默认归宿**（待定层，见 §0）（P6 各波次票确认后实施）：
  - 今日 → 回来时；录入、收件箱 → 记一下与“收进来的”；
  - 题库、笔记、错题本、知识 → 资料；
  - 草稿审核、AI 观察、后台结果 → 系统为我做了什么；
  - Coach、画像 → 我的学习；
  - CopilotDock 浮层 → 常驻的学习伙伴侧栏（C1）；
  - 管理面（`admin-*`）不进主导航，经 `⌘K` 与设置进入。

## 3. 回来时（H）

- **H1 顺序**（待定层，见 §0）：
  1. banner：日期、时段与今晚可用时间；衬线一句回来时叙述，加一两句说明（包含未知与已准备好的东西）；右侧是本页的吉祥物；
  2. 快速记录（H2）与刚收进来的条目；
  3. “接着来”：等大并列的“继续你的 / 建议”；
  4. “今天”：今天可做的事，逐行说明；
  5. “系统准备的”：后台结果与状态。
- **H2 快速记录**（待定层，见 §0）
  - 一行输入，加拍照、口述与意图选择：“只保存 / 帮我理解 / 一起做”。回车记下。
  - 记下后立即出现在下方，并带撤销；同时飞进“收进来的”（M5）。
  - 手机上由标签栏“记一下”打开玻璃底部表单，同样带意图选择。
- **H3 并列与主次**（待定层，见 §0）：继续与建议同尺寸、同层级。继续在阅读顺序前位，可用回车进入。建议用“为什么 · 换一种”展开。
- **H4 建议必须说明**（待定层，见 §0）
  - 卡面直接给出“为了什么”与预计投入，并标注“估计”。
  - 展开后逐项给出 §7.2 要求的内容：为什么现在、需要什么、何时可以停下，以及可替代的做法。展开用 0fr → 1fr 的高度过渡。
  - 推迟是乐观写入加撤销（M10）。
- **H5 准备状态诚实**：只有可用结果才显示“准备好了”；生成中显示进度并注明“还不能开始”；需要复核用 caution 色说明原因。
- **H6 确定性能力同级**：到期复习等不依赖模型的项与 AI 建议同列，并标注“按复习间隔，不需要 AI”。
- **H7 久别与三态**：沿用行为设计的要求——久别时直说多少天没见、不累加到期任务；载入、空、出错按区域设计，
  AI 建议取不到时，继续项与确定性项照常可用。第二轮原型没有覆盖这几种状态，由 W1 波次的 UI 票补齐并截图验收。

## 4. 阅读与复盘页：题目、笔记（R）

- **R1 三位置不变量**：正在看的内容（题干、图形、笔记正文）、自己的东西（草稿步骤、作答记录、批注）、围绕它的帮助，三者位置不混，
  同时存在于屏幕上。帮助的载体属于待定层：原型里帮助都在学习伙伴对话中；理想设计可能让步骤级提示就地出现在那一步旁边，对话只是载体之一（§0）。**帮助不得覆盖自己的尝试**；打开或收起学习伙伴不改变正文内容与阅读位置（M7）。
  - 手机例外：学习伙伴抽屉拉到一半或全屏时可以覆盖正文，但正文仍可滚动；从对话跳回正文（C4）时，抽屉必须先降到露出，被引用的内容完整可见。
- **R2 题目页结构**（待定层，见 §0）：banner（来源、标题、状态芯片：目标、范围、各小问的核对结果）→ 题目（题干、图形、小问、作业要求）→
  草稿（逐步列出，每步注明来源：作业照片 / 今晚 / 看提示后；识别不清的部分注明“未用于判断”）→ 我的作答（时间线）→
  系统目前的理解。
- **R3 判分与解释分开**：确定性核对的结果明确陈述（“与参考答案不一致（确定性核对）”）；原因还没判断时直接写明，不按最终答案解释能力（§6.3）。
- **R4 不确定的呈现**：理解按“观察到 / 你说过 / 还不知道”分行，“还不知道”用中性标记，**禁止使用 critical 红色**（§6.4）；旁边有“纠正”入口。
  - 掌握度等数值在含义与可靠性经过校准之前，不做成主视觉（YUK-1388 发现现有掌握度参数是未校准的常量）。
- **R5 可引用的锚点**：草稿的每一步、笔记的每一节都是锚点（`第 N 步`、小节标题）。
  - 被学习伙伴引用过的锚点，在页边显示一个小对话标记，点它打开学习伙伴并定位到那条消息（M6）。
  - 当前正在做的一步用左侧强调线标出。
- **R6 笔记页**：衬线标题与来源说明；正文 680px 版心，按节排列；自己的批注用强调线与小字标出。
  选中一段文字时浮出玻璃气泡“问学习伙伴”，选中内容作为引用发出（M6）。
  - 键盘也要能做到：用键盘选中文字后，有快捷键或聚焦可达的入口发出引用（原型只响应指针，未实现，见 A4）。
- **R7 公式**
  - KaTeX 样式表与渲染同包、按需加载。现役页面从未加载该样式表（[YUK-1379](https://linear.app/yukoval-studios/issue/YUK-1379)）。
  - 行内公式不断行；推导步骤可以在关系符处换行，并给公式行留出块向间距（KaTeX 0.19 的 strut 需要上下 0.2em 外边距）。
  - 引用、复制带公式的文字时保留 TeX 源（选区跨到公式时整段带上公式），引用里再渲染成公式。
- **R8 推广到其他活动**：阅读材料、写作反馈、听说练习沿用 R1：内容是主栏，自己的东西紧随其后，帮助锚定到内容位置（载体同 R1，属待定层）。
  具体形态在各活动的 UI 票 pre-flight 中声明。

## 5. 学习伙伴（C）

- **C1 常驻侧栏**
  - 桌面在内容右侧，宽 384px，与正文同在主框内，不覆盖正文。每个页面记住自己的开合状态。
  - 默认在哪些页面打开属于待定层（原型：题目、笔记页默认打开），随 R1 的帮助载体一起裁决。
  - 头部：名字、状态（“在这里 / 在想…”）、收起按钮。其下是“正在看：……”，说明它看到的上下文。
- **C2 手机抽屉**
  - 可拖动的底部抽屉，三个停靠点：露出标题（peek）、一半、全屏；回来时、资料页可以完全关闭。
  - 抽屉位置是带速度的阻尼弹簧：甩动时速度带进停靠点，动画中途可以再次抓住。点按把手在露出与一半之间切换。
  - 露出时正文区淡出，只留标题行，避免内容透过标签栏；淡出的部分同时不可聚焦（A1）。
  - 拖动被系统取消（来电、手势中断）时按松手处理，弹回最近的停靠点。
  - 键盘可以到达所有停靠点（原型只有标签栏开关在露出与一半之间切换，全屏只能拖动，未实现，见 A4）。
- **C3 临时输出不冒充生效**（ADR-0066 第 45–46 行）
  - 一条回答从第一个字到记录完成是**同一个元素**，原地变化：
    1. 在想：只有状态标记；
    2. 生成中：浅灰文字加光标，标注“生成中 · 还未生效”；
    3. 记录中：文字下方有一条细线在走，标注“生成完毕 · 正在记录”；
    4. 已记录：重新读取已提交状态之后，文字过渡为正常墨色，出现“✓ 已记录”，约两秒后收起。
  - 一条回答属于提问时的会话与上下文：切换页面后，它只在原会话里继续生成与落定，不会出现在另一页的学习伙伴里；
    在它完成之前又提出新问题时，它仍然记录在原会话里，不会被丢弃。
  - 生成可能持续数分钟（YUK-1388 实测一次可信的证据型回答约 13 分钟）：“生成中 / 记录中”必须允许离开当前页面继续阅读与记录，回来时看到原位落定的结果；
    不得用全屏等待或阻塞输入来呈现。
  - 生产中，第 4 步必须以重新读取的已提交状态为准，不能以流结束为准。
  - 吉祥物在想时转动，记录完成时前进一格花瓣（B2）。
- **C4 引用双向**
  - 回答里的“↳ 第 5 步”是按钮：正文滚到该步并亮一下。手机上抽屉先降到露出，再滚动。
  - 自己发出的引用也是按钮，点它回到原文。
  - 正文里被引用的锚点有页边标记，点它回到对话（R5）。
- **C5 需要确认的建议**（待定层，见 §0）：会改变学习安排的提议以卡片出现，标“建议 · 需要你确认”，有“加入 / 不用”。
  加入后卡片变为已加入的状态，并给撤销（M10）。
- **C6 输入**：两行输入框，回车发送、Shift+回车换行；在想时禁用发送并说明“它在想，稍等…”；`@` 引用正在看的内容（原型只有按钮，未实现选择）。

## 6. 资料（L）

- **L1 结构**（待定层，见 §0）：banner（总数与错题数）→ 分段切换“题目 / 笔记 / 错题”（带计数，滑动的墨块）→ 筛选（有待跟进、来源）→ 表头 → 行。
- **L2 行**（待定层，见 §0）：名称（图标、标题、副标题、待跟进点）、来源、状态、最近、下次复习。数字用 `tabular-nums`。手机上只保留名称与状态。
- **L3 进入与返回**（待定层，见 §0）：点行进入详情时标题形变为详情页标题；返回时落回同一行。资料页记住上次的分段（M4）。
- **L4 长列表**：真实数据量下虚拟化，由资料与题库波次的票验收。

## 7. 吉祥物与 logo（B）

- **B1 一页一朵**（待定层，见 §0）：吉祥物只出现在页面 banner 的指定位置。大小按页面设计：回来时 208px、题目与笔记 128px、资料 96px；手机为 112 / 84 / 68px。
  换页时同一朵花用弹簧移动、缩放到新位置，不重新创建。
- **B2 状态只跟随变化**
  - 静止时朝向读者，按页面有轻微不同的角度；任何状态下偏转不超过 x 22°、y 28°，不会侧对读者。
  - 指针或手指靠近（300px 内）时转向它，离开时回到静止角度。
  - 学习伙伴在想时像风车一样转动；记下东西或回答记录完成时前进一格花瓣。
  - 没有任何变化时它不动。
- **B3 手机停靠**：banner 可见时吉祥物随 banner 滚动；banner 滚到顶栏下方时，缩小并停进顶栏右侧，往回滚时回到 banner。
- **B4 实现约束**
  - three.js 渲染，只在需要时绘制；生产中懒加载，在空闲时初始化，不进首屏关键路径，也不在任何交互的那一帧初始化。
  - WebGL 不可用、只有软件渲染（如 SwiftShader）、开启减少动态效果，或设备性能不足时，退回同一朵花的静态图。
  - 依据：软件 WebGL 下，原型的玻璃花会让合成卡住 10–16 秒、首次初始化卡住约 3 秒（scorecard §4.3）。验收须包含一次无 GPU 加速的测量。
  - 吉祥物始终 `aria-hidden`，不承载信息；它表达的状态在文字里都有（如“在想…”）。
- **B5 logo**：二维编织方块（两根经线、三根纬线，中间一根是珊瑚色），与吉祥物分开使用。品牌位、图标与 favicon 用 logo，不用吉祥物。
- **B6 未完成**：当前花朵模型偏灰，表面有褶皱，缩到 22px 停靠时辨识度不足。需要第二轮建模（更清透的玻璃、更顺的表面、小尺寸可辨认），
  在 YUK-1354 之前或其中完成，见 §11。

### 8.2 规则

- **T1** 组件只引用语义 token：`--bg*` `--text*` `--line*` `--accent*`、状态色、尺寸、层级与动效 token。色阶原值只出现在 token 文件。
- **T2** 新设计系统在独立作用域落地（独立 CSS layer 或根属性作用域），供 TanStack Start 前门（`server/start/`）下重写的页面使用；
  不复制、不继承 `web/src/globals.css`。
- **T3 玻璃只给浮层**：命令面板、选区气泡、提示条、手机标签栏、手机记录表单。
  材质为 86% 的 raised 底加 `backdrop-filter: blur(22px) saturate(1.8)`（原型用 64%，次级文字在最不利背景上只有 3.05:1 / 2.28:1，违反 A3；YUK-1354 改为 86% 后为 5.11:1 / 4.65:1，并由单元测试钉住），内侧一道高光与一圈细线，外侧柔和投影；暗色降低高光。
  正文、卡片、侧栏、学习伙伴侧栏不用玻璃。不支持 `backdrop-filter` 时退回不透明的 raised 底。
- **T4 动效 token**
  - 曲线：`--spring`（`cubic-bezier(0.32, 1.28, 0.48, 1)`，略带回弹，用于小元素）、`--glide`（`cubic-bezier(0.22, 1, 0.36, 1)`），
    以及大面积飞行用的弱回弹 `cubic-bezier(0.32, 1.12, 0.48, 1)`（原型 `motion.js` 中的 SPRING；生产中应命名为 token）。
  - 时长三档：反馈 ≤ 100ms、界面 `--t-ui` 280ms、面板 `--t-panel` 420ms。
  - 吉祥物、手机抽屉等用 JS 阻尼弹簧（刚度约 190–240、阻尼约 23–29），保留速度，可被新目标打断。
  - 这比准备计划 §6 的“150–250ms”更长，属于**有意偏离**：大面积的面板与形变在 250ms 内完成显得急促，而所有过渡都可以打断，
    不会阻塞下一步操作。小元素（按钮、芯片、计数）仍按 150–250ms。是否成立以真机录屏和 M12 的指标为准。
- **T5** 所有文本 token 在 `--bg`、`--bg-raised`、`--bg-sunk`、`--bg-hover` 上 ≥ 4.5:1（禁用文字除外），亮暗两套都满足；焦点环对页面底 ≥ 3:1。
  玻璃上的文字以其最不利的背景计算对比度。
- **T6** 主题默认跟随系统（`prefers-color-scheme`），用户显式选择后才持久化覆盖。
- **T7** 层级使用命名 token：吉祥物 3 / 选区气泡 4 / 手机抽屉 40 / 标签栏 42 / 记录表单 45 / 命令面板 50 / 提示条 60。组件不写裸 z-index。
- **T8** 断点是共享常量，生产中以共享 TS 常量或 custom media 提供。原型只有 phone ≤ 720 一个断点；中等宽度下学习伙伴是否改为覆盖式尚未决定（§11）。
- **T9** 新 token 不得与 Tailwind v4 的主题命名空间同名（`--tracking-*`、`--ease-*`、`--text-*`、`--radius-*`、`--shadow-*`、`--spacing` 等），
  除非有意通过 `@theme` 映射。原型里的 `--text-*` 在生产落地时须加前缀或映射。
- **T10** 原型里仍有尺寸字面量（芯片高、状态点、图标、吉祥物位尺寸、抽屉停靠偏移等），生产中须收进 token 或共享常量。

## 9. 动效与交互（M）

### 9.1 原则

- **M1 只在变化时动**：没有用户动作或数据变化时，页面上没有任何东西在动（包括吉祥物与背景）。
- **M2 每个动画回答一个问题**：这个东西从哪来、到哪去、算不算数。回答不了的动画不做。
- **M3 可以打断**：任何过渡进行中都可以被新的操作接管，不先跳到终点，也不留下残影、隐藏的元素或卡在中间的状态。按实现方式分两类：
  - **弹簧**（吉祥物、手机抽屉）：从当前位置**和速度**转向新目标。
  - **CSS 过渡**（面板宽度、展开、计数）：从当前位置转向新目标（CSS 不保留速度）。
  - **一次性飞行**（形变、收进去、引用飞入）：取消当前飞行，并**从正在飞的副本此刻的位置**重新起飞；被撤销的飞行在原地淡出，不再到达。
  - `prefers-reduced-motion` 下所有过渡直接切换（含字面量时长），程序滚动改为瞬时，吉祥物不转动，状态只靠文字表达。

### 9.2 连续动画

- **M4 共享标题形变**（待定层，见 §0）：从“继续你的”卡片或资料的一行进入详情时，那个标题从原位置移动、放大成详情页 banner 的标题；旧标题沿同一路径淡出，
  页面其余部分只淡入，不位移。返回时沿原路收回。连续快速切换会取消上一次飞行。
  原型在提交阶段测量新页面的标题位置，会迫使整页同步排版；4× 降速下这是切屏最慢的部分（scorecard §4.3）。生产中把测量推迟到新页面首帧之后，
  或改用 View Transitions API。注意 View Transitions 在新导航到来时会直接跳到终点，**不满足 M3**；选用时须在该票的复核中裁决。
- **M5 收进去**（待定层，见 §0）：记下的内容沿弧线飞进“收进来的”（手机上是“记一下”按钮），落地时计数滚动加一、入口轻轻弹一下。
  撤销时计数滚回；飞行途中撤销不计数。
- **M6 引用飞入与回跳**：选中的段落离开正文，落成对话里的引用（目标在移动时，比如面板正在打开，也逐帧追踪落点）。
  引用、步骤引用与页边标记之间可以来回跳转，目标处亮一下（约 1.6s 淡出）；短时间内再次跳转时重新计时，不被上一次截断。
- **M7 保持阅读位置**：学习伙伴开合、侧栏折叠导致正文重排时，把阅读线上的那一段固定在原处；滚轮、触摸或按键立即把控制权交还给读者。
  页面已经滚到底、无法保持时不强求。
- **M8 布局过渡**：侧栏与学习伙伴的宽度变化在原型里是 `grid-template-columns` 过渡，手机标签栏收窄时过渡 `height/left/right`，
  都会逐帧重排，**不符合**“只动 transform/opacity”。
  生产中先在真机上量 Long Animation Frame；不达标时改为面板用 transform 滑入、正文只重排一次（配合 M7）。
- **M9 小的连续性**：计数滚动（变大向上、变小向下）；分段切换的墨块滑动；展开用 0fr → 1fr 的高度过渡；新条目先撑开自己的空间再出现，不一帧推挤下方内容。

### 9.3 基线

- **M10 乐观写入**：推迟、加入、记下等写操作立即生效，并给 4.5 秒撤销；失败时恢复原状并说明原因。
- **M11 反馈**：任何点击或按键在 100ms 内有可见反馈（悬停、按下颜色与按下缩放）。
- **M12 性能门槛与测量**
  - 门槛：INP < 200ms、CLS < 0.05、关键过渡流畅。“流畅”的判定：在**有头浏览器或真机**上录 Chrome trace，
    关键过渡期间没有超过 50ms 的 Long Animation Frame，且掉帧率 < 5%。每张 UI 票附真实操作录屏与上述指标。
  - headless 下 rAF 空闲时就有约 27ms 的间隔，**不能证明 60fps**。
  - 测量对象必须是生产构建，不是开发服务器。
  - 原型实测（scorecard §4）：CLS 通过；INP 在 1× 下通过，在 4× 降速下不通过（200–296ms，最慢都是切屏）。
- **M13 预取**：继续入口在悬停或聚焦时预取详情（TanStack `preload="intent"`）；公式等昂贵渲染前移到服务端或空闲时，不在切屏那一帧同步渲染。
- **M14 三态**：每个区域都设计载入（与布局一致的骨架，骨架到内容原位淡入）、空（带进入动作）、出错（区域隔离、可重试、已保存的工作不受影响）。
- **M15 提示条**：玻璃提示条不压住底部固定元素；手机上位于标签栏之上，文字不换行成竖排；撤销按钮的触控目标见 A2。

## 9A. 可达性（A）

- **A1 收起即不可达**：收起的学习伙伴、折叠的“为什么 · 换一种”、关闭的命令面板与记录表单、让位隐藏的标签栏、露出状态下抽屉的正文，
  都必须 `inert`（或在过渡结束后 `visibility: hidden`），不能只靠透明度。不得出现带 `aria-hidden` 却仍能聚焦的元素。
- **A2 触控目标**：触屏上每个可点击目标的点击区 ≥ 44×44px，桌面 ≥ 24×24px（WCAG 2.5.8）。视觉上可以更小，用不可见的扩展点击区补足
  （原型在 `pointer: coarse` 下给文字按钮、图标按钮、页边标记、引用芯片、分段按钮加了扩展区，提示条按钮最小 44px 高）。
  原型仍有残留，生产须修正：手机标签栏的项 90×38、首页内联“记下”按钮 50×36。
  - 获得焦点的元素不能被固定层遮住（WCAG 2.4.11）：正文滚动容器的 `scroll-padding-bottom` 不小于“抽屉露出高度 + 标签栏高度”。原型在手机题目页用 Tab 时有 3 处被遮住。
- **A3 对比度**：T5 的要求同样适用于状态色在其 `-soft` 底上的组合（如“正确”芯片），以及强调色在 hover 底上的组合；
  玻璃上的次级文字按最不利背景计算。复核实测的不达标组合：亮色 `--positive` / `--positive-soft` 4.30:1，`--accent-strong` / `--bg-hover` 4.42:1，
  玻璃上 `--text-3` 最坏约 3.05:1（亮）/ 2.28:1（暗）。生产落地 token 时须修正，并让禁用状态有可见区别（原型已加）。
- **A4 键盘路径**：新的交互都要有键盘入口：引用与页边标记是按钮（原型已满足）；对选中文字提问、抽屉的各停靠点在原型里只有指针路径，生产须补上。
