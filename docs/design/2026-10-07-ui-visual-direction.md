## 1. 选定方向：A 的首页、导航与视觉语言 + 三区同屏工作台

一句话：**安静的单栏阅读页，顶栏加命令面板；工作台里题干、草稿、帮助同屏，帮助写在页边并按步骤锚定。**

这是一个明确的混合方案：

- **首页、导航与视觉语言**取自变体 A「纸页」。
- **工作台的同屏原则**取自变体 B「工作室」，用 A 的文档流和按步骤锚定的页边注释实现。
- **手机顶层页的底部标签栏**也取自 B。

原型中对应 `?v=a`（A 第二版）。

| 方面 | 选定 |
| --- | --- |
| 导航 | 桌面：顶栏三个去处 + `⌘K`，无常驻侧栏。手机：顶层页有底部标签栏，任务页让位给任务自己的操作条 |
| 首页“回来时” | 回来时说明 → 等大并列的“继续你的 / 系统建议” → 带来新的 → 其余可做 → 系统准备的 → 折叠的全部未完成 |
| 工作台 | ≥1360：题干、草稿、页边帮助三区；1024–1359：题干钉左，帮助就地展开；≤1023：单栏，题干可随时展开 |
| 视觉 | 暖纸暖墨、唯一的珊瑚强调色、衬线叙述标题；层级靠字号、字重、灰度与底色差，阴影只给浮层 |

### 1.1 为什么这样选

**分数只作辅助。** 评分见 [scorecard](2026-10-07-visual-loft/scorecard.md)：

- 复核者初审重评为 A 28 / B 27 / C 23。
- 修复后，第二轮复核裁定为 A 29 / B 27 / C 23。作者复评为 A 31，取复核者的分数，见 review.md §4。
- A 前后修订了两轮，B 和 C 没有修订，**分差主要来自修订**。

因此，选择依据以下面的定性理由为主：

1. **首页最贴近 §4.1**（“首页主要呈现可以继续的事情和有理由提出的建议”）。A 的单栏叙述只放可继续的事和有理由的建议，
   等大并列体现了 §4 第 78 行的“同等正式”。B 的首页是一组面板，信息密、层级平，适合管理面，不适合每日入口。
2. **工作台需要宽度**。常驻侧栏会在最重要的工作台上吃掉 232px。顶栏方案让 ≥1360 能放下三区，1024–1359 至少保持题干与草稿同屏（W2）。
3. **高级感来自克制**。A 的层级几乎全靠排版与底色差，没有仪表盘式的框与徽标。
4. **手机不需要另一套信息架构**。单栏结构在 390px 下自然成立。请求帮助时，所属步骤保持可见、帮助在其下方展开（`probes.json` 中 `phoneHelp` 实测）；
   题干可从上下文条按需展开。

### 1.2 loft 内修订与流程说明

**第一次修订（初评之后）**，吸收了三点：

- 题干固定在左栏（来自 B/C 的同屏原则）；
- 手机顶层页的底部标签栏（来自 B）；
- 顶栏的三个主去处与“系统为我做了什么”状态指示。

**第二次修订（复核之后）**，修复了复核者证实的问题，见 [review.md](2026-10-07-visual-loft/review.md) §2：

- 乐观写入没有生效；
- 手机上的帮助把尝试挤出屏幕；
- 断点与规则不一致；
- 页边注释错位。

第一版 A 的原始截图在 `evidence/round-1/original/`。`?round=1` 只是结构近似重建，带有后续修复，截图在 `round-1/reconstructed/`，
不能当作原始记录。

**B 没有修订**。它的长处（同屏、手机标签栏）已经被采纳，弱点在首页信息架构与常驻侧栏，而这两项都没有采用。

### 1.3 为什么不选 B「工作室」

B 的三栏工作台在桌面上最直接地满足“三位置同屏”，也最贴近现有 `RootShell`（侧栏 + 顶栏 + 手机标签栏），复用成本最低。
不选的原因：

- 常驻侧栏压缩了工作台；
- 首页面板化，与 §4.1 的“只呈现可以继续的事和有理由的建议”相悖；
- 手机上，草稿与帮助只能分段切换，不能同看。

B 的同屏原则与手机标签栏已被采纳。

### 1.4 为什么不选 C「学习线」

C 的“现在 → 分叉”最好地表达了连续性与“停下也是正式选择”。学习线写明了关联依据（“都需要先选择设直线的方式，不是因为都属于椭圆”），
也最贴近 §13.2。不选的原因：

- 首页把跨线索的建议降为次要，所有安排都附着在一条线上；
- 工作台的帮助面板多一次开合，手机上遮挡大；
- 需要新造 Dock、Sheet、Timeline 三个原语。

C 有两点保留为规则：停下与继续、建议同级（H2），关联须写明依据（H8）。

## 2. 导航骨架（N）

- **N1 桌面顶栏**
  - 左侧：品牌，随后是三个主去处“回来时 / 资料 / 我的学习”。
  - 右侧依次为：“系统为我做了什么”状态指示（有“准备好了 / 需要复核”时显示点）、`⌘K` 搜索框、“＋ 带来材料”、外观与账户。
  - **不设常驻侧栏。** 顶栏 56px，底色不透明度至少 94%，加模糊，滚动时保持。
- **N2 手机**
  - 顶栏保留品牌（或页标题）、状态指示和搜索；**不显示“＋”**。
  - 顶层页有底部标签栏：“回来时 / 资料 / ＋带来 / 我的学习”。
  - 工作台等任务页不显示标签栏，底部让给该页的固定操作条（提交、提示、讲解、停下）。
- **N3 命令面板**
  - `⌘K` 是全局入口，手机上为搜索图标。
  - 分组为“继续 / 带来 / 这道题 / 前往 / 外观”；无匹配时，回车把这句话交给学习伙伴。
  - 高频动作在面板中显示快捷键。
- **N4 任务上下文条**：从首页进入任务后，顶栏下方有粘性上下文条，包含：
  - 返回“回来时”（触控目标不小于 44px）；
  - 任务标题与当前小问；
  - ≤1023 时的“题干”展开；
  - 下一项是否已备好；
  - 保存状态。
- **N5 §4.4 功能区落位**
  - “资料”：按主题、来源、时间、目标、问题找资料与作品。
  - “我的学习”：判断与变化、纠正、关闭跟进。
  - “系统为我做了什么”：指示 + 页面，显示后台结果、未完成工作与费用。
  - 管理面（`admin-*`）不进主导航，经 `⌘K` 与设置进入，沿用准备计划 §2 的 LIGHT 处理。
- **N6 现有导航的默认归宿**（P6 各波次票确认后实施）：
  - 今日 → 回来时；
  - 练习、录入 → 工作台入口与“＋带来”；
  - 收件箱、草稿审核、AI 观察 → 系统为我做了什么；
  - 题库、笔记、知识、错题本 → 资料；
  - Coach、画像 → 我的学习；
  - Copilot 浮层 → 工作台页边的“问学习伙伴”与命令面板。

## 3. 首页“回来时”（H）

- **H1 顺序**：
  1. 日期；
  2. 回来时叙述：衬线一句，加一两句说明，包含未知与已准备好的东西；
  3. 今晚可用时间：可改，注明来源；
  4. 等大并列的“继续你的 / 系统建议”；
  5. “或者带来新的”：拍照、粘贴、口述；
  6. “也可以”：逐行标“你的 / 建议”；
  7. “系统准备的”与本周费用；
  8. 折叠的“全部未完成 · 不会累积成欠账”。
- **H2 并列与主次**
  - 继续与建议同尺寸、同层级。
  - 继续在阅读顺序前位，并持有**页面上唯一的实心强调按钮**（回车）。标签栏的“＋”用浅底。
  - 建议用次按钮“开始”与“为什么 · 换一种”。
  - “今晚只记录 / 停在这里”始终是可见的正式选择（取自 C）。
- **H3 建议必须说明**
  - 卡面直接给出“为了什么”与预计投入，并标注“估计”。
  - 展开后逐项给出 §7.2 要求的内容：做什么、为了什么、为什么现在、需要什么、何时可以停下，以及一键替代（换成、推迟、不再跟进）。
  - 替代与推迟是乐观写入 + 撤销（M5）。
- **H4 准备状态诚实**
  - 只有可用结果才显示“准备好了”。
  - “生成中”显示进度并禁用“开始”。
  - “需要复核”用 caution 色说明原因与影响。
- **H5 久别**
  - 标题直说多少天没见。
  - 说明“没有新记录只是没有新观察，不代表退步”。
  - 不累加到期任务；不沿用“今晚”“你下午说的”等过期语境，可用时间显示为“还没说”。
  - 建议位给出**可点击**的“5 分钟确认”，另可直接继续断点。
- **H6 三态**
  - 载入：与布局一致的骨架。
  - 空：三个进入方式（带来一道题 / 粘贴材料 / 让系统先提一个）。
  - 出错：按区域隔离。AI 建议取不到时，已保存的继续项与确定性项目（到期复习）照常可用，并给重试。
- **H7 确定性能力同级**：到期复习等不依赖模型的项与 AI 建议同列，并标“按复习间隔 · 不需要 AI”。
- **H8 关联要写依据**：任何“与之前相关”的提示都写明关联依据（取自 C），不能只因同主题就归并。

## 4. 学习工作台布局（W）

- **W1 三位置不变量**
  - 正在看的内容（题干、图形、材料）、自己正在做的东西（草稿步骤、作品）、围绕它的帮助（判断、提示、讲解、提问）同时存在于页面。
  - **帮助不得覆盖自己的尝试**；打开讲解不清除草稿。
- **W2 断点**（常量见 T7）
  - **≥1360**：左栏题干（360px，sunk 底，独立滚动，粘性）｜中栏草稿（阅读宽度）｜右侧页边帮助（300px）。
    输入框与操作条与草稿列同宽。
  - **1024–1359**：题干钉在左栏。帮助折叠为所属步骤下方的标签按钮，点开就地展开。
  - **721–1023**：单栏，题干与图形在上，草稿在下。上下文条提供“题干”，点开为可滚动的浮层，不改变滚动位置。
  - **≤720**：同上，另加固定底部操作条。从操作条请求帮助时，把**所属步骤的顶部滚到粘性条下方**（减少动态效果时瞬时滚动），
    帮助在该步下方展开。验收：步骤完整可见，帮助从屏内开始。
- **W3 帮助锚定**
  - 每条帮助**按步骤 id 锚定**（照片 ↔ 第 1–3 步；提示 1 ↔ 第 4 步；判断、提示 2、讲解 ↔ 第 5 步），不按“最后一步”锚定。
  - 每条页边注释写明“第 N 步”。
  - 宽屏下注释浮在页边，后一条在前一条之下堆叠；早先步骤已读过的提示收为两行，点开再展开。
  - 验收：注释顶部与所属步骤顶部的偏差 ≤ 一行（约 30px）。原型在 1440 宽实测为 0 / 0 / 11px。
- **W4 步骤来源**
  - 每一步标注来源与帮助条件：学校草稿照片 / 今晚 / 看提示 1 后 / 看提示 2 后 / 正在写。帮助条件变化时，标签同步变化。
  - 识别不清的部分用**中性虚线**标记，并注明“未用于判断”。
- **W5 帮助条件先说后做**：打开提示前写明会怎样记录（“打开后，第 5 步记为看提示后完成”）；讲解注明不改草稿与判分。
- **W6 临时输出不冒充生效**
  - 模型流式输出以弱化文字和“生成中 · 未生效”标识呈现。
  - 流结束后显示“生成完毕 · 正在确认记录”。
  - 只有**重新读取已提交状态**之后，才显示“已记为……”（ADR-0066 第 45–46 行）。
  - 流式区域在打开时（仍在点击的输入窗口内）就预留预计高度，之后在原位填充，不推挤下方内容。
  - 预留高度的容器必须让内容顶部对齐（`align-content: start`），不能把预留的高度分摊给各行。
  - 原型中：未预留时，手机内联讲解的 CLS 为 0.047；预留但未对齐时升到 0.058；两者都做之后约为 0.002（review.md §5）。
- **W7 判分与解释分开**：确定性核对的结果明确陈述；原因还没判断时，用中性虚线标“原因还没判断”，不按最终答案解释能力（§6.3）。
- **W8 不确定的呈现**
  - 判断按“观察到 / 你说过 / 还不知道”分行。
  - “还不知道”用中性虚线标记，**禁止使用 critical 红色**（§6.4）。
  - 数值只在含义与可靠性说明齐全时出现。
- **W9 草稿编辑**
  - 点任一步进入原文编辑（等宽字体），失焦后渲染公式。
  - 保存状态在 100ms 内变化（保存中… / 已保存）；回车添加下一步。
  - 获得焦点的输入框始终在固定栏之上可见（`scroll-margin` + 滚入视野）。
- **W10 推广到其他活动**：三位置按任务映射，原则不变。
  - 阅读：原文为主栏，批注与讨论在页边。
  - 写作：作品为主栏，要求钉在左栏，反馈在页边。
  - 听说：音频与转写为主栏，可定位的反馈在页边。
  - 具体形态在各活动的 UI 票 pre-flight 中声明。
- **W11 公式**
  - KaTeX 样式表与渲染插件同包、按需加载。现役页面从未加载该样式表，公式会以 MathML 加一段乱码重复显示
    （[YUK-1379](https://linear.app/yukoval-studios/issue/YUK-1379)）。
  - 正文中的行内公式不断行；推导步骤可以在关系符处换行。
  - 允许换行的推导步骤，要给公式行留出块向间距。KaTeX 0.19 的 strut 不带行距，相邻两行的分式会碰在一起；原型给 strut 加了 0.2em 的上下外边距。

### 5.2 规则

- **T1** 组件只引用语义 token：`--bg*` `--text*` `--line*` `--accent*`、状态色、尺寸、层级与动效 token。色阶原值只出现在 token 文件。
- **T2** 新设计系统在独立作用域落地（例如独立 CSS layer 或根属性作用域），供 TanStack Start 前门（`server/start/`，PR #1592）下重写的页面使用。
  不复制、不继承 `web/src/globals.css` 的 1.58 万行；旧样式在 P7 删除（准备计划 §12 风险表）。
- **T3** 所有文本 token 在 `--bg`、`--bg-raised`、`--bg-sunk`、`--bg-hover` 上都 ≥ 4.5:1（`--text-disabled` 除外），亮暗两套都要满足。
  焦点环对页面底 ≥ 3:1。数字使用 `tabular-nums`。
- **T4** 原型中仍有约 88 处尺寸字面量（芯片高、状态点、图标尺寸等，见 scorecard §3）。生产实现须把它们收进 token（如 `--h-chip`、`--dot`），
  组件内不得出现裸数值。
- **T5** 主题默认跟随系统（`prefers-color-scheme`），用户显式选择后才持久化覆盖。现役 `RootShell` 总是写入 `data-theme`，
  导致系统暗色从不生效，新壳不得沿用。
- **T6** 层级使用命名 token：粘性 10 / 分段 15 / 顶栏 20 / 面板 25 / 浮动条 30 / 遮罩 50 / 提示条 60。组件不写裸 z-index。
- **T7** 断点是共享常量：phone ≤720、tablet 721–1023、laptop 1024–1359、wide ≥1360。CSS 媒体查询不能读取自定义属性，
  因此生产中以共享 TS 常量或 custom media 提供。
- **T8** 暗色下，照片与扫描件降低亮度（约 0.82）；半透明粘性栏的不透明度不低于 94%，避免内容透过来形成残影。

## 6. 动效与交互（M）

- **M1 反馈**：任何点击或按键都在 100ms 内有可见反馈：悬停与按下的颜色变化 90ms，按下时 `scale(0.98)`。
- **M2 移动**：时长 160 / 220ms；只动 `transform` / `opacity`；进入位移 6px；退出更快（ease-in）。
- **M3 布局过渡**
  - 路由切换用 View Transitions API 与命名元素，新旧快照不拉伸（`object-fit: none`）。首页卡片标题与工作台标题共享名称，切换时形变衔接。
  - 常驻的栏（顶栏、上下文条、底部条、帮助面板）作为独立命名层，层级高于内容，避免内容在过渡中盖住它们。
  - 页面内的展开、插入步骤、移除建议，在生产中改用**元素级 FLIP**（只动 `transform` / `opacity`）。原型这些交互也走整页 View Transition，
    4× 降速下出现了 89–141ms 的长帧（scorecard §4）。
- **M4 减少动态效果**：`prefers-reduced-motion` 下，时长归 1ms，不启用 View Transition，旋转与微光动画停止，程序触发的滚动改为瞬时。
- **M5 乐观写入**：推迟、换一种、不再跟进等写操作立即生效，并给 5 秒撤销；失败时恢复原状，用 critical 提示说明。
  原型在三个变体中实测：1 → 0 → 撤销后恢复为 1（`probes.json` 中 `optimistic`）。
- **M6 预取**
  - 继续入口在悬停或聚焦意图时预取工作台（TanStack `preload="intent"` 与 loader）。
  - 作答期间预取下一项，就绪后显示“下一项已备好”。
  - 预取包括昂贵的渲染：公式在服务端（Start server function / SSR）或空闲时预渲染，不在切屏那一帧同步渲染。
    预热前只测过一次。运行间波动大，预热前后的差异不能严格归因于预热。
- **M7 键盘**
  - 全局 `⌘K` 打开命令面板；首页回车继续。
  - 工作台：`H` 提示、`E` 讲解、`D` 聚焦草稿、`⌘↵` 提交、`Esc` 收起帮助或页边注释、`[` 返回。
  - 按钮内显示快捷键，触屏隐藏；只有图标的按钮必须有可访问名称。
- **M8 长列表**：资料、题库等长列表虚拟化。loft 未覆盖，由相关波次的票验收。
- **M9 性能门槛与测量协议**
  - 门槛：INP < 200ms、CLS < 0.05、关键过渡流畅。“流畅”的判定方法：在**有头浏览器或真机**上录 Chrome trace，
    要求关键过渡期间没有超过 50ms 的 Long Animation Frame，且掉帧率 < 5%。每张 UI 票都附真实操作录屏与上述指标。
  - headless 下 rAF 空闲时就有约 27ms 的间隔，**不能用来证明 60fps**。
  - loft 结果（scorecard §4）：
    - CLS 全部通过。
    - INP 按 3 次中位数全部通过，但单次最差 200ms，触及门槛。
    - “100ms 内反馈”未全部达成。
    - 流畅**未验证**。
    4× 降速下，切屏与插入步骤出现 89–141ms 的长帧，这是确定的负面信号，按 M3、M6 处理后须复测。未通过前，不得宣称满足本条。
- **M10 三态**：每个区域都设计载入（与布局一致的骨架）、空（带进入动作）、出错（区域隔离、可重试、已保存的工作不受影响）。
- **M11 提示条**：toast 不压住底部固定条。手机上位于标签栏或操作条之上；撤销按钮的触控目标遵循 N4 的 44px 规则。
