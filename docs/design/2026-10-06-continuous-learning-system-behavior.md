# 连续学习系统：完整产品与行为设计

状态：r0 行为稿，2026-10-06；2026-10-07 由 agent 在 owner 的持续委托下采用为设计基线。

本文描述希望产品怎样工作。除 §1 标明的 owner 要求与既有决定外，具体行为、信息组织与默认策略由 agent 依据[持续委托](../planning/2026-10-07-autonomous-delivery-charter.md)负责细化和验证。采用本稿不等于 owner 逐项批准，也不代表已经实现或验证有效。文档章节表达系统关系，不表达实施先后，不设 MVP、阶段或开发排期。

## 1. 产品要对什么负责

Owner 的原话：

> 实时准确评估学习状态，自适应安排学习，为学习提供一个全场景的工具。

> 我在学习数学的时候，做题一道椭圆相关题目，但是很难，即便做完也感觉提升不稳固。我做这个产品，就是感觉在学校做题，自己做练习等等没有一个能串联我的所有行为，总是恰到好处记录，帮助我的人/团队。

> 不去讨论先后了。我们需要用语言把一整套系统与行为设计出来，然后再做实现。

据此，产品承担一个持续责任：把分散发生的学习连接起来，形成有依据、能修正的理解，并用这种理解帮助学习者决定和完成后续学习。一次难题做完、一次讲解看懂、一次任务结束，都只是这份责任中的一个时刻。

它应当让学习者能够说：

- 我在不同地方学过的东西，可以接在一起，不需要反复解释自己的情况。
- 我可以直接学习；记录与整理尽量随过程发生。
- 它知道哪些是有证据的进步，哪些还需要确认，不轻易给我贴标签。
- 它为我准备的东西能看出与我的经历有关；我也能自己选方向。
- 它记住尚未学稳的地方，并在合适时机跟进，不把所有经历都变成负担。
- 它出错时，我能看出、纠正，后续安排会真正改变。

全场景包括学校课堂与作业、自主阅读与练习、备考、写作与表达、语言听说、编程与项目、实验和其他实践。不同活动保留自己的工具与成果形态，共享学习经历、判断和安排。支持全场景不等于无权限观察所有活动，也不等于对所有领域都能自动准确评分。

现有确定性工具、纸笔、自选资料、自定计划都是正式学习方式。AI 服务不可用时，已经保存的资料、作品及可独立运行的学习工具仍有价值。

## 2. 学习者与系统怎样分工

学习者决定为什么学、哪些承诺必须遵守、是否接受一次帮助，以及何时改变方向。系统承担记录整理、关联经历、提出和修正判断、准备材料、组织活动、提供帮助、跟进效果的工作。

前台有一个连续的学习伙伴。它可以承担讲解、讨论、批改、计划和整理等不同职能，不要求学习者认识后台角色，也不把内部讨论作为必须处理的信息。

系统可以做出判断，但须表达依据与边界。学习者对个人目标、时间、经历说明和产品使用拥有控制权；数学命题、评分规则等可核对事项不因双方偏好而改变。发生争议时保留事实、不同解释与复核结果，不能用一句“你说得对”覆盖原始记录。

### 2.1 日常合作约定

学习者可以用自然语言或设置表达稳定约定，例如“平时可以调整下一项练习”“写证明时先给提示”“这周以学校考试范围为主”“今晚只记录”。这些约定可查看、修改、暂停，只在明确范围内生效。

系统每次行动都区分：当前请求已经授权的事、持续约定已经授权的事、需要新决定的事。已授权的常规动作不反复询问；系统也不能从一次允许推导出永久授权。

| 行为 | 推荐的默认权限 |
| --- | --- |
| 保存产品内输入、关联同一次活动、更新有依据的暂定判断 | 按记录约定自动进行，能查看与纠正 |
| 在已同意的目标、时间与费用范围内准备材料、调整未开始的建议 | 自动进行，保留理由与变化记录 |
| 改变当前正在做的任务、增加学习时间、改动用户锁定的安排 | 提出修改，学习者决定 |
| 改变长期目标、认定长期个人特征、覆盖个人作品或删除资料 | 明确确认；不能由普通推荐暗中完成 |
| 开启新的外部数据来源、分享资料、通知他人、提高费用上限 | 单独明确授权 |

这些权限是产品内未来行为的设计，不是本轮开发或生产操作的授权。

## 3. 系统中的核心事物

以下是用户能理解的概念，描述其关系，不预设新增数据库表、后台服务或强制填写表单。

| 概念 | 含义与关系 |
| --- | --- |
| 学习方向与目标 | 想理解、能做或达到的事情，可包含课程范围、期限与成果标准。允许“我先随便看看”，不强迫每次活动绑定目标 |
| 材料 | 题目、课本、文章、视频、录音、数据、参考答案等。材料本身不证明学习者已经学习或掌握 |
| 学习经历 | 一次真实发生的阅读、尝试、讨论、练习、创作或实践。可以很短、跨多次进入、在产品外发生；已安排不等于已发生 |
| 个人作品 | 草稿、解答、笔记、代码、录音、作文、实验记录等。保留作者、帮助来源和版本；同一作品可以属于多次经历 |
| 证据 | 能支持某个判断的经历片段、结果或陈述，包含来源、发生时间、所处条件、帮助程度和可靠性。重复呈现同一片段不增加独立证据 |
| 学习状态 | 对“在什么条件下能做什么”的当前判断，包括依据、不确定性和适用范围。沿用 CONTEXT.md 的已批准含义，不把判断等同事实 |
| 待跟进的问题 | 系统或学习者认为仍值得弄清或巩固的地方，如“遇到变形条件时能否独立选择方法”。它是持续关注的内容，不天然是一道待办题 |
| 学习安排 | 根据目标、证据、限制和当前活动，对接下来做什么、如何做、何时再看作出的选择。它可包含建议和用户已经确认的承诺 |
| 帮助与教学活动 | 讲解、示例、提示、对比、检索练习、创作任务、模拟、反馈等。每项有目的、适用理由和观察结果的方法 |

一条经历可以支持多个目标；同一个困难也可能出现在不同学科或任务中。系统可以建立关联，但不能把“相关”直接变成另一个领域已经掌握的证据。

资料、经历和作品允许暂时没有分类。知识结构帮助检索与判断，不成为开始学习之前必须维护的目录。

## 4. 用户怎样进入和使用产品

产品接住三种同等正式的进入方式：继续已有学习、带着自己的事情来、让系统提出安排。任意一种都能进入完整的记录、帮助与后续跟进，不要求先走系统推荐。

### 4.1 回来时

首页主要呈现可以继续的事情和有理由提出的建议。系统已经做的准备，只有形成可用结果才显示为“准备好了”；仍在生成、需要复核或资料缺失须明确表达。

例如：

> 上次你完成了那道椭圆题，但还不确定遇到新条件时能否自己想到关键转化。我准备了一个短对比例子。也可以继续你原来的作业。

建议给出预计投入、选择理由和替代选择。预计时间是可修正的估计，不是对学习速度的要求。时间很少时，可以缩短范围、记录断点或停下，不用赶完原计划。

未完成、到期与值得关注的事项可以完整查看；首页不把它们全部平铺为欠账。长时间未使用后，不自动叠加每天错过的任务。

### 4.2 带着材料或问题来

上传照片、文件、链接，粘贴内容，口述一段经历，或直接打开既有资料，都可以开始。用户可以附带“帮我理解”“只保存”“一起做”“看看我的过程”等意图。系统能可靠推断时直接承接；不同意图会导致明显不同处理时，用短问题澄清。

默认上传进入已有的基础接收与抽取流程；额外收费的增强处理仍遵循已有单独授权约定。“只保存”明确抑制教学跟进与额外分析，不能因为内容像题目就强制开始测验。

### 4.3 学习工作台

工作台保留三个位置关系：正在看的内容、自己正在做的东西、围绕它发生的帮助。具体布局随任务和设备变化，不把所有活动挤进消息流。

- 阅读时保留原文、当前位置、批注与引用；讨论能定位到原段落。
- 解题时保留题干、图形、草稿、步骤与已获得的提示；不会因打开讲解丢失自己的尝试。
- 写作与项目中保留作品、版本、要求、反馈和验证结果；AI 建议与自己的改动能分开辨认。
- 听说活动保留被授权录制的声音、相关文本与可定位反馈；识别不清的位置标明，不能直接当成表达错误。
- 实验与操作活动保留过程记录、测量、产物和外部结果。系统看不到的步骤不自动补成已执行。

学习者可以随时把系统建议放在一边，查资料、直接看答案、自由提问或继续创作。系统记录适当的帮助条件，不用拒绝提供帮助来强迫产生评测数据。

### 4.4 回看与管理

用户能按主题、来源、时间、目标和当前问题找到资料与作品；从任何判断跳回相关原件和经历；从原件查看后来哪些帮助与判断与它有关。

“我的学习”解释当前判断与变化，允许纠正、补充背景、关闭跟进。“系统为我做了什么”显示有用的后台结果、尚未完成的工作和费用，不要求用户阅读内部运行日志。

这些是需要承载的功能区域，尚未锁定最终导航数量、路由或视觉布局。

## 5. 全场景记录与接续

### 5.1 能看到什么

产品内的活动按可见的记录约定留存；产品外的经历来自用户主动带入或明确连接的数据来源。系统不默认录屏、录音、监视其他应用，也不把材料打开时长当成认真学习时长。

每条记录区分：原始内容、抽取结果、用户说明、外部批注或成绩、系统解释。它们可以一起展示，但来源不能混成一个无从追溯的结论。

学校的一张照片可以同时包含题干、自己的草稿、老师批注和参考答案。系统应当分别识别；不能可靠区分时保留原件并标明歧义，不将整页内容都归为学习者独立作答。

### 5.2 何时记录与何时追问

产品内已发生且可观察的动作自动记录；不要求用户再抄一次“今天做了什么”。线下学习允许在结束后一次带入，不要求做题中不断拍照。

系统只追问会影响下一步的重要缺失信息。照片模糊到不能判断答案，可以请用户补拍或改用原图讨论；不能只因科目标签或知识点为空就阻止保存。

用户说“这题很难”“我看了答案”“今天很累”，都是有来源的自述。它们可以改变当下帮助策略，不能直接被升级为永久能力、性格或健康结论。

暂时缺背景的记录仍可检索和使用；系统说明可做与不能可靠做的判断。没有处理能力的格式可以作为附件保留，明确未分析，不显示虚假的完成状态。

### 5.3 时间、重复和跨设备

发生时间与带入时间分开。今天上传上周的试卷，会补充历史经历，并重新考虑当前判断；不会把上周作答算成今天的新练习。

同一草稿的重复上传、截图或转录关联到同一来源，必要时询问是否补充版本。用户重新独立做了一次相同题目，则是新的经历，不能被内容去重吞掉。

手机拍照、电脑继续整理、纸上接着做，都指向同一经历和作品的适当版本。两台设备改动冲突时保留双方内容，让用户选择或合并，不能静默覆盖。

### 5.4 保存、处理和生效

用户能区分“仅在当前设备”“已同步”“正在整理”“等待复核”和“已影响学习判断”。保存成功不以模型成功为前提。

处理失败时原件与个人作品保留，说明哪些分析未完成，支持重试、补充材料或人工继续。未完成的处理不能显示成已经掌握，也不能当成零分。

## 6. 系统怎样理解学习状态

### 6.1 判断的具体形状

一个有用的判断需要回答：在什么任务和条件下，学习者能做什么；依据哪些经历；判断有多稳；还有什么未知；哪种新证据会使它改变。

例如：

> 在给出辅助线的两个例子里，你能完成后续推导。遇到未给辅助线的新题时，是否能自己识别这种方法还没有证据。上次你也说对这一点没把握。

这段描述分别包含观察、自述和未知，不能压缩成一个没有边界的“几何薄弱”。

### 6.2 区分哪些方面

系统按活动需要判断理解、提取与记忆、独立执行、策略选择、迁移、表达与自我检查等方面。它们是可描述的观察角度，不是每个主题必须填满的一套量表。

读过、看懂解释、跟随完成、得到提示后完成、独立完成、隔一段时间仍能完成、在陌生情境应用，是不同的证据条件。它们不必构成人人逐级通过的阶梯。

记忆安排、能力判断与内容难度保留各自含义。按期复习完成不能自动证明迁移；一次高难题失败也不能抹掉有明确证据的基础能力。现有确定性算法及显式自评不因自然语言叙述被替代。

### 6.3 判断怎样获得与更新

能够可靠核对的计算、代码结果、明确答案或规则由相应能力核对。开放作品按清楚的目标与标准给反馈；主观评价、模糊资料和模型推断保留限制。模型同意自己不构成额外独立证据。

判分与学情解释分开：答案是否正确是一项判断，为什么做错以及接下来怎样学是另外的判断。一次结果可以明确，原因仍未知。

系统更新时考虑相关性、任务范围、帮助程度、证据新鲜度和来源质量。失败、成功和与原判断矛盾的证据都进入考虑，不能只积累支持旧结论的例子。

材料被重复讲解、AI 改写自己的总结、同一作品生成多个报告，均不得使系统看起来更有把握。跨主题类比可以帮助提出问题，不能无依据地转移掌握结论。

### 6.4 不确定和过时

未知不能伪装成低能力，也不能自动当作已经掌握。系统可以选择一个有信息价值且负担合适的活动来了解情况，也允许用户跳过了解过程，按其要求开始。

没有新记录只表示没有新观察。对于有遗忘依据的判断，可以说明“可能需要重新确认”；不能生成一条并未发生的失败经历。长期未观察到的领域显示证据日期和适用范围。

数值必须有明确含义及其可靠性说明。没有经过验证的概率不能当作真实掌握概率；用户可以优先看到可理解的描述，再下钻查看计算值与证据。

### 6.5 待跟进的问题

“这次做完仍不稳固”可以形成一个持续关注的问题。问题包含相关目标、依据、当前解释、已经做过的帮助，以及怎样判断是否还值得跟进。

系统可以发现类似问题并归并，避免每次错误都新建一张卡。问题可处于仍需了解、正在帮助、等待后续验证、不再优先、已获得足够证据或已关闭等状态；这些是产品含义，不要求逐个暴露为管理流程。

用户关闭跟进不等于证明已掌握；系统验证达到当前目标后可以停止主动跟进，保留历史。目标变化或出现新的相关困难时可以重新提出，但说明为何重新出现，不能在用户刚拒绝后循环推送。

## 7. 学习状态与安排怎样共同变化

学习安排同时使用当前目标、学校要求、期限、可用时间、材料可用性、近期经历、已有判断、未知以及正在进行的活动。无需等待完整画像；学习本身也产生证据。

### 7.1 从目标到学习路线

目标可以来自学校课程、一次考试、一件想完成的作品，或“我想真正理解这个东西”。系统帮助把它说成能讨论的结果，如解释某个概念、独立解决某类问题、读懂一段材料、完成并验证一件作品；不能未经确认就把所有目标换算成分数或题量。

对于较长的目标，系统给出一条可修改的学习路线，说明内容之间的联系、需要先具备的条件、可选择的深度，以及能够观察进展的成果。未知的前置能力允许通过自然学习了解；推测的知识依赖不能伪装成禁止继续的硬门槛。

学习路线容纳新内容、练习、创作、复习、探索与休息，既关注困难，也利用已有优势拓展新的能力。系统不能把学习收缩成反复补弱点，更不能因某领域记录稀少而永久不给探索机会。

学习者可以从路线中间开始、带入校内进度、改变要求或暂停整个方向。变更后，系统解释哪些建议失去必要性、哪些成果仍可复用；不会要求重新录入已经发生的学习。

目标是否达到，依据事先说清的成果及证据范围。完成计划中的活动、完成一件作品、确认达到某项能力、用户决定结束目标分别记录；不能通过多生成几个任务延长已经完成的目标。

### 7.2 每一项安排要说清什么

一项建议需要说清：做什么、为了什么、为什么现在提出、预计投入、需要什么材料或工具、得到什么结果后可以停下或改变，以及可选的替代方案。

“因为薄弱所以刷题”不足以解释安排。系统应当能说出这项活动是为了确认一个判断、理解一个概念、练习一种方法、完成作业、复习还是探索新内容。一次活动可以有多个目的，但不能为收集数据无限追加任务。

### 7.3 多目标与真实限制

学校作业、近期考试、长期理解和个人兴趣可以同时存在。用户标明必须完成的事项、期限和锁定的安排；系统表达取舍，不通过无限加时声称全部兼顾。

当范围超过时间，系统给出可调整方案与代价，例如保留学校必交部分、缩减额外练习、调整长期目标的期限。改变已承诺范围仍由用户决定。

兴趣探索是合法目的。系统可以提示它与当前目标的关系，也允许暂不关联，不把偏离原计划自动认定为需要纠正的行为。

### 7.4 改变什么，何时改变

新证据、纠正、时间变化、学校任务变化、材料失效、用户请求或相关复查时机都可能触发重新考虑。系统只重看受影响的部分，无需每来一条记录就重排整天。

| 对象 | 推荐的变化行为 |
| --- | --- |
| 当前学习状态 | 新证据可靠接收后及时修正，明确哪些解释仍在处理中 |
| 未开始、未锁定的建议 | 在既定授权范围内更新，重要变化给出简短理由 |
| 已接受但尚未开始的安排 | 小范围、已授权的自适应可发生；改变目标、时间或承诺则提出修改 |
| 正在进行的活动 | 保留当前材料、进度和已提供帮助；在自然停顿处提出调整 |
| 用户锁定的安排 | 保持锁定；新证据形成提示或替代提案，不静默替换 |
| 已完成经历与当时展示内容 | 保留原样；后续改判和解释追加记录，不重写为当时已知 |

当前材料被确认有错误、出现影响继续使用的重要安全问题或用户明确要求切换时，可以立即提示暂停。一般学情更新不能成为频繁打断的理由。

### 7.5 实时的用户承诺

系统先可靠接收当前行为，再显示处理进度和已经生效的结果。需要模型的解释可以晚于确定性更新，但不能阻塞继续记录。

用户提交新证据期间，旧分析即使随后完成，也要检查依据是否还适用；过期结果不能静默覆盖新判断或安排。学习者看到的是一份明确的当前安排，以及必要时可查看的变更过程。

“实时”分别验证接收、判断更新和安排变化的延迟。本文不虚构秒数，也不以页面动画或模型流式文本作为生效证明。

### 7.6 停止、休息和回归

每次活动都允许结束、暂停、缩短和改变目的。用户说累了、没有时间或不想继续，系统据此调整当前协作；不需诊断其心理状态。

系统不能因为某个判断不确定就无限测量。达到约定投入、目标已满足、材料不合适或继续收益不明时，都可以停止并保留断点。

回来时先利用已有记录恢复上下文，再按最新情况提出合适的继续方式。可以短暂确认重要变化，但不强制重走初始化测评。

## 8. 系统如何提供帮助

系统选择讲解、提示、示例、对比、提问、练习、反馈或工具支持时，要把选择与当前任务、已知障碍及用户偏好联系起来。教学方式是可调整的策略，效果要由后续表现检验。

### 8.1 帮助的分寸

用户可以要求一点提示、完整解释、直接答案、陪同推导或独立完成后的反馈。系统按要求协作，并保留实际提供的帮助，不把“有帮助”当作惩罚，也不将其伪装成独立证据。

不以固定“学习风格”标签决定教学。用户的表达偏好可以影响呈现，实际任务与学习证据决定需要观察什么。讲解失败时，系统检查自己的说明和假设，不只重复得更长。

### 8.2 按不同工作提供工具

| 学习活动 | 应提供的工作能力 | 对学习判断的限制 |
| --- | --- | --- |
| 阅读、听课、看视频 | 原文定位、批注、引用、概念解释、段落比较、可选择的回述或应用 | 浏览、播放完成不自动证明理解 |
| 做题、证明、计算 | 题干与图形、草稿、分步推导、提示、数值或符号核对、完整复盘 | 过程、帮助和最终答案分开，不能只按最终答案解释能力 |
| 写作、翻译、表达 | 原稿与修订、具体位置反馈、目标或量规、对照版本 | AI 改好的作品不等于本人已经能够写出 |
| 听说训练 | 明确录音许可、可定位音频、转录纠正、对话与练习 | 识别错误不当成学习错误，能力按任务范围描述 |
| 编程与项目 | 要求、文件或成果、实验记录、运行与验证结果、调试帮助 | 成品运行成功不等于理解所有实现；未运行不声称已运行 |
| 实验与现实操作 | 观察、测量、照片、步骤和反思、结果核对 | 看不到的操作和环境条件保持未知；有现实风险的内容按场景另设限制 |
| 回顾与备考 | 范围梳理、选题或任务、模拟条件、反馈揭示、复查与再安排 | 一次模拟成绩与长期能力判断分开，测评条件改变需明确 |

### 8.3 测评与学习模式

活动开始前，说明是否允许提示、何时揭示反馈、是否计时和结果用于什么。不能在用户作答中偷偷切换规则。

用户在模拟测评中请求帮助时，可以退出测评或切换为学习，系统说明该次结果的可比性变化，保留已经完成的部分。外部学校考试的规则作为已知约束，不推断用户始终处于考试。

### 8.4 内容来源与质量

系统可以使用已有资料、检索可用来源或生成适合任务的内容。引用来源和生成内容能辨认；检索到的文字不能冒充可靠结论，参考答案也允许有争议。

一道练习只有在题意、所需材料、作答方式及适用评分依据足够清楚后才作为正式评测。探索材料可以带着不确定性讨论，必须保持对应标识。

内容准备失败时可以选择已有可用内容、调整活动或如实等待。不能以随便生成一题填满安排，也不能把多模型意见一致当作已经核实。

### 8.5 帮助之后

每次帮助记录它针对什么、实际发生了什么和用户怎样回应。后续活动按目的观察独立完成、保持、迁移或作品改进，不要求每次帮助都附带完整考试。

“用户说懂了”是有价值的反馈，但不自动证明长期保持。后续表现与期待不符时，系统修正对问题的解释和帮助策略，避免不断重复同一种无效安排。

## 9. 学习者不在时，系统做什么

后台工作围绕用户已有目标、授权来源和待跟进的问题进行。它整理新经历、寻找前后关联、复核相互矛盾的判断、准备适合的材料，并检查先前帮助有没有后续结果。

每项后台工作需要一个具体理由。已有结果仍适用时复用；没有相关变化时可以不做事。不能靠不断生成总结、题目和通知来表现“团队在工作”。

### 9.1 备课的产物

有用的产物可以是一份已经核对的练习、一段围绕某个困难的讲解、一份可执行的学习建议，或“暂不安排，因为缺少关键证据”的说明。准备尚未完成时不承诺打开即用。

准备过程中用户改变目标、修正记录或完成了相关活动，系统检查产物是否仍适用。过时的材料可以保留在资料中，但不以当前推荐出现；无法避免的已发生费用如实记录。

团队内部分析、用户可见建议和已经生效的安排必须区分。生成了一项建议不等于用户已经接受，更不等于已发生学习。

### 9.2 怎样交到用户手里

默认在用户回到产品、结束当前活动或主动查看时呈现相关结果。外部提醒另行开启，可设频率、时间和类别，并可整体暂停。

有价值的提醒要说明为什么值得现在看；不能因后台任务完成就通知。重复指向同一问题的提醒合并。用户拒绝一次建议后，同样内容不换个说法再次推送；有新的依据才重新提出，并说明变化。

### 9.3 时间、费用与停止

持续约定覆盖后台工作可以花费的额度和范围。用户知道哪些工作需要外部模型或服务，能查看已发生费用、估算与未知部分；未知费用不能显示成零。

达到上限时暂停需要新增费用的工作，说明哪些产物未完成；继续提供已经可用的内容与工具。扩大额度、启用额外收费能力或采用新的付费来源需要明确授权，不能用自动重试绕过。

暂停后台工作会停止新的处理与排程，并尝试停止尚未完成的工作；已经完成的动作和可能已经发生的费用单独说明。停止不伪装成撤销。

## 10. 纠偏、争议与学习者控制

“改一下”有几种完全不同的意思，产品要就近提供合适动作，而不是全部变成重新生成。

| 用户指出的问题 | 系统行为 |
| --- | --- |
| “照片识别错了，这里是减号” | 修正抽取，保留原件与修订依据，重审依赖它的判分、状态和安排 |
| “最后一步是看答案做的” | 修正帮助条件，重新解释独立完成的证据，不删除实际完成的作品 |
| “这是上周做的，不是今天” | 修正发生时间，调整时间相关判断和展示，避免重复计入 |
| “这题我认为判错了” | 保存争议与原提交，按原适用材料和规则复核；不要求重新作答才能申诉 |
| “这不是我卡住的地方” | 保存用户的解释，撤回未经支持的确定性标签，检查真正的困难 |
| “我不想继续这个目标” | 暂停或结束对应安排与后台跟进，保留已有作品；不推导为学习能力下降 |
| “别再提醒我这件事” | 停止相应提醒或跟进；说明是否仍保存资料，允许用户精确选择 |
| “我就是想把这个答案记下来” | 按保存意图处理，不能为了获得评测数据强迫用户先答题 |

教师、参考答案、确定性工具与系统评价不一致时，展示不同来源、具体争议点和可核对依据。能判明则解释并更正；不能判明则保持待确认。权威来源可以提高参考价值，不能让矛盾凭身份消失。

纠正必须沿着依赖关系生效：修改有关记录或解释，重算受影响的当前判断，在授权范围内撤回或修订未锁定的不合适建议，标明已经发生的帮助受何种旧判断影响。不能只改一张卡片的文字。

已接受的承诺、当前活动和锁定安排仍遵守 §7.4 的保护。所需材料错误或已删除时，标明该活动不可按原样执行及其原因，提出替代方案；不能静默取消用户的学校作业或其他学习承诺。

用户可以选择不让有争议的证据继续驱动自动安排。此时相关判断显示证据受限，不编造替代证据，也不要求用户先承认系统正确。

## 11. 数据边界与信任

### 11.1 选择记录多少

记录约定须让用户理解哪些内容会保存、哪些只用于本次帮助、哪些会进入长期学习判断。下面是待批准的完整产品行为，不代表当前实现已支持。

- 通常学习：保存约定范围内的作品与经历，支持后续跟进。
- 仅保存：保留资料或作品，不新增学情推断和主动教学安排；为提供保存与检索所需的处理仍须明确。
- 临时使用：本次内容不进入长期学情与备课。若技术或外部服务有无法消除的保留，使用前明确说明，不能宣传成绝对不留痕。

用户无需理解后台存储结构。产品在选择发生的位置说明实际影响，不用一个模糊的“隐私模式”承诺做不到的事。

临时使用须在开始前说明结束条件、恢复期限和清理范围，这些规则同时适用于原件、提取文本、摘要、反馈与未完成任务。重试、离线同步和恢复不能自行延长约定期限；转为长期保存或作为学习证据，需要用户明确选择。期限过后不能再承诺恢复已清理的内容，可能未保存的个人作品须在到期前给出可见提示与取回机会。

### 11.2 隐藏、停止使用与删除

隐藏一项内容只改变显示；停止用于判断改变使用范围；删除才处理保存的内容。三个动作要可区分。

停止用于判断时，原件可以保留用于用户自己查看，但须重建受影响的当前判断、推荐和后台工作。系统不能通过摘要、旧标签或既有判断间接继续使用被停用证据；历史展示标明它已停止参与判断。用户重新启用时按当前条件重新计算，不直接恢复旧安排。

删除前说明受影响的作品、提取文本、摘要、判断和安排，并区分唯一来源与仍有其他依据的内容。确认后停止继续使用被删除的内容，相关当前判断撤销、降为证据不足或按剩余证据重建；不能通过旧摘要继续保留被删除的事实。

正在处理和后来从离线设备同步的工作也遵守删除结果，不把它重新带回来。备份、外部服务和必要运行记录的删除能力与期限须如实说明；无法立即清除的部分可追踪，不伪装成已经彻底消失。

日常修订保留历史的原则服从用户有效的隐私删除要求。能否保留不含已删内容的最小操作记录，应按清楚的保留规则说明，不能以“可追溯”为由无限保留原件。

### 11.3 分享与协作

产品服务学习者本人。教师反馈、同伴建议和共同作品可作为有来源的材料带入；系统区分作者与贡献，不将他人成果计为本人能力。

向他人分享作品、进度或诊断需明确选择内容、接收者和权限。私人学习判断默认不随作品分享；本设计不自动扩展成学校管理、家长监控或多人教学平台。

### 11.4 原件、导出与恢复

用户可取回自己的材料、作品和可理解的学习记录，包括必要来源与关联。导出不应只剩难以解释的分数，也不能默默漏掉正在进行的学习。

恢复时核对可恢复的内容、时间和未完成工作。不能为了让界面显示正常而把未知任务标成完成；恢复旧备份也不得复活后来已经生效的删除或重新执行已完成的收费动作。

若缺少核对删除与已完成动作所需的记录，恢复内容保持隔离，说明无法确认的范围，不自动恢复后台分析与执行。用户选择保留或恢复一份个人副本，不等同于重新授权其参与长期判断。

## 12. 系统不顺利时怎样工作

失败是正常产品状态，应当能继续做有意义的事，而不是把错误转嫁为学习者失败。

| 情况 | 用户应看到并能做的事 | 系统必须保持的行为 |
| --- | --- | --- |
| 刚上传后识别失败 | 原件已保存、未识别部分、补充或重试入口，也可直接围绕原件讨论 | 不丢原件，不把失败变零分 |
| 网络中断 | 哪些只在本机、哪些已同步；已具备离线能力的资料和编辑可继续 | 恢复后避免重复提交；不支持离线的动作明确暂停 |
| 两台设备发生编辑冲突 | 看到冲突版本，保留未同步内容，可以选择或合并 | 不静默覆盖，不用旧分析覆盖新输入 |
| 模型超时或输出不可用 | 已保存的尝试、当前未完成的评价、可用的人工或确定性操作 | 不伪造分析，不默默切换已限制的模型或费用规则 |
| 学习记录已生效，安排仍未更新 | 清楚显示记录已经保存、安排正在更新或需要恢复；可继续已有活动 | 不把单项成功描述为整个过程已经完成 |
| 运行中刷新、关闭或重启 | 回来后看到同一作品、活动和任务状态 | 不丢断点；恢复不重复作答、结算、通知或已经完成的业务动作 |
| 任务需要更长时间 | 当前正在做什么、哪些结果已可用、取消或离开的入口 | 不要求一直开着页面；取消后的已完成部分说明清楚 |
| 原题或答案后来发现错误 | 错误位置、相关结果的复核状态、替换或继续选项 | 不责怪学习者；修正受影响的判断与安排 |
| 费用到达上限或服务不可用 | 哪些工作暂停、可使用哪些已有材料与工具 | 不以重试规避上限，不把未知外部结果当作未发生 |

没有能力恢复的内容也必须如实报告。本设计要求可验证的恢复行为，不以框架名称或“已入队”替代完成证据。

## 13. 一道椭圆题在系统中的完整经历

这是根据 owner 的真实动机构造的行为样例。未提供原题和草稿，因此下述具体障碍与表现均是假设，不能当作对 owner 的诊断。它展示各部分如何共同工作，不是实施顺序。

### 13.1 学校里的尝试

学习者在学校花很久做完题，感觉收获不稳。系统未观察课堂过程，不自动推断耗时、独立程度或错误原因。

后来学习者拍下题目与草稿，说“这题做完了，但下次可能还不会”。系统先保存原件和这句话，识别题干、个人草稿与可能的批注；无法区分的部分保留来源疑问。

用户可以就此离开。系统在既有授权内整理，不强迫此刻回答一套诊断问题。

### 13.2 连接过去

系统发现之前有一段相关推导和一次类似卡点，展示关联依据，而不是仅因都属于“椭圆”就认定是同一困难。

它形成一个暂定问题：“已能完成这份推导，但选择关键转化的独立性仍未知。”若草稿表明关键步骤其实独立完成，则不能因为用户说“不稳”抹掉成功证据；把自信与表现的差异留下。

### 13.3 当下帮助

用户有时间时，系统可以邀请其指出最难想到的一步，也可以直接解释关键方法。假设用户说“这里看了老师提示”，系统将该步骤记为有帮助完成。

系统围绕如何从题目条件选择这一步展开，保留用户原推导。用户请求完整解答就提供，不把这次讲解后的复述计为一条独立新题证据。

若用户只想保存，流程停在保存和允许的整理范围，不自动加练。

### 13.4 后续安排

系统根据近期考试范围、可用时间和其他目标，决定何时提出确认机会。可以是相关作业中的自然机会，也可以是一项准备好的短任务；不必再追加一整道高难题。

建议说明它准备观察什么：“这次换了条件表达，看看能否独立识别同一个转化机会。”用户可以接受、换一种方式、推迟或关闭跟进。

### 13.5 结果分支

- 独立识别且完成：增加这类条件下的证据，减少相同帮助；仍不凭一个样本外推到所有椭圆题。
- 识别方法但计算卡住：保留策略方面的成功，将帮助移到具体计算，不重新讲整个方法。
- 再次依赖提示：修正原先关于稳定性的判断，考虑更清楚的对比或更小的任务；不只加题量。
- 系统题目有问题：撤回该题的不可靠评价，保存学习者的尝试，修正已经受影响的安排。
- 用户拒绝继续：按其意愿调整安排，不把拒绝作为负面能力证据。

### 13.6 再次在学校遇到它

几天后出现新的相关作业，用户带入过程。系统把它作为新情境中的实际证据，关联此前帮助，更新判断与下一步。若信息不足，仍只记录已知部分。

回看时，用户能看到那次困难之后发生了什么、哪一部分有了较可靠的进步、还有什么未知。系统不能仅展示累计做了几道题。

## 14. 同一系统在其他场景中的行为

| 场景与触发 | 系统怎样承接 | 用户可见结果与约束 |
| --- | --- | --- |
| 新用户带来一本书或一个问题，没有学习档案 | 按当前意图开始，使用已有材料，必要时询问影响活动的背景 | 可以立即使用；未知保留未知，不强制完成初始化考试 |
| 听完一堂课，只有几行笔记和一个疑问 | 保留课内来源，连接有关材料，帮助回到那个疑问 | 笔记少不代表没学习，不能伪造完整课堂过程 |
| 阅读中突然想研究旁支问题 | 保存原断点，围绕新问题检索、解释或探索 | 能返回原文；兴趣不被自动变成新的考核目标 |
| 看懂例题，却在独立题上卡住 | 保留看懂的自述和独立尝试，检查差异具体发生在哪里 | 给出针对当前差异的帮助，不指责此前“假懂” |
| 完成学校要求的作业，系统觉得另一个主题更重要 | 保存作业经历，说明替代建议的理由及时间代价 | 不静默覆盖必须完成的学校任务 |
| 多科考试临近，时间不足 | 结合范围、期限和已知表现提出取舍及其不确定性 | 用户决定承诺的调整，系统不能无限加时或承诺分数 |
| 做一次限时模拟，中途请求提示 | 说明活动规则和切换后的结果含义，允许按规则退出或转为学习 | 已完成部分保留，不混合呈现无提示成绩与有提示成绩 |
| 写一篇文章，多轮接受 AI 修订 | 保留原稿、建议与采纳过程，围绕表达目标反馈 | 作品改进与本人独立能力分开，可以随时取回原稿 |
| 做编程或现实项目，成果由多人或工具共同完成 | 记录本人贡献、过程说明和实际验证结果 | 可以复盘与后续验证，不能把整个成品归为个人掌握 |
| 听说录音转写错误 | 用户定位并纠正转录，系统重审依赖该文字的反馈 | 原始音频与纠正可对照；未听清不算说错 |
| 教师、参考答案与系统结论冲突 | 并列依据、核对具体步骤，必要时暂停使用争议结果 | 可以继续其他学习，不要求接受某一方才能推进 |
| 长时间离开后回来 | 展示断点及仍有依据的状态，邀请更新重要目标或限制 | 不累积补打卡任务，不把缺记录当成退步 |
| 用户只想查公式、计时或整理资料 | 提供对应工具并按约定保存 | 不强制聊天、评测或生成新计划 |
| 新证据推翻过去的一个关键判断 | 更新相关解释，审查仍未开始的安排，提示有意义的变化 | 能看到改变原因；旧经历和当前作品不被篡改 |

## 15. 怎样判断设计兑现了

验收对象是连续经历中的行为。功能存在、后台任务成功、页面有掌握度、自动测试通过，都不能单独证明产品目标已经兑现。

### 15.1 行为验收样例

| 编号 | 给定与触发 | 应观察到的结果 |
| --- | --- | --- |
| B01 | 相同题目，甲次独立完成，乙次在完整答案后重做 | 两次经历都保留，独立性判断与后续建议有所区别 |
| B02 | 一张学校试卷重复上传两次 | 材料关联，没有两次独立学习或重复掌握增益；真实重做仍可单独记录 |
| B03 | 用户批量带入上周的练习 | 按发生时间解释历史，当前判断使用相关证据，不算成今天刚完成 |
| B04 | 没有课程、画像或知识点标签，用户直接阅读一份资料 | 能开始、批注、求助和保存，不因组织信息缺失被阻止 |
| B05 | 正在做题时，后台收到较早作答的分析结果 | 当前题与草稿稳定；结果检查适用性后才影响后续安排 |
| B06 | 用户纠正“独立完成”为“老师提示后完成” | 有关判断与尚未开始的建议一起复核，原作品保留 |
| B07 | 用户拒绝加练，选择休息或自由探索 | 时间与意愿约束更新，不产生负面能力记录，不重复推同一建议 |
| B08 | 上传、保存或判分后中断，随后恢复 | 用户能辨认已保存、未分析与已生效部分；不丢作品、不重复业务效果 |
| B09 | 新数据与旧分析同时到达，或两台设备修改同一作品 | 冲突可解释且不丢内容；旧依据不能覆盖已经更新的事实 |
| B10 | 系统不能可靠评分或材料有误 | 保持待确认，提供可行的人工或其他学习方式，不伪装成零分 |
| B11 | 删除曾用于摘要与推荐的一次经历 | 被删内容停止参与后续处理，派生判断适当撤销或重建，旧同步不复活内容 |
| B12 | 新学校任务与既有时间预算冲突 | 展示取舍，保留用户锁定承诺，不隐藏加时 |
| B13 | 相似问题曾经出现，但证据条件或帮助程度不同 | 推荐反映差异，并能解释用了哪些经历；不能只做姓名或主题替换 |
| B14 | 系统说某份学习材料已准备好 | 用户能实际打开并完成所描述的活动，所需附件与反馈条件齐全 |
| B15 | 学习者长期未打开产品 | 显示缺少新观察与已有断点，不生成未发生的失败，不制造逾期债务 |
| B16 | 停止后台工作或到达费用上限 | 不再启动范围外的付费工作，已发生与未知费用清楚，现有工具仍可用 |
| B17 | 测评中切换到有提示学习 | 提示正常提供，结果明确记录条件变化，不与原测评结果混算 |
| B18 | 系统帮助后任务完成，但之后独立应用仍失败 | 修正效果判断与帮助策略，不把先前完成当作不可推翻的成功证明 |
| B19 | 临时求助超时后用户离开，任务重试或设备后来同步 | 遵守原定结束条件与恢复期限；到期清理相关派生内容与任务，不自动转长期保存 |
| B20 | 一条争议评分已产生能力标签，用户随后停用该证据 | 当前标签与依赖它的推荐、后台工作一起重建；原件可回看但不再间接参与判断 |
| B21 | 纠偏使某项已锁定作业的材料不再可用 | 显示不可执行原因并提出替代，保留学习承诺；不静默撤销锁定安排 |

上述是应覆盖的行为，不是本轮已运行的测试，也不指定某个测试框架。

### 15.2 评估产品质量

记录负担看用户为整理、补字段、处理重复和恢复上下文付出了多少额外动作；不能把上传条数越多解释为越好。

判断质量看有代表性的真实材料与作答中，结果及解释是否可核对，错误能否发现，系统对未知是否诚实。不同领域、题目形态与帮助条件分开报告；工具调用成功不能代替模型输出质量。

自适应价值看新的经历是否改变了有必要改变的安排，改变是否可解释，是否减少了无效帮助或不必要任务。保持原安排也可以是正确结果。

学习帮助看用户想达到的具体能力或成果是否出现了有依据的改善。即时完成、过后保持和陌生情境应用按目标分别观察；不根据少量前后对比宣称系统造成了提升。

信任与自主性看用户能否理解、拒绝、纠正、暂停、导出和删除，并且这些选择是否真实生效。打开次数、时长和连续打卡不能替代这些结果。

准确率、延迟、费用和允许的打扰量，需要依据目标场景与实际验证确定门槛。本文定义它们应测量什么，不虚构已经达标的数字。

## 16. 本稿的产品取舍与待确认边界

本稿尽量给出可运行的推荐默认行为，不把设计问题全部退回用户。以下是仍需要 owner 看过完整体验后确认的重大取舍；确认前不改变现役行为。

| 取舍 | 本稿推荐 | 另一选择与代价 |
| --- | --- | --- |
| 记录与分析范围 | 按明确的持续约定处理学习内容，并提供仅保存与临时使用 | 更窄的 LIGHT 是所有额外分析逐次请求，少自动处理但打断更多；本稿描述的 FULL 需要完整的派生使用控制，推荐保留该目标 |
| 自适应自主程度 | 授权范围内调整未开始的建议，保护锁定承诺与当前活动 | LIGHT 只出提案、逐次采纳，控制直接但管理负担较高；FULL 在明确边界内自动调整，推荐本稿默认，但不自动扩大授权 |
| 长期判断 | 有依据的暂定能力判断可更新；个人长期特征按已有确认边界处理 | 全部判断逐条审批会增加负担；所有判断自动固化会放大错误。本稿推荐按影响与证据性质区分 |
| 纠偏争议 | 事实纠正生效、评价争议复核、无法裁决保留未知；用户可停用争议证据 | 一律服从用户结论或一律服从系统都不满足可信评估，均不推荐 |
| 用户面对的组织结构 | 以学习经历、作品、问题与下一步帮助组织，共享资料与判断 | 完全按技术能力分模块便于对应实现，但要求用户自己串联；固定一切为聊天又会损害复杂学习工具 |

LIGHT/FULL 在这里表示产品权限与能力范围的对比，不是阶段安排，也不撤销既有全量题目契约决定。本文推荐的是完整系统，未提出把愿景拆成先后交付的缩减版。
