## 1. 设计原文（逐字引用）

### 1.1 行为设计 `docs/design/2026-10-06-continuous-learning-system-behavior.md`

§4 第 78 行：
> 产品接住三种同等正式的进入方式：继续已有学习、带着自己的事情来、让系统提出安排。任意一种都能进入完整的记录、帮助与后续跟进，不要求先走系统推荐。

§4.1 第 82、88、90 行：
> 首页主要呈现可以继续的事情和有理由提出的建议。系统已经做的准备，只有形成可用结果才显示为“准备好了”；仍在生成、需要复核或资料缺失须明确表达。

> 建议给出预计投入、选择理由和替代选择。预计时间是可修正的估计，不是对学习速度的要求。时间很少时，可以缩短范围、记录断点或停下，不用赶完原计划。

> 未完成、到期与值得关注的事项可以完整查看；首页不把它们全部平铺为欠账。长时间未使用后，不自动叠加每天错过的任务。

§4.3 第 100、103、108 行：
> 工作台保留三个位置关系：正在看的内容、自己正在做的东西、围绕它发生的帮助。具体布局随任务和设备变化，不把所有活动挤进消息流。

> - 解题时保留题干、图形、草稿、步骤与已获得的提示；不会因打开讲解丢失自己的尝试。

> 学习者可以随时把系统建议放在一边，查资料、直接看答案、自由提问或继续创作。系统记录适当的帮助条件，不用拒绝提供帮助来强迫产生评测数据。

§4.4 第 114、116 行：
> “我的学习”解释当前判断与变化，允许纠正、补充背景、关闭跟进。“系统为我做了什么”显示有用的后台结果、尚未完成的工作和费用，不要求用户阅读内部运行日志。

> 这些是需要承载的功能区域，尚未锁定最终导航数量、路由或视觉布局。

§6.4 第 184、188 行：
> 未知不能伪装成低能力，也不能自动当作已经掌握。系统可以选择一个有信息价值且负担合适的活动来了解情况，也允许用户跳过了解过程，按其要求开始。

> 数值必须有明确含义及其可靠性说明。没有经过验证的概率不能当作真实掌握概率；用户可以优先看到可理解的描述，再下钻查看计算值与证据。

§7.2 第 216 行：
> 一项建议需要说清：做什么、为了什么、为什么现在提出、预计投入、需要什么材料或工具、得到什么结果后可以停下或改变，以及可选的替代方案。

§7.5 第 245 行：
> 系统先可靠接收当前行为，再显示处理进度和已经生效的结果。需要模型的解释可以晚于确定性更新，但不能阻塞继续记录。

>    - 先 token 后组件：字号 5–6 级、4/8 间距、9–11 级中性灰 + 1 个强调色、圆角 2–3 档、动效时长与曲线入 token；组件禁止硬编码数值。
>    - 层级靠字号/字重/灰度与背景色差，少用边框和阴影；空、载入、出错三态必须设计；数字用 `tabular-nums`。
>    - 交互 100ms 内有反馈；写操作乐观更新并可回滚；路由 `preload="intent"`，下一题在作答时预取。
>    - 动效 150–250ms、只动 `transform`/`opacity`，列表与展开用布局过渡，尊重 `prefers-reduced-motion`。
>    - 键盘优先：高频操作有快捷键，提供 `⌘K` 命令面板；长列表虚拟化。
>    - 可量化门槛：INP < 200ms、CLS < 0.05、关键交互低端机 60fps，附真实操作录屏为证据。

## 2. 组件类型

**page**：一个一次性原型页（dev-only 独立 Vite 入口，单路由内用切换器在变体、屏幕、主题、设备宽度与数据状态之间切换）。
不是生产 route；不挂入 `web/src/router.tsx`，不进 `src/ui/primitives/`，不进 `pnpm build` 产物。

原型内部要比较的正是各变体的结构形态，因此变体内会出现 drawer（侧滑帮助）、bottom sheet（手机帮助）、
modal（`⌘K` 命令面板）与多栏 pane；这些都是原型内的比较对象，不是对生产组件形态的承诺。
生产组件形态以本次决策文档为准，并在 YUK-1354 起的每张 UI 票 pre-flight 再次声明。

## 3. 三个变体的结构假设（开工前写下，评分后才选）

| | A 纸页（Folio） | B 工作室（Studio） | C 学习线（Thread） |
| --- | --- | --- | --- |
| 导航骨架 | 顶栏 + `⌘K`，无侧栏；次级区域经命令面板与“更多” | 桌面左侧常驻导航栏；手机底部标签栏 | 无常驻导航；底部输入式命令条（问、带材料、跳转） |
| 首页“回来时” | 单栏叙述：一段回来时说明 + “继续 / 建议”等大并列 + 带来材料；准备情况安静列表；其余未完成折叠 | 两栏并列面板：左“接着做（你的）”，右“系统建议”；顶部为时间与目标约束条，底部为准备情况 | 以学习线组织：当前线索的“现在”节点分叉出继续 / 建议 / 停下；下方为该线索已发生的经历 |
| 工作台解题态 | 单栏文档：题干 + 图形 → 我的草稿步骤；帮助作为边注锚定到步骤（窄屏内联） | 三栏：题目 / 我的草稿 / 帮助，可折叠；手机为分段切换 | 舞台：题干与草稿双栏，帮助是从底部升起的面板，推开而不覆盖草稿 |

脱敏 fixture：一道长题干椭圆综合题（含图形与两问）、学习者草稿步骤与一张草稿照片、已获得的提示 1、未打开的提示 2 与完整讲解、
“第 (1) 问确定性核对正确 / 第 (2) 问待复核”的判分、“给出辅助线时能完成，未给出时能否独立想到暂无证据”的不确定判断、
学校作业 / 期中考试 / 长期理解 / 兴趣阅读四个目标，以及准备好了 / 生成中 / 需要复核三种准备状态。
内容依据行为设计 §13 的假设样例构造，不含 owner 原题、草稿或任何真实个人记录。

## 6. 验收方式

- 真实浏览器截图（Playwright Chromium）：3 变体 × 首页/工作台 × 桌面 1440×900 / 手机 390×844 × 亮/暗。
- 交互录屏：每个变体走一遍“回来时 → 进入工作台 → 写草稿 → 打开帮助/提示 → 关闭 → 草稿仍在 → `⌘K`”。
- 指标：CLS、交互事件时长（INP 代理值），并在 4× CPU 降速下测关键过渡的帧间隔；原型使用本地 fixture，
  这些数字只证明布局与交互本身的成本，不代表生产数据链路。
- 评分：§1.3 第 3 条五项 + 第 6 条质感与交互基线。
- 独立复核：另起 Claude Opus 5.5 只读复核截图、录屏与原型，结论与处置写入 `review.md`。
- 本机检查：`pnpm typecheck`、`pnpm lint`、`pnpm build`，并确认构建产物不含原型文件；不运行完整 `pnpm test`。
