# YUK-1353 评分表（第二轮）

评分依据：真实 Chromium 截图、录屏、`evidence/probes.json` 与 `evidence/metrics.json`。

- 作者：Claude Opus 5.5。独立复核者：另起的 Claude Opus 5.5，见 [review.md](review.md)。
- 评分对象：第二轮的单一方案（owner 已认可方向）。第二轮不是变体比较，因此分数用来定位弱点，不用来选择。
- 第一轮 A/B/C 的评分（终评 A 29 / B 27 / C 23）在 git 历史里（commit `147ce1615`）。两轮的页面范围不同（第一轮是首页 + 手写解题工作台），分数不可直接比较。

**刻度**：5 = 桌面与手机都满足；4 = 满足，但有一处已记录的弱点；3 = 只在一种设备上满足；2 = 部分满足；1 = 不满足。
“复用成本”一项，分数越高表示成本越低。

## 4. 实测指标

测量环境：Headless Chromium 151.0.7922.34，Apple M4，本地 fixture。

- 被测对象是原型的**生产构建**（`vite build` 输出到 `/tmp` 后用 `vite preview` 提供），不是开发服务器；
  开发服务器跑的是 React 开发版，数字会偏慢。
- WebGL（吉祥物）走真实 GPU（ANGLE Metal）。另有一组软件 WebGL（SwiftShader）对照，代表没有 GPU 加速的设备。
- 每格运行 3 次，取中位数，最大值另列；`cpuThrottle 4` 作为低端机的代理。
- 脚本：`prototype/capture.mjs metrics`（`LOFT_GL=swiftshader` 得到对照组）。原始数据在 `evidence/metrics.json` 与 `evidence/metrics-swiftshader.json`，
  包括每次运行、每个交互窗口的帧间隔，以及每次运行最慢的交互落在哪一步。

两个指标的算法：

- **INP 代理值**：本次操作序列中各交互的事件时长（按 interactionId 合并）取最大值。
- **帧间隔**：每一步操作后 700ms 内，相邻两次 rAF 的最大间隔。

| --- | --- | --- | --- | --- | --- | --- | --- |

### 4.3 判读

- **CLS < 0.05：GPU 下全部通过**（桌面约 0.0003，手机约 0.017）。
- **INP < 200ms：1× 通过，4× 触线。** 4× 降速下桌面中位数正好 200ms，手机 208–216ms，**不能宣称满足**。
  最慢的一步始终是“回来时 → 题目”的切屏。CPU profile 显示主线程约 113ms（4×），其中约 71ms 是共享标题形变在布局阶段读取新页面的位置，
  迫使整页（含公式）同步排版；其余是 React 提交与绘制。对策写入决策 M4、M12：生产中切屏用 View Transitions 或在首帧之后再测量目标，并把题目页的公式前移到服务端渲染。
- **“100ms 内反馈”**：1× 下交互中位数 48–64ms，单次最慢 104–112ms（切屏）。**未全部达成**。
- **软件 WebGL 是吉祥物的真实风险。** 对照组（§4.2）里，三维玻璃花在没有 GPU 加速时会让合成卡住：桌面从题目页去资料时，
  画面约 9–16 秒没有新帧（主线程空闲，CPU profile 证实卡在合成与 GPU 一侧）；其余交互的中位数也升到 184–632ms。卡顿结束时，学习伙伴面板收起的宽度过渡一次性跳到位，
  被计为 0.06–0.08 的 CLS。屏蔽 three.js 后，同一流程的 CLS 降到 0.0004，卡顿消失。页面首次加载时，花的初始化也会卡住约 3 秒。
  这直接支持决策 B4：吉祥物必须懒加载、在空闲时初始化，并在软件渲染、减少动态效果或低性能设备上退回静态图。
- **流畅（60fps）：未验证。** headless 下即使用 GPU，空闲时帧间隔也约 27ms，不能证明 60fps；须按决策 M12 在有头浏览器或真机上测量。
- 指标只说明布局与交互本身的成本。生产中的数据加载、网络与服务端渲染，从 YUK-1354 起按真实路由测量。


## 5. 结论

方向已由 owner 认可。按决策文档定稿，以下弱点作为规则或后续票处理，而不是在原型里继续打磨：

- 吉祥物第二轮建模（B6）；
- 久别、空、载入、出错状态（H7、M14）；
- 布局过渡的真机成本（M8）与动效时长的偏离（T4）；
- 撤销按钮触控目标（M15）、预取（M13）、尺寸与时长字面量收进 token（T4、T10）。
