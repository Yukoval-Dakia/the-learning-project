## 第一轮：A/B/C 三个结构变体（历史）

第一轮的完整复核记录、原型与证据在 git 历史里（commit `147ce1615` 的本文件）。方向随后被 owner 替换，这里只保留对第二轮仍然有效的结论。

- **复核方式**：另起的 Claude Opus 5.5 只读子代理，两轮（初审与 P1 修复验证），都在 2026-10-08。没有交给 GPT、Codex 或 MiMo。
- **结论**：初审“有条件同意”，提出 6 条 P1（乐观写入未实现、手机帮助遮住尝试、断点与规则不一致、页边注释错位、60fps 无法用 headless 证明、评分与流程偏差）。
  第二轮确认修复，终评 A 29 / B 27 / C 23。
- **仍然有效、已写入第二轮决策的经验**：
  - headless 下 rAF 空闲时就有约 27ms 的间隔，不能证明 60fps；流畅须在有头浏览器或真机上用 Long Animation Frames 判定（决策 M12）。
  - KaTeX 0.19 的 strut 不带行距，可换行的推导步骤需要块向外边距（决策 R7）。
  - 流式区域预留高度时，容器要让内容顶部对齐，不能让各行分摊预留的高度，否则 CLS 反而上升（第一轮实测从 0.047 升到 0.058，修正后约 0.002）。
  - 原型 token 曾与 Tailwind v4 的字距主题命名空间同名，导致 Start 的 CSS 多出两个主题变量；改名后产物逐字节一致（决策 T9）。
