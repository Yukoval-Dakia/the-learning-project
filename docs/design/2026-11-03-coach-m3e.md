## 先查清楚谁在用什么

- `/coach` 渲染 `CoachHub`，它只有三个视图：活动量（同文件里的 `CoachActivityView` → `CoachReport` / `CoachKpi`）、校准诊断（`CoachCalibrationView`，顶部是 onboarding 注入的 `CalibrationMaturityBadge`）、成效趋势（`EffectivenessTrendPanel`，`embedded`）。三者都只读，页面上唯一的“写”是跳转。
- 任务单里列的 `OvernightCostSummary`、`PrepDeskConjectures`、`ProbeAnswers`、`TeachingBrief` **不在 `/coach` 上**，只由 `TodayPage.tsx` 渲染：`TeachingBriefBand` 是今日页第二块；`OvernightDigestBand`（在 `TodayPage.tsx` 里，仍是旧基座）里展开“备课猜想”出 `PrepDeskConjectures`，展开“待你试做”出 `ProbeAnswers`，卡底是 `OvernightCostSummary`；`ProbeAnswerCard` 还会在简报“现在就试做这道题”后原位展开。它们也一并换成 M3E，`TodayPage.tsx` 一字未改。
- `calibration-view.ts`、`coach-hub-view.ts`、`effectiveness-trend-view.ts`、`coach-weekly.ts`、各 `*-api.ts` 是逻辑，没动。`coach-hub-view.ts` 里的图标名（旧图标词表）保留，教练页用 `VIEW_ICON` 对应到 lucide。

## 做了什么

- **外壳**：`<UiNextRoot className="ch-page">` + `<main className="ch-main un-m3e-bridge">` + `<ToastHost />`，做法同题库页。页面宽度与留白和今日页一致（最宽 1240px，左右 `clamp(16px, 4vw, 48px)`），样式都限定在 `[data-ui-next].ch-page` 下，颜色走 M3 角色。
- **页头**：小字“复盘 · 当前视图说明”、标题、视图说明；三个视图是一排胶囊标签（`role="tablist"`，选中项是 secondary-container 底色），窄屏上三等分铺满。
- **活动量**：时间窗是一个小号分段外观的按钮组（仍是 `aria-pressed` 的普通按钮）；四个数字块与今日页数字块同形（surface-container-low、20px 圆角、28px 数字）；评分分布和归因分布两张卡（白卡 + 细线、24px 圆角），逐日复习量卡（加了图例，每天的总数在柱上方），失败排行是可点的行（右箭头）。
- **校准诊断**：概览卡（大号百分比 + 一条三段占比条 + 图例）+ 四个数字块；冷启盲区卡在浅底上，盲区是一排白色胶囊（名称、“— 未知”、“去练”）；可靠度分布带保留原来的点位算法（每点位置和泳道都来自 `calDots`），悬停显示名称；知识点表格是白卡里的细线表，表头按钮可排序，阶段用 ui-next 的 `Chip`（可信 positive、渐稳 caution、冷启 neutral）。
- **成效趋势**：方向分布条 + 图例 + 说明；每科一张卡（科目名可点下钻、知识点数、方向标签、置信标签、“展开知识点”次要按钮）；“本期动了的”小卡带迷你轨迹；“持平 / 数据不足”是虚线小按钮；下钻页有“返回科目”、每个知识点一张卡（说明、看图谱、轨迹 + 轴）。轨迹仍是同一个 SVG，几何全来自 `trajGeometry`；颜色改由 `data-dir` 选：在涨 positive、持平 outline、在退 critical、数据不足 outline-variant；低置信仍是更细的虚线和更实的不确定带。空态、出错态的文字一字未改。
- **今日页的教研块**（每个块的根节点带 `un-m3e-bridge`，所以在今日页和教练页里读到的是同一组 M3 角色）：
  - 为你而备：一个白色面板（和今日页“学习画像与依据”同样的 24px 圆角、24px 内边距、上下 24px 间距），标题前一个 secondary-container 圆形图标；四段之间用细线分隔，段名是真实 `h3`（被程序聚焦时显示 primary 描边）；“团队正要问你的一道题”是浅底引用块；依据是一排灰底小标签；当前结果是图标 + 文字（判断得到支持 positive，判题失败 critical，其余中性）。
  - 备课猜想：白卡，小字“教研团的猜想 · 为你而备”，判断正文，反复次数，“尝试区分这一猜想的题 / 你改过”用 `Chip`，题目引用块，证据小标签，接受 / 不太像。
  - 待你试做：浅底卡，题目，原样包住的 `EvidenceComposer`，提交按钮；结果条按结果着色（排除了 positive、与猜想一致待复验 caution、确实卡了 secondary-container、无关错误中性）。
  - 昨日 AI 用量与费用：一个带细边的展开按钮（`aria-expanded` + `aria-controls`，展开后变 secondary-container），面板仍用 `hidden`；明细是浅底小块。
- **嵌套三元**：活动量的状态改由 `activityStatus` 决定，KPI 的显示值改由 `kpiText` 决定，备课猜想和试做题的 `statefulStatus` 改成 if / else，顺序与条件都不变。
- **动效**：只在变化时动。标签、时间窗、按钮、行的底色和颜色过渡、费用箭头旋转、分布点名称的淡入，都读 `--un-t-*`（用户要求减少动效时是 1ms）。没有入场动画（原 KPI 的 `stagger` 逐个上浮去掉了），没有关键帧。玻璃只在 `ToastHost` 的提示条上，卡片没有阴影（T3）。
- **触控**：`un-hit` 加在视图标签、时间窗、表头排序按钮上；ui-next 的 `Button` 自带。会换行且是写入的按钮行（`.cs-acts`：猜想接受 / 不太像、简报的接受 / 不太像 / 保存并验证 / 取消、知道了、提交作答）在 `pointer: coarse` 下行距 16px；盲区“去练”胶囊换行时行距 16px。教练页本身没有写入按钮。

## 逻辑未变的证明
